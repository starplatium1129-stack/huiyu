# CG 与人物壁纸：画面设计与编译保真

适用于人物参与环境的 CG，以及单人物立绘／特写壁纸。先区分创作目标；沿用入口的身份、衣装、分级和交付约束，不把本参考升级为所有图像的固定构图模板。

- 叙事 CG 重视事件与人物环境关系；人物壁纸重视身份、轮廓、表情、衣装和桌面留白。简单背景可构成完整壁纸，全身完整与有意特写裁切分别评价。4K 150% 桌面缩放不改变最终壁纸的 3840×2160 目标，生成尺寸仍以实际工作流支持为准。

- 叙事 CG 先明确可见事件、焦点、人物与关键物件的位置／接触，以及共享光源，再组织引擎输入。补充细节应服务原始意图，不能为丰富度擅自增添人物或改衣装。
- 空间层次和细节数量按画面需要决定；特写不强塞远景，环境叙事不机械加极浅景深，远景人物可以通过轮廓或颜色成为焦点。没有固定主体比例或“越多越好”的物件配额。
- Anima 按 profile 保持标签／精确词，再用有效描述通道写关系；Krea 按项目契约写连贯 prose。两者共享画面意图，不共享一份机械模板或参数。
- 最终编译检查要特别看：通用 Anima 的显式 animaCaption 与自动短语筛选；热门分支的 sceneProse 及自动尾句；left／right 位置词的保真；Krea 自动身份句、风格与单数代词。不能假设原文原样送达，也不能未经出图断言一定损害画质。
- 当前本地 Krea 使用自定义编码器／增强链路；按实际 workflow 记录参数，不能把托管扩写、风格参考或官方裸 Turbo 示例当成本地能力。长短文本也不等价于 creativity 参数。
- 官方事实、项目行为、待实测建议分开。写作规范可立即用于草稿与审核，具体短语效果只有经过对应 checkpoint 的真实对照才升级为默认经验。

## 背景与光影的编写检查

用于需要人物参与环境的 CG；特写、简单背景立绘及刻意留白按原目标处理，不强塞远景或物件。

- **背景能否画出来。** 正文交代镜头中实际可见的环境内容及其与人物的位置关系。只写 `balcony`、`cafe` 或 `detailed background` 不足以表达环境叙事；需要说明人物身后、身侧或视线延伸处可见什么，以及空间怎样延续。按景别选择关系，不固定前中后景数量或人物占比。
- **光影能否画出来。** 依据本条已确定的光源，写清入光方向和受光区域，并选择符合画风的投影、反光或明暗分离关系。`soft lighting`、`warm lighting`、`cinematic lighting` 不能单独作为完整光影设计。阴天可用柔和接触阴影，暗场可保留局部亮部；不一律改成硬光、高对比、逆光或体积光。
- **补强是否改变内容。** 描述已有光源如何作用于已有物体，不自动加入灯笼、烛台、星空、雾、光粒子或额外人物。具体背景内容由这条场景明确设计，并服务于原地点与事件，不作为全库通用补词。
- **风格是否明确选择。** 画师词完全可选；没有选择时，背景与光影仍需成立。保留明确指定的赛璐璐、平涂、厚涂等目标，不默认附加上色词，也不靠更换画师补救缺失的环境。
- **最终请求是否保真。** 背景与光影关系进入有效的 promptProse / animaCaption 等正文通道，并核对最终正向和负向。维护页的 lighting 字段、检索标签或未知风格 hint 不等于有效模型输入；若缺项、被截掉或有冲突，修正后再定稿。

例如，“阳台，清晨柔光”只命名了地点和光照；环境 CG 可进一步明确“栏杆外可见住宅立面，地板透视延伸到人物身后；晨光在衣袖与地板上投下栏杆阴影，远处建筑对比度较柔和”。这是本条画面设计的信息差异，不是要求其他场景复制阳台、住宅或这一组光影。

成功输出不等于通过审核；保留失败图、平局和关键约束失败。不能声称规范保证每个 seed 都惊艳，也不能用文档案例代替生产 Token／真实画面验收。
