# 仓库写入与生成验收

仅在实际维护数据、编译/生成验收、批量重写或定稿时读取。字段与脚本路径均相对仓库根目录。先按 [工作流](../../../../docs/workflow.md) 选择现成入口；人物、服装、场景和蓝图以运行目录 `content/catalog.sqlite` 为工作权威，经记录 API 或 `content:catalog` 维护，保存后显式 export 项目快照。`data/catalog/` 仅是导出快照，旧分片只作升级导入，不手改或聚合回写。具体边界查 [内容库设计](../../../../docs/architecture/CONTENT-CATALOG-DESIGN.md)。

批量以目标 ID、manifest 或 delivery 确定范围；委派时按不重叠的角色/场景分工，交代引擎、源文件与保护字段，主任务合并并复核证据。

## 字段与编译核对

| 层 | 要核对的内容 |
| --- | --- |
| 角色 | `characterTokens` 标记名字/别名，`copyrightTokens` 独立提供作品；保留鲜明身份锚点与 exact tokens，不把 `identityProse` 全文重复灌入 Anima |
| 服装 | 当前 `outfitId`、名称与 `outfits[].tokens/prose` 一致，避免身份字段泄漏旧衣装；Anima 服装进入画师后的普通标签段，用普通服饰词表达设计，不把自创套装名当模型触发词 |
| 蓝图 | `description` / `action` 的可见核心进入 `promptTokens` / `promptProse`，同步核对会追加消费的 `nsfwTokens` / `nsfwProse`，避免旧动作重注入；场景已有同伴名字由蓝图 `characterTokens` 分类，不登记成主角别名 |
| 背景与光影 | 决定本场景效果的空间/光照关系进入最终正文；逐条核对 camera / lighting / 展示描述中的必要关系是否在 promptTokens / promptProse 或 animaCaption 实际承载，不能因有宽泛镜头、光照标签就视为已保留；一般细节交给模型，不强制补齐所有背景与光影细节 |
| 导演 | 镜头、光照、构图、`recommendedSize` 和模型参数不互相覆盖冲突；实际人数不由分级强制改单人，显式 `1girl, 1boy` 等人数组合须保留 |
| 最终请求 | Anima 六段顺序与自然语言末尾边界，完整 positive / negative、模型/LoRA、seed、尺寸、采样参数及参考输入；批量/维护入口不能编译后另拼标签 |

原场景明确要求的镜面形象／幻影可用 `allowRepeatedSubject` 保留，画内完整同伴使用 `compositionIntent: group`，只有画外视角或伸入的手时保留单主体，三格叙事使用 `triptych`；不能把这些字段当成所有场景的默认。外貌形态冲突时，`identityTokensOverride` / `identityProseOverride` 在对应蓝图、独立场景或实际参与编译的衣装中声明已有形态，不改变角色 ID；衣装未选用时不注入其外貌变体，蓝图明确变体优先。散发、摘眼罩等状态同时核对角色默认锚点是否让位，不能只在衣装 prose 中声明。普通游戏形态、发型和配饰变化不作为内容访问门槛。正文明确幼态的变体仅用于非性化场景，不能靠删年龄词保留原性化内容。衣装字段只保留衣装与对应穿戴状态，手持道具属于具体场景。

衣装调整同时检查所有引用蓝图及独立场景实际消费的服装词、散文和展示描述。成人蓝图当前不自动注入绑定衣装的 tokens/prose，应同步其已有服饰描写，不能只改 `outfitId`。优化衣服不包含改变原穿着状态：明确裸体的条目保留裸体及原名称，不统一改名或添加休息等姿态；浴巾、局部搭盖和披挂关系也保持原意。中文正文明确裸体而英文标签夹带衣服时，不能反向改中文来迁就衣服标签，应按明确的原状态修正冲突词与绑定；仅凭旧 `outfitId` 不能推断全裸，需结合原正文。若同一占位衣装被衬衫、浴衣等不同穿着混用，优先绑定匹配的已有衣装；确无匹配时按原场景已有服饰建立独立记录，逐条保留裸体与穿衣的区别。多人画面分别绑定各人的衣装，必要关系放自然语言末尾，避免共享服装词把两人穿着混成一套；Anima 不自动叠加旧式括号包裹的整组身份词，作者明确写出的 BREAK 作用域单独核对。

代码入口：`src/utils/popularContent.ts`、`src/composables/prompt/usePopularPromptAssembly.ts`、`src/utils/promptCompiler.ts`、`src/utils/promptPolicy.ts`；独立场景检查复用 `scripts/lib/scene-render-contract.js`。

分级沿用项目字段；蓝图 `adult` 决定创作分级，`sampleRating` 描述已有样张，改写文字不等于旧图重新评级。旧样张未替换和复核时保留其原分级。项目内角色按成年创作设定，成人内容不受本机、远程、内容开关或旧成年资格字段限制，界面展示遵循 AGENTS.md 的目录与作品册边界。不要为完成场景数量自动增添成人内容，不把分级标记当作人物成年依据。该 skill 提供全年龄、明确成年角色的非露骨创作与中性的分级/一致性审查，不提供露骨性描写的扩写配方。

## 验证与交付

- **草稿/解释**：标明目标引擎、必要假设、提示词及负向策略；不需要为了单纯草稿启动仓库工作流。没有真实运行就写“未编译/未出图”，不能称最终请求。
- **实际数据变更**：检查最终编译内容并真实出图，核对身份、衣装、动作/接触、人数/肢体、构图和环境。静态通过、生成成功或 UI 文案都不是视觉通过。
- **批量重写**：逐条真实改写并审查交付差异；仓库不保留或执行测试。单点纠错须明确范围，不冒充全量重写。
- **定稿**：批量跳过 `data/prompt-pinned-scenes.json` 的保护字段。单条修改按项目要求先真实出图再 `npm run scenes:pin-capture`。
- **规则实验**：保持 checkpoint、LoRA、尺寸、采样器、步数及加速设置一致，用同一组固定 seeds 对比；一轮只改一个因素。建议先用 3 个 seed 小样筛查，不能据此推断全库效果。
- **记录**：保留候选清单、最终请求、参数和输出路径，逐图标记问题；区分生成失败、视觉未通过和未审核。只有实际查看过的图才能计为视觉审核。
- **仅修改 skill / 文档**：做结构、链接、规则一致性等必要检查即可，不把文档验收宣称为生成质量提升，也不机械运行与本次风险无关的完整构建或真实出图。
- **服务或素材阻塞**：先完成可独立进行的源数据检查、候选草稿或编译核对，记录缺失服务/输入与待验收 ID；不循环重试同一失败，不把候选发布为已验收结果。

交付形式遵循 AGENTS.md，仅在聊天中给出必要的提示词或改动、依据、当次检查及未完成项；涉及出图时附真实证据。批量交付需明确目标数、已改写数和已视觉验收数。
