# Studio Prompt Craft

将用户意图写成模型能够执行的画面描述，保留身份、服装、人数、分级和构图。协作与授权遵循 [AGENTS.md](../../../AGENTS.md)；本 skill 不扩展任务范围。

## 按任务读取

- MiaoMiao 1.6：读 [版本规则与作者依据](references/miaomiao-v16.md)及 [Anima 输入与编译](references/anima.md)。其他 Anima checkpoint 只读后者，不能套用 1.6 的配方。
- Krea 2 提示词或编辑描述：读 [Krea 规则](references/krea.md)。
- MiaoMiao Harem MOSS BASE v1.0：读[原生推理指南的 MOSS 章节](../../../docs/guides/independent-inference.md#8-miaomiao-harem-moss-base-v10)及其中作者版本页。它是独立 MOSS 架构；支持中文和布局 JSON，不套用 Anima 六段编译、编码器或 LoRA 规则。
- 叙事 CG 或单人物立绘／特写壁纸的构图与完成度：再读 [构图参考](references/narrative-composition.md)，按目标进入叙事或壁纸规范。
- 手机竖屏壁纸：读 [手机规范](../../../docs/guides/prompts/mobile-wallpaper-prompt-standard.md)。
- 成年角色成人向／NSFW 场景与蓝图规范：读 [NSFW 规范](../../../docs/guides/prompts/nsfw-cg-prompt-standard.md)；项目内角色按成年创作设定，界面展示遵循 AGENTS.md 的目录与作品册边界。
- 写入仓库、批量重写、换装/生成验收或定稿：再读 [字段与交付](references/delivery.md)。纯草稿不要求启动仓库工作流或出图。
- 成年角色非露骨题材研究、中性一致性排查、其他引擎能力或历史规范冲突：按需查 [研究来源与采用边界](../../../docs/research/README.md)。其中 MiaoMiao 作者页未核验的历史限制由本 skill 的 1.6 版本参考补充，不覆盖其他 checkpoint；无需默认加载所有历史指南。

## 写作与审查

1. **确认实际输入条件。** 从任务和当前配置取得 modelId/checkpoint、profile、LoRA、画幅和参考用途。项目当前默认为 MiaoMiao 1.6，历史配方或显式选择优先；不能只凭“Anima”推断版本。只输出需要的引擎，共享蓝图变更才核对双引擎。
2. **先确定必须控制的画面。** 保留主体身份与数量、鲜明特征、当前衣装主特征、主动作和关键环境；把场景写成可想象的一个瞬间，交代必要的动作接受者、手与物件的接触、人物左右和画内／画外关系。氛围来自本场景已有的神态、光源及其照到的人物或物件，不用通用“唯美、梦幻”尾句或擅加花瓣、星空等装饰。未指定的发丝、衣褶、配饰、材质和背景小物交给 Anima 补全，不把人物档案写成全身清单。多人需用各自的辨识特征绑定位置和动作；简化不能删掉事件核心，也不把连续动作硬塞进同一静止画面。
3. **按目标模型表达。** Anima 使用 Gelbooru 普通标签、Danbooru 画师名与必要关系句，严格遵循 [输入与六段编译契约](references/anima.md#标签与六段顺序)，保留精确词和显式类别；Krea 按独立 prose 契约表达同一画面。语法细则集中在对应引擎参考中，不能混用。
4. **分离身份和可变内容。** 从内容库读取真实 ID 与身份，选用名字/作品和足以识别的外貌锚点，不自动写全所有外貌细节，也不按固定标签数量机械截断。精确触发词及已验证 LoRA 控制契约保持原样。衣装设计结合角色的标志色、轮廓或纹样与场景用途，用少量明确的剪裁、层次和材质建立特色；原作标志服保留辨识结构，时装感不等于给每套衣服套用同一种配色或堆满配饰。借来的衬衫、工作制服等有叙事用途的服饰保留其来源与功能。衣装、动作、环境进入对应字段，换装清除旧衣装冲突；结合实际绑定的衣装检查蓝图重复，不只在单一字段里去重。区别必要的颜色／形制特征与无新增信息的同义叠加，不用猜测性的全局同义词替换。对白仅在用户要求画面文字时进入 prompt。
5. **负面从精简基础开始。** 采用目标 checkpoint 的配方，再保留本条必要排除项，不能与所需文字、多人、分格或镜像冲突。MiaoMiao 1.6 见 [作者配方](references/miaomiao-v16.md)，其他 Anima 见 [精简负面基础](references/anima.md#精简负面基础)，Krea 沿用其本地负向契约。
6. **核对最终编译。** 按所选引擎参考核对身份、衣装、镜头、关键关系、词序与负面。Anima/Krea 的工作台、批量、反推采纳后的编译和维护预览统一调用 [`compilePromptRecipe`](../../../src/utils/promptRecipe.ts)，按 `kind: 'studio' | 'popular' | 'free'` 传入完整上下文；调用方不直接绕过内容组装层或在编译后另拼标签。新场景通常只需维护内容字段并查看同入口的编译预览，无需修改编译代码；只有新增模型能力或确认通用编译缺陷时才调整实现。反推、导演来源与模型分层见 [Anima 编译消费](references/anima.md#分类与编译消费)。确认没有重新注入人物/服装长段或负面模板，不臆造全局别名映射；编译预览不代替实际画面验收。

## 输出边界

- 遵守仓库分级边界；处理全年龄、明确成年角色的非露骨创作与既有文本的中性转换，不扩写露骨细节。项目成年创作设定与原作设定分开判断，不能仅凭原作年龄、娇小体型或校服跳过条目；正文若明确出现与成年设定矛盾的年龄描述，单独核对并清理冲突，负向排除词不当作人物属性。分级词不是成年依据，也不扩展模型调用授权。
- 草稿给出目标版本、必要假设、正向与负向策略；注明是否实际编译/出图。官方事实、项目当前行为与待实测建议分别说明，字符数不当作 Token 数。不以字符数、词数或句号数判定提示词质量与完整度；数据检查保留非空、绑定、冲突及编译消费约束，输入大小限制按真实接口契约保留，画面语义按本 skill 审查并以真实出图确认。
- 数据定稿遵循交付参考，以最终请求与真实画面为证据。仅修改 skill 时检查结构、链接及规则一致性，不能把文档通过当成生成质量通过。
