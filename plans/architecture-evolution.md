## 1. 结论、范围与已有基础

### 1.1 核心决定

保留 Vue / Pinia 前端、Express 网关、Tauri 桌面壳和现有存储方案，沿着**边界清楚的单体应用**演进。首先让“作品是什么、生成请求是什么、如何将结果入册”脱离工作台内部状态，再收紧接口和引擎边界。

本计划的成功标准不是多出几个目录，而是：修改一个小功能时，需要了解的模块更少；出现失败时，能够明确定位责任和保护用户数据；同一业务能力能够被不同入口使用，而不必模拟一个完整工作台。

优先执行顺序：

**基线与夹具 → 业务类型独立 → 新边界检查 → 入册用例独立 → API 契约 → 后端引擎边界 → 按需整理存储与生命周期。**

### 1.2 事实、推断和计划的区分

本次成文时，主干已从前序审查使用的 `040caa97973242dbca9abc715fefe3cdb534605e` 前进到 `5f9151601173e0ef8361673f90c0a5c7b1d133c3`；新提交包含维护入口和实施状态的文档对齐。因此，不再把旧文档中的同类状态冲突机械列成新的架构待办。[S01]

本文使用前序固定源码审查与成文时的重点复核，**不是全仓依赖图扫描、性能测试或运行故障诊断**。各证据链接固定到实际读取过的提交；启动实施时必须执行 A00，确认后续提交是否已经解决相应问题。建议路径、类型名称和任务编号均是方案，不表示文件或命令已存在。

| 已确认的源码事实 | 架构上的解释 | 本计划处理方式 |
| --- | --- | --- |
| `HistoryEntry` 由工作台 Store 定义；结果上下文工具依赖 Store 类型 | 公共业务表达仍与特定页面状态连接 | 提取业务类型，保留兼容导出；不把类型引用误报成运行时循环。[S03]、[S04] |
| `commitHistoryEntry()` 集中处理图片、元数据、持久化和失败清理，缺失字段仍有当前表单回退 | 新入口必须理解隐含默认值，独立复用成本较高 | 提取入册用例，逐个迁移调用者到显式快照；不能据此宣称所有现行路径都存在串数据故障。[S03] |
| 生成客户端声明的返回结构，比当前运行时校验覆盖的字段更完整 | 下游可能获得过强的类型保证 | 先校验关键消费字段，再统一契约归属，不盲目拒绝所有旧数据。[S11] |
| `routes/generation.ts` 包含引擎选择与提交逻辑，并引用 `routes/anima` | HTTP 入口与业务编排尚有耦合 | 在现有服务上调整依赖方向，保留各引擎的能力与编译差异。[S12]、[S13] |
| Repository 已有适配接口；`useKVStore.ts` 实际是 IndexedDB 封装 | 部分目录名称与实际职责不一致，不等于严重 Vue 耦合 | 顺带整理基础设施归属，不以此为由迁移数据库。[S07]、[S09] |
| 任务中心已有摘要持久化、控制入口及部分后端身份关联 | 已有能力应继续利用；任务摘要不等于持久化执行器 | 先明确任务所有权和恢复语义，不重新建设一个任务中心。[S14] |

### 1.3 明确不重做的能力

作品 Repository、软删除和关联记录处理、跨窗口清理保护、Anima 的校验/媒体/工作流/服务分层、任务中心，以及已接入的工作流和交付证据机制，都是本计划的复用基础。[S07]、[S08]、[S13]、[S14]、[S19]

005/006/009/010 的已有实现与设备待验项继续以 `docs/project-status.md`、`docs/roadmap.md` 为准。布局接口整理、内容保存事务、已完成的办公机功能和动效修复不能因为新计划出现而重新开工；真实模型和原生设备验收也不能被架构单测代替。[S23]

### 1.4 不在默认实施范围内

不更换前端框架，不拆微服务，不建立通用插件平台或全局事件总线，不引入大型依赖注入容器，不统一重写全部生成编译器，不迁移用户图库或改变备份格式，不将整个仓库切换为另一种模块系统。

SQLite、持久化后台任务、全仓 feature 目录搬迁、新共享运行时包、虚拟列表和大型备份方案，只能在出现明确需求、瓶颈或兼容性证据后单独立项。它们不是“完成架构升级”的必选项。

本计划不授权真实模型调用、外部资源下载、安装、发布、生产数据清理或对主干直接写入。后续实际实施按用户授权和仓库协作规则执行。

## 2. 目标架构与依赖规则

### 2.1 目标调用关系

以下为建议结构，不要求一次性创建全部目录。

```text
展示与交互：View / Component
        │
        ▼
页面适配：Composable / Store
        │  将响应式状态转换成显式、独立的业务输入
        ▼
业务用例：保存生成作品 / 发起生成 / 恢复已确认的任务关联
        │
        ├── 业务类型与纯规则：作品、创作快照、生成结果、兼容解释
        │
        └── 能力接口：现有 Repository / 图片读写 / API 客户端
                         │
                         ▼
              IndexedDB / HTTP / 平台实现

HTTP 路由 ──► 后端生成业务编排 ──► WebUI、Comfy 等适配实现
                   │
                   └── 复用现有任务执行、Anima 服务及公共校验能力
```

箭头表示调用关系。代码导入还应满足：业务用例依赖能力接口，不依赖具体 Store、页面或平台实现；具体实现由装配入口提供。对简单能力允许直接传函数或对象，不要求所有函数都包装成类。

### 2.2 建议归属

| 位置 | 应承担的职责 | 不应继续增加的职责 |
| --- | --- | --- |
| `src/types/` | 复用现有业务类型，补齐作品与生成快照定义 | 反向引用整个 Store；把网络原始数据当作已验证对象 |
| `src/utils/` 中明确命名的纯模块 | 现有纯规则与兼容映射；先查重再新增 | 偷读当前表单、访问数据库、弹出通知 |
| `src/application/artwork/`，拟新增 | 一个具体的“保存生成作品”用例 | 管页面布局、选择当前角色、决定提示词风格 |
| `src/stores/`、`src/composables/` | 响应式状态、用户交互、订阅与页面适配 | 定义所有入口必须依赖的公共业务类型 |
| `src/storage/` | Repository、存储适配、已有互斥与关联写入能力 | 依赖页面状态；自行推断创作身份 |
| `src/api/` | 传输、响应解析、接口错误映射 | 不经验证直接承诺完整业务对象 |
| `server/generation/`，拟新增或复用已有同职能位置 | 引擎选择、生成用例与服务适配装配 | 从 HTTP 路由文件反向取得核心业务能力 |
| `routes/` | HTTP 输入、请求身份、鉴权、限流、响应和连接语义 | 混入不断扩大的引擎选择表 |

`src/types/` 是项目已有的类型归属约定，优先复用，不另建一套重复字段表。[S02] 新目录必须先经过 A00 查重；如果现有目录已能表达职责，只补模块，不为对称性建空目录。

### 2.3 三类模型必须区分

| 模型 | 用途 | 约束 |
| --- | --- | --- |
| 网络传输模型（DTO） | 表达后端真正发送的请求和响应 | 在边界解析；保留接口版本和缺省语义 |
| 业务内部模型 | 表达已明确的创作输入、结果和操作 | 不依赖 Vue、Express 或某个页面；不随意包含原始未知字段 |
| 持久化兼容模型 | 读取旧作品、草稿和历史配方 | 允许已支持的旧表示；保留未知字段与缺失信息，不读后自动回写 |

这三类模型可以复用字段定义，但不能为了“一个统一类型”强行合并。特别是缺少引擎、种子或服装信息的旧作品，不得根据当前表单填成“已知且可复现”。

### 2.4 跨运行时共享的边界

第一阶段只共享必要的纯类型和已存在的纯规则，不默认新增 `shared/` 运行时目录或 npm workspace。

当前构建器按项目、源码清单和输出归属生成运行文件，`tsconfig.node.json` 也有明确的输入范围。**增加一个共享目录，并不自动让 Node、浏览器和桌面安装包都获得可用的运行产物。**[S16]、[S17]

只有 A03 证明共享运行时校验能减少真实重复维护，才进行单独决策：确定唯一源、编译方式、输出归属、清理范围、前端打包入口、桌面暂存和许可边界。必须先通过干净工作区和打包夹具验证，再迁移调用者；不能依靠开发机遗留 `.js` 或桌面上并未携带的 `.ts` 侥幸运行。

## 4. A00：建立本批可复核基线

**目标：**在修改之前知道当前行为、调用者和失败边界，防止重复开发与“重构顺便修好了什么”的不可解释变化。

**入口：**`AGENTS.md`、项目状态、roadmap、本文相关证据、当前分支 diff、工作流手册。只阅读影响本批的内容，不重跑全站历史审计。[S19]、[S23]、[S24]

**执行步骤：**

1. 记录当前完整 commit、工作区状态、Node/npm 版本；对照本文审查快照，检查相关模块是否已变化。使用隔离工作区，保护其他会话改动。
2. 列出本批函数的全部调用者、类型消费者、生成文件和测试入口；同时检查 `import`、动态导入、`require()` 和兼容再导出，不凭文件名判断运行依赖。
3. 为当前正确行为建立中性夹具，记录输入、输出及副作用顺序；未运行的验证明确记为 `not-run`。建立失败场景后再修改实现。

**最小交付物：**一张本批影响表，包含 `入口 → 调用链 → 写入位置/上游 → 受影响测试 → 不在范围内的行为`，以及对应源码与测试证据。无需为所有模块建立巨大的人工清单。

**验收：**能够回答“为什么修改这些文件”“哪些行为必须不变”“哪一个测试证明它”。如果基线相关检查失败，先区分既有失败、环境限制和本批引入问题；没有可靠基线的链路不大范围迁移。

**回退：**本任务不改业务代码。夹具不得读取、复制或上传用户真实作品、对话、令牌与私有素材。

## 5. A01–A02：业务类型与生成结果入册

### 5.1 A01：把公共业务表达从工作台中解开

**依据：**工作台、结果上下文与历史记录的类型关系；旧记录本来就允许更宽松的数据表示。[S03]、[S04]、[S05]、[S06]

**现有入口：**
`src/stores/promptBuilderStore.ts`、`src/stores/promptHistoryStore.ts`、`src/types/artwork.ts`、`src/types/anima.ts`、`src/utils/resultContext.ts`。

**建议新增：**仅在查重后增加 `src/types/generation.ts` 或同职能文件。避免把全部状态和所有 API 字段装进一个新的“大类型文件”。

| 子任务 | 执行内容 | 完成条件 |
| --- | --- | --- |
| A01.1 迁出定义 | 将作品/生成结果的公共定义放到已有类型层；旧 Store 仅兼容再导出；同步直接消费者 | 字段语义不变；新类型文件无 Store/组件导入；旧导入入口可继续编译 |
| A01.2 收窄输入 | 让 `captureResultContext()` 接受显式需要的字段接口，而非整个 Store 的返回类型；页面负责组装输入 | 纯测试可传普通对象；不需要 Pinia 实例；输入快照不共享可变数组或嵌套对象 |
| A01.3 明确旧新模型 | 区分可读的旧作品、新生成记录和规范化视图；逐个替换跨层双重断言 | 字符串/数字 ID 均保持原兼容语义；缺失字段有解释，不伪造历史事实 |

**兼容要求：**保留作品 ID、`parent_id`、项目关联、未知扩展字段以及 `null`/缺省的区别。不得顺便统一全部 ID 生成算法，或把热门角色 ID 强行约束为工作室角色枚举。纯类型中的只读表达不应迫使网关依赖 Vue 类型模块；页面适配需要的 Vue 类型留在前端适配处。

**必验场景：**工作室与热门角色、旧记录缺字段、字符串/数字 ID、缺失父作品、未知扩展字段、快照后修改原始数组、历史恢复与视频交接身份一致性。已有快照相关行为测试应复用，不以新测试覆盖率替代旧回归。[S25]

**回退：**保留旧位置再导出，按消费者分批回切；不产生数据库迁移或数据回写。兼容导出只有一个真实定义，不复制第二套接口。

### 5.2 A02：独立“保存生成作品”用例

**依据：**当前 `commitHistoryEntry()` 同时处理图片、缩略图、尺寸、作品字段、Repository 和失败清理，并包含对当前表单的回退读取。[S03]

**目标：**保存逻辑处理“明确的生成快照 + 真实结果 + 显式依赖”，不认识当前页面，不弹出 Toast，不导航。现有 Repository 和互斥机制继续使用，不再造一套持久化框架。

**建议入口：**`src/application/artwork/saveGeneratedArtwork.ts`；旧 `commitHistoryEntry()` 先作为兼容外壳，逐渐只负责适配、调用和刷新展示。

| 子任务 | 执行内容 | 完成条件 |
| --- | --- | --- |
| A02.1 无语义抽取 | 先把当前保存步骤抽出；对字段优先级、失败处理建立特征测试；默认值仍由兼容外壳明确提供 | 同一夹具得到相同记录和副作用结果；新用例没有 Store、Toast 或路由导入 |
| A02.2 迁移提交快照 | 从一个现有生成入口开始，在首次异步操作前捕获身份、故事、风格、模型参数和项目等必要信息 | 新路径中，保存用例不再为缺失生成事实读取当前表单；原始结果元数据与提交快照的优先级有测试 |
| A02.3 迁移其余调用者 | 覆盖队列、临时结果、手动入册及当前已存在的其他保存路径；逐项记录完成，不新增未授权功能入口 | 每个现有调用者都映射到同一保存能力；确需保留的旧输入通过显式兼容适配器处理 |

不得将 A02.1 的机械抽取与 A02.2 的默认值时机调整混成一个不可区分的提交。已有显式任务快照优先级继续保持；缺失生成字段的旧结果应返回兼容说明，不能被“当前选中值”伪装成真实生成参数。

**用例边界示意，非现成可运行代码：**

```text
saveGeneratedArtwork({ submissionSnapshot, generatedResult }, dependencies)
  ├─ 校验新路径必须具备的事实；旧结果走独立兼容入口
  ├─ 通过现有暂存保护创建图片并测量真实尺寸
  ├─ 由纯映射组装持久化记录
  ├─ 通过现有 Repository 提交记录
  ├─ 返回成功记录或明确失败结果
  └─ 只在安全范围内处理本次产生、确认未被提交引用的残留

页面/Store：构造输入 → 调用 → 成功后更新展示 → 通知用户
```

依赖使用简单对象或函数，包括图片存取、Repository、时钟/ID、测量、缩略图和允许的诊断能力。不要为了测试而引入容器。原 `historyIdSeq` 及其现有保证先保留，不把进程内序号描述成跨进程全局唯一协议。

### 5.3 入册失败与数据保护契约

| 场景 | 应保持或落实的行为 | 禁止做法 |
| --- | --- | --- |
| 图片写入失败 | 不添加作品记录；返回可感知失败 | 先更新内存列表造成“看似已保存” |
| 主记录提交失败 | 保留原错误；只处理本次拥有的、确认未提交引用的资源 | 清理整批未引用图片，或删除历史图 |
| 提交结果无法确认 | 先查询/核对提交身份，再决定是否补偿或重试 | 仅凭异常就认定没写入并删除图片 |
| 缩略图失败 | 按现有可再生成附属资源语义处理，保持原图和主记录 | 因展示附属资源失败回滚已完成作品 |
| 尺寸读取失败 | 保留未知尺寸的既有兼容行为 | 用表单下拉尺寸冒充真实图片尺寸 |
| 生成期间编辑表单 | 新路径只使用已冻结输入与该任务真实结果 | 从当前角色、项目或参数补齐任务身份 |
| 补偿失败 | 单独报告原始失败与补偿失败，不报告成功 | 静默宣称已完全回滚 |

表中“提交结果无法确认”是防护要求，不是本轮已复现的缺陷。若落实它需要新增持久化身份或改变恢复语义，应从机械重构中拆出单独设计；不得把原地重试包装成“恰好一次保存”。

现有文档会话锁、图片暂存保护、作品写锁及 IndexedDB 事务各有职责。[S07]、[S08]、[S09] 不改变它们的获取顺序，不在新外壳中重复取得同一非重入锁，不把图片解码/网络等待塞进必须连续完成的数据库事务，也不把跨两个存储域的补偿宣称成物理原子事务。

**验收出口：**无需挂载页面即可测保存流程；异步修改表单不影响该任务记录；失败和补偿路径可注入测试；所有迁移后的现有入口完成回归；生成请求内容、作品格式和用户数据位置保持约定兼容。

**回退：**按入口回到旧外壳或回退对应提交，不同时跑新旧两次写入做对照。对照测试只运行纯记录组装或隔离夹具。代码回退不自动撤销用户之后创建的作品。

### 6.1 A03：先把关键接口的承诺变得可信

**依据：**`GenerationJob`、`GenerationStatus` 的声明较完整，但当前 `isJobEnvelope()` 主要检查对象与 ID；共享客户端已经承担缓存、消费者隔离、取消和错误处理，不应被另一套客户端替换。[S10]、[S11]

**现有入口：**`src/api/generationApi.ts`、`src/api/client.ts`、相关 API 类型文件、`routes/generation.ts` 的公开响应与测试。

| 子任务 | 执行内容 | 完成条件 |
| --- | --- | --- |
| A03.1 消费字段表 | 按 status/create/get/cancel 分别列出实际消费字段、后端输出、缺省语义和错误情况 | 每个承诺必需的字段都有来源；明确“未提供、未知、不支持”的区别 |
| A03.2 解析与契约 | 先补关键响应解析与请求最终输入约束；前后端使用同一组中性合法/非法样例验证 | 非法状态、错误字段类型、缺失必需值可定位；合法现行响应保持兼容 |
| A03.3 共享决策 | 评估类型共享、已有 schema 或纯校验模块，只有维护收益明确才扩大运行时共享 | 有明确方案及成本；允许结论为“维持当前运行位置，只共享类型与契约样例” |

**实施要求：**

1. 新生成请求的业务内部模型、网络 DTO、旧持久化记录分别命名。先复用现有类型位置；禁止前端一份、后端一份、测试里再手写一份互不关联的权威字段表。
2. 根据实际协议处理必需字段和可选字段，不能因为 TypeScript 某字段目前写成可选，就认定服务端允许省略；也不能把正常缺省值突然改成协议错误。缺少证据的兼容补值必须标明未知，不推断 `provider`、任务成功或真实种子。
3. 消费者解析使用自己的响应副本，不能污染共享缓存。业务规范化放在 API 专属边界，不把作品、语音、生成规则全部塞入通用 `ApiClient`。[S10]

**失败策略：**响应无效时输出可识别的 `invalid-response` 或等价受控错误，保留已知任务身份并提供核对入口；不能将“无法解析”显示为“生成成功”，也不能自动重提可能已被接受的任务。

**验收矩阵：**至少覆盖合法响应、缺失必需字段、错误类型、未知状态、可选字段缺失、旧兼容响应、未知扩展字段、取消/超时、并发消费者隔离。对返回数组与有限枚举逐项验证，不仅检查外层是对象。不要为了类型通过而把所有边界转换成 `any`。

后端服务端鉴权、访问限制、路径检查、限流和输入白名单仍独立执行。共享数据结构不构成共享信任；前端校验不能替代服务端授权。

**回退：**保留传输接口与 URL。按端点回切解析实现，但不得通过删除现有安全校验“恢复兼容”。若新解析揭示真实的历史响应缺口，先记录样例并修复契约，再决定是否放行，不静默制造默认事实。

### 6.2 A04：让 HTTP 路由只组织 HTTP，生成服务组织生成

**依据：**当前生成路由直接承载 WebUI/Comfy 的选择与能力分支；Anima 已有可复用的服务拆分。[S12]、[S13]

**现有入口：**`routes/generation.ts`、`routes/anima.ts`、`routes/anima/` 的相关模块、`server/job-runner.ts`、网关装配入口 `server.ts`。以上是影响盘点入口，不表示全部需要改动。

**建议目标：**在 `server/generation/` 或查重后确定的现有服务位置放置生成编排与适配接口；逐步让公共逻辑不依赖某个 HTTP 路由文件。旧路由导出可以临时作为兼容转发，但不得保留第二份核心实现。

| 子任务 | 执行内容 | 完成条件 |
| --- | --- | --- |
| A04.1 提取选择规则 | 为现有 provider 选择建立决策表与特征测试；把可纯化部分提成输入明确的规则 | 相同请求和能力快照选择同一分支；保留默认值和错误语义 |
| A04.2 抽取编排与适配 | 业务服务调用现有引擎服务；鉴权身份从 HTTP 边界明确传入；路由保留连接、限流与响应职责 | 业务服务无 Express `Request/Response` 依赖；不通过 route 文件导入核心服务 |
| A04.3 兼容收口 | 逐个迁移依赖旧路由导出的脚本/测试；验证结果读取、消费、取消和关闭行为 | 接口 URL、公开字段和既有错误映射可兼容；干净构建与网关契约通过 |

**最小适配面：**探测能力、提交、查询、取消、获取结果引用、关闭资源。不同引擎不支持的能力使用明确的能力声明和受控错误，不靠一串可选函数和调用方猜测。

`sd/anima/krea2` 等创作引擎或模型家族，与 `comfy/webui` 等执行提供方是不同维度。统一任务操作，不代表合并提示词语法、LoRA 规则、negative、工作流节点、默认参数或上游能力。

**必须先固定的决策场景：**两端都在线、只有一端可用、资源缺失、模型不匹配、采样器/调度器/放大能力不足、自动高清修复、脸部修复、探测后掉线。场景的预期分支来自现行行为和明确需求，而不是“架构看起来更统一”的主观选择。

**提交与结果语义：**

| 边界 | 必须保持的行为 |
| --- | --- |
| 服务端身份 | 使用服务端确认的 owner/授权上下文；不信任浏览器自报身份；不把令牌放入业务快照 |
| 提交前失败 | 明确未提交，是否重试按现有策略决定 |
| 已接收但响应异常 | 标为待核对；不得自动切换另一个 provider 重复生成 |
| 取消 | 区分请求取消、取消已确认和最终状态；不因本地 Promise 中止就虚构上游已停止 |
| 结果读取 | JSON 状态与二进制结果分开；保持现有结果消费时机和所有权检查，不为对照或诊断多读取一次可消费结果 |
| 服务关闭 | 按现有职责关闭计时器、连接与任务资源；不遗留另一套注册表 |

**提示词等价要求：**对中性夹具比较迁移前后的最终请求、编译文本和参数；结构性重构默认要求相同。实际变化必须单列为行为变更并重新确定验收，不能用归一化、排序或丢字段掩盖不同。真实模型画面仍需在相应授权和环境中单列验证。

**回退：**一次只切换一个生成链路，保留旧公开入口。回退前先核对在途任务归属，不能用关闭进程或重发任务代替迁移处理。若必须改变后端任务存储，拆成另一个独立方案，本批不顺带实施。

### 7.2 A06：明确谁拥有任务、谁只显示任务

**依据：**任务中心当前承担摘要、控制映射和恢复关联等职责，并将部分历史运行记录解释为中断；本地诊断也明确区分“同时活跃”与“因果关联”。[S14]、[S15]

**目标：**继续利用现有任务中心，不让 Store、页面和任务中心各自成为同一任务的第二个权威状态机。

| 子任务 | 执行内容 | 完成条件 |
| --- | --- | --- |
| A06.1 所有权表 | 对实际存在的生成、排队、语音、查看器、Live2D 和视频任务记录 owner、资源、销毁和恢复策略 | 每种资源有唯一清理责任；每个任务有明确状态来源 |
| A06.2 定向补缺 | 只修复表中已确认缺口，复用已有取消、session/revision token 和 dispose 能力 | 快速切换、失活/激活、销毁和迟到响应测试通过；不改变未授权的后台执行范围 |
| A06.3 恢复能力立项 | 仅当确需刷新/重启后继续任务时，评估持久化任务身份、服务端查询、幂等和恢复 | 没有需求则 deferred；不因架构计划而默认开发持久化执行器 |

**以下是建议契约，实施时必须与实际入口逐项核对，不表示现状全部已实现：**

| 生命周期事件 | 建议职责 |
| --- | --- |
| KeepAlive 失活 | 暂停纯展示开销；已接受任务是否继续由任务所有者决定，不由摘要组件重新提交 |
| 页面真正销毁 | 解除页面订阅与明确属于页面的资源；任务中心保留可解释摘要，不伪造上游成功/取消 |
| 切换角色或对话 | 旧语音/响应不得污染新会话；资源终止和迟到回调由相同会话身份保护 |
| 查看器关闭 | 释放其拥有的 Blob URL、解码任务和观察器；不删除原图存储 |
| 刷新页面 | 查询并关联已经明确保存的后端身份；无法证明可恢复时显示未知/中断，不重复提交 |
| 重启程序 | 仅在后端确有持久化与重连协议时承诺恢复；普通任务摘要不提供这种保证 |

页面生命周期、用户任务生命周期与上游任务生命周期不是同一件事。轮询停止不等于任务取消，HTTP 中止不等于 GPU 停止，任务列表重建不等于上游任务重建。

**状态与诊断要求：**由后端或本地执行 owner 提供任务事实；任务中心是投影。展示错误不能覆盖真实执行状态。需要关联请求时使用显式传递的本地关联 ID，不能把 `activeTaskIds` 当作因果证明。继续遵守当前诊断不收集请求体、提示词、令牌和私有媒体的边界。[S15]

**验收：**重复挂载/销毁、快速换角色、连续切页、迟到返回、重复取消、断网恢复、查看器反复开关。工程探针只证明所测资源，不将 Blob URL 数量稳定当作 GPU/纹理/进程内存全部稳定。

**回退：**按组件或任务种类回切适配，不同时保留两个任务执行 owner。任何超出当前后端身份恢复范围的需求单独评审，不在回退过程中补发旧任务。

## 8. A07：架构检查与持续治理

### 8.1 A07.1：让新边界可检查

**启动时机：**随 A01 第一批出现，不能等全部重构结束再补。

现有页面架构检查覆盖入口、路由、模块存在性和样式等约束；保留这些必要规则。新增检查关注实际依赖关系，而不是靠函数名、注释或文件字符串存在来证明业务正确。[S22]

**建议规则：**

| 规则 | 初始约束范围 | 失败条件 |
| --- | --- | --- |
| 公共业务定义独立 | 本计划明确迁出的类型文件 | 引用 Store、组件或 View；经再导出间接引入也计入 |
| 入册用例独立 | 新保存用例及其纯规则 | 依赖 Pinia/Vue 页面状态、Toast、router 或直接选择当前角色 |
| 存储独立 | 已整理的纯驱动与 Repository 边界 | 反向依赖展示层；生产装配绕过必需的保护路径 |
| 后端业务独立 | 已迁移的生成业务模块 | 导入 HTTP route 的核心实现，或依赖 Express 请求/响应对象 |
| 新循环受控 | 本批迁移模块及可达依赖 | 新增运行时循环；类型图与运行图分别报告 |

检查必须处理实际解析后的路径、别名、再导出、静态 `import`、`require()` 和可解析的动态导入。无法静态解析的动态路径作为 unknown 明示，不能报成“零违规”。测试、生成产物和 vendor 的范围单列，不把全仓忽略作为解决方法。

**建议脚本名：**`scripts/tests/test-module-boundaries.ts`，仅为拟议文件。实施后生成的运行入口、suite 注册和可用命令须同步登记；本文件不把它列入“现在已有”的可运行命令。

**验收：**正例允许正常依赖，反例覆盖别名绕过、再导出绕过、`require()`、Vue SFC 与类型/运行时差异。检查自身应有夹具测试；不能只在当前仓库上运行一次就宣称可靠。

## 10. 回退、交付与双机验收

### 10.1 全计划不可突破的边界

现有提示词定稿保护、分级与本机/远程接入限制、用户数据保护和源码/生成文件约定继续生效。[S24] 架构调整不更改 prompt/negative、模型参数、数据源内容、用户作品和远程授权规则；确有需求的行为变更另列，不用“重构”绕过审核。

不能为完成计划而删失败测试、把校验改成恒真、降低覆盖率或包体门槛、放宽路径/owner 检查、移除未知状态的拒绝行为。不能用历史通过记录代替当前受测源码的证据。

### 10.2 各类回退策略

| 变更类型 | 可采用的回退 | 不可采用的回退 |
| --- | --- | --- |
| 类型与纯规则 | 恢复兼容导出/消费者，回退受控提交 | 删除仍被调用的公共定义，留下半迁移模块 |
| 入册用例 | 入口级回切；保留已产生的合法记录 | 同时执行两套写入，或恢复旧数据库覆盖新作品 |
| API 解析 | 在保留安全约束下回切单端实现；保留问题样例 | 把未知状态强制改成成功或默认某个 provider |
| 后端分层 | 保留公开 URL 与兼容转发；核对在途任务后回切 | 通过重新提交所有任务来“恢复运行” |
| 存储路径调整 | 恢复旧导出路径，使用同一存储实现 | 顺带改变数据库版本、名称或删除缓存数据库 |
| 生命周期修复 | 按 owner/组件回切，确认只有一个执行者 | 留下两个播放器、轮询器或任务控制 owner |

一旦变更涉及持久化格式、后端任务身份协议或旧安装版不能读取的新数据，本计划的轻量回退不再足够；先补独立迁移/降级方案，再决定实施。
