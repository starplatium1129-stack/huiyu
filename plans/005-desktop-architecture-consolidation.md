### C：持久化结论与隔离证据

**推荐继续使用 IndexedDB 和现有仓储。** SQLite 按行更新在大量索引中有收益，但不构成本轮换库理由：当前浏览器访问仍需保留，换库必须新增服务 API、跨来源协调、媒体权限、旧版本兼容和备份切换；此次没有证据证明整体成本更低。可在明确的大库性能需求出现后，以作品域为首批候选，设置、聊天和临时草稿保持独立。

| 数据 | 当前所有者与写入路径 | 如果将来迁移作品域 |
| --- | --- | --- |
| 作品索引、收藏、回收站、项目引用 | `artworkRepository` 的串行队列与 `withArtworkMutation`；相关 KV 在 `aics_kv_store` 事务提交 | 网关作品仓储作为唯一写入口；桌面窗口与浏览器均走同一认证 API 和版本检查 |
| 原图与临时结果图 | `useImageStore` / `aics_image_store`；生成 store 先写图再发布索引，失败补偿 | 内容寻址文件目录；有持久暂存清单，元数据发布前验证文件，临时结果单独租约 |
| 缩略图 | `aics_kv_store` 的 `thumb:<imageId>` Data URL；可以按原图重建 | 单独文件缓存，可重建，不把缺缩略图当作缺原图 |
| 项目整体编辑、旧数据导入、备份恢复 | 现有各入口须持有同一个 Web Lock；备份先写新 ID 图片再原子发布索引/项目 | 由同一仓储事务操作项目关系；备份走明确版本的导入命令 |
| 设置 | `settingsRepository` 和各领域现有 LocalStorage 键；`storageKeys` 维护备份白名单 | 本轮不迁移；主题等首屏同步读取保留，凭据不混入作品库 |
| 聊天、归档与宿主配置 | `useChatStorage` 的 LocalStorage 写入/合并；服务宿主配置在 runtime state 独立 JSON | 不随作品迁移，沿用现有失败提示与跨窗口合并 |

Web Locks 仅协调同来源窗口，不能协调不同来源的 WebView 与浏览器库；缺少 Locks 时现实现拒绝不安全保存。推荐方案保留这个边界。服务统一方案若未来启用，必须取消同域双写并通过网关统一串行化/数据库事务；不能同时保留两份“主库”。

隔离原型 `artwork-sqlite.js` 使用 Node 内置 SQLite，没有新增依赖。每次在新临时目录创建 schema v1，媒体以 SHA-256 命名，写临时文件并 fsync 后 rename，再用 SQLite 事务一次发布索引、关系和 ready 标记。迁移 ID 绑定完整源快照指纹，同 ID 重跑幂等；源变化或文件损坏拒绝继续，半完成媒体只成为未发布孤立文件。七项故障测试覆盖媒体写后、事务中、提交后中断重开，以及重复迁移、源变化、损坏、较新版本拒绝、悬空引用和丢弃候选后的备份保留。原型只证明进程中断下的协议，不证明 Windows 断电时目录 rename 的持久性；正式实现还需断电/磁盘满/多进程/病毒扫描占用验收。

同机基准见 [原始 JSON](../docs/evidence/desktop-storage-prototype-2026-09-12.json)，复跑入口为 `npm run wf -- desktop:storage-benchmark`。Node 24.18.0、Windows x64、Edge 153.0.4234.32；每规模三轮、每轮新私有浏览器上下文与 SQLite 目录，以下为中位毫秒。

| 负载 | IndexedDB | SQLite 原型 |
| --- | ---: | ---: |
| 1,000 索引：整体写入 / 30 次收藏更新 / 全量读取 | 9.30 / 86.50 / 0.70 | 2.98 / 10.08 / 1.39 |
| 10,000 索引：整体写入 / 30 次收藏更新 / 全量读取 | 47.20 / 639.80 / 5.00 | 35.31 / 9.39 / 10.90 |
| 64 对原图 256 KiB + 缩略图 16 KiB：写入 / 全量读取 | 35.10 / 32.10 | 105.28 / 10.92 |

IndexedDB 测量使用实际仓储/锁、原图 Blob 与 KV 缩略图接口；SQLite 使用按行索引及原始媒体文件。素材是合成字节，不含解码/缩图时间；SQLite 没有网络/IPC 开销，两者持久化策略也不完全相同。记录数、收藏数与读回字节均校验，结果只支持候选比较，不能宣称生产速度提升。

将来真迁移时的可执行顺序：

1. 显式进入维护模式，阻止所有窗口写入，导出旧版可读的带版本/数量/哈希清单备份，记录来源 origin、库版本和设备路径；保留原库与原图。
2. 建立独立 v1 候选，迁移 ID 绑定备份指纹；逐批复制原图、缩略图和元数据，保存检查点；中断后只补缺项，不覆盖来源。先拒绝未知版本、重复 ID、悬空项目/图片引用。
3. 对账索引、项目、回收站引用、每个原图哈希及备份可读性；未发布的暂存/孤立文件仅在清单可证明无引用后清理，回收站保留 30 天规则。正在使用和取消中的任务图片不参加回收。
4. 所有客户端关闭旧仓储连接后，原子切换唯一仓储指针。旧版客户端在 schema 不兼容时拒绝写；不要让旧版软件把旧库的新写入伪装成同步成功。
5. 切换前失败只丢弃候选并解除维护；切换后、尚无新写入时恢复旧指针。如果新库已有写入，先导出增量到旧版可读备份并验证再回退；不能直接回旧快照而丢作品。旧库在完成实际安装/恢复验收前不删。

以上切换、备份与回滚步骤是后续生产设计，原型未实现真实库扫描、客户端维护协议和切换指针，本轮不运行生产迁移。

### D：恢复结论与故障注入

**生产保留现有恢复行为，后续优先建设持久日志和按后端 ID 对账。** 自动重提交、继续下一镜和自动入册都属于新功能，未启用。新增 `task-recovery.js` 仅供隔离测试，恢复接口没有 submit 方法。

| 链路 | 当前 ID 与边界 |
| --- | --- |
| Anima / Krea 2 / WAI Comfy | 网关 job ID 与内存 `upstreamId = prompt_id`；网关存活可查，崩溃后无持久上游 ID |
| WAI WebUI | 本地网关 ID；同步 txt2img 接口没有当前接入可查询的后端任务 ID，丢失响应只能明确中断 |
| 单视频 | 内存 Comfy ID；界面可按网关 ID 重连。`job-snapshot` 只保存最小 tombstone，重启时报告 410 `JOB_LOST`，读后即删，再次重启不保留 |
| 视频分镜 | 内存批次、逐镜 job/prompt ID；顺序、尾帧关系和拼接进程未持久，不能重启后直接调用批次 `kick()` |
| 任务中心 | 本地摘要与部分 backend ID；重载把历史 running 变 interrupted，不能将摘要当作后端运行事实 |

窗口关闭与退出不同：Tauri 的 atelier/companion/chat 关闭是隐藏；显式退出会 kill/wait 自有网关，不保证 Node 优雅关停，外部附着网关不归它清理。界面卸载时 SD/Anima disposal 尝试取消，视频只停止页面轮询；网关崩溃后 Tauri 健康监控恢复网关并导航重载。模型断开时，有 ID 的任务优先查询，不能重新 POST；休眠唤醒的 `aics:resume` 应先对账已完成结果，再应用超时。

原型状态迁移：`prepared → submitting → running → succeeded/failed/cancelled`；提交中或运行中可进 `cancelling → cancelled`。未知提交结果、后端身份变化、历史缺失或无法确认的超时进入 `interrupted`，`upstreamSettled=false` 保留。终态不可复活；迟到 prompt ID 只补身份，不清除取消意图。这里 succeeded 仅表示观察到后端成功，未声明结果已取回或保存。

日志采用单写者、schema v1、递增序列、前序哈希、校验和及记录 revision，落盘后再更新内存；损坏日志整体保留并禁止恢复副作用。记录包含 owner 哈希、request key/参数哈希、引擎/后端指纹、上游 ID、提交/取消/截止时间和结果处置，不存提示词正文、凭据或图片。发上游请求前持久化 submitting，得到 prompt ID 后立即记录；同 `(ownerHash, requestKey)` 和参数返回既有任务，参数变化拒绝。提交已到上游但 prompt ID 应答丢失时，当前后端契约无幂等键反查能力，必须中断而非猜测重提。

取消意图先持久化，每次 await 查询后重新读取消状态，取消请求先落盘则迟到成功结果标 discard。HTTP 取消应答不当作完成证据；只有经过验证的定向幂等取消才能按相同上游 ID/取消键重试。原型 30 秒取消期限、5 秒重试间隔仅为夹具；生产仍保留 Anima 的队列/历史双次确认、旧 Comfy 定向删除回退和 WebUI 全局 interrupt 的差异。不得用全局 interrupt 代替未知 ID 取消。

十九项隔离故障测试覆盖重复/并发恢复、取消与完成竞态、迟到提交应答、网关响应/上游 ID 响应/取消响应丢失、日志尾部撕裂/校验和/序列/字段损坏、后端变更、历史缺失、休眠超时及清理边界。清理只返回预览候选，要求终态、已确认上游结束、无待交付结果且超过保留期限；未知上游状态及幂等 tombstone 不自动清除。

上线前还需跨进程独占、坏日志修复、owner/后端重新授权、输出校验与交付回执、幂等取图、批次关系及取消策略。原型校验和不防恶意修改或完整前缀截断，文件 fsync 不代表目录持久性或断电验证。主力机 WebView2 的隐藏恢复、重载、退出、网关崩溃、模型断连、休眠、跨显示器及安装/UAC 仍由 V04/V05/V07 追踪，未把隔离测试计作原生验收。
