### 基线证据与本次修复

[Quality 运行 35238860129](https://github.com/starplatium1129-stack/huiyu/actions/runs/35238860129) 的 Static & Quality Checks 中，生产构建及包体预算通过；`npm run check` 的 17 个子步骤中 15 项通过、2 项失败。失败根因为 `test-tag-shards.js` 漏登记，以及 `randomPromptAssembler.ts` 的未使用导入 `mutualGroupOf`；关键浏览器道随后被跳过。包体预算虽通过，仍有接近上限的 warning，不应放宽阈值掩盖。

[Nightly 运行 35275471843](https://github.com/starplatium1129-stack/huiyu/actions/runs/35275471843) 为 97 通过、1 失败；失败是工作区状态栏数量断言，并非像素差异。测试进入空白导演台后只切换模式，没有选择场景，但 `PromptBuilderView.vue` 仅在非专家模式且有场景／热门角色上下文时渲染归档栏。

本次受控修复：

- `scripts/tests/quality-test-inventory.ts`：把现有 `test-tag-shards.js` 纳入 contract 道，与分片完整性测试同类；不删测试、不重复登记。
- `src/utils/randomPromptAssembler.ts`：仅移除未使用导入；不修改随机逻辑、提示词、评级、角色或服装数据。
- `tests/e2e/particle-narrative.spec.ts`：分别验证空白导演台、有场景的状态栏及专家模式往返；其余工作区按路由拆成独立用例，保留唯一性、可见性与真实上下文断言，不添加固定等待或更新快照掩盖失败。
- `.github/workflows/nightly-e2e.yml`：原截图目录 `.review-shots` 被 hidden-file 默认过滤，日志显示无文件上传。仅对 `.review-shots/*.png` 开启隐藏目录上传，缺图改为报错，失败时仍保留上传；不扩大权限或上传工作区其他隐藏文件。
- `scripts/tests/test-e2e-ci-split.ts`：增加截图上传守护，防止路径、hidden-file opt-in、失败时上传或缺图报错契约再次丢失。
