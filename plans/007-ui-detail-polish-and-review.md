## 1. 目标与已确认方向

沿真实创作流程，把控件一致性、信息层级、浮层布局、材质和操作反馈逐项打磨到可交付：

**选择角色 → 选择场景 → 调整参数 → 提交与等待 → 查看、比较和保存结果。**

用户已经确认的方向，执行者不再重新解释成其他风格：

- **同心圆角**：带胶囊外框的分段切换，选中块也为胶囊，端部与上下等距，内外弧线协调。参照工作台“场景模式 / 专家模式”的关系；不能再用大胶囊包小圆角矩形。
- **形状分工**：普通按钮、输入框、卡片和弹窗用按尺寸分级的规则圆角矩形；圆形图标按钮保持正圆。不能把全部控件改成胶囊。
- **材质与背景独立**：液态玻璃不要求彩色背景。保留现有背景体系，不为突出玻璃新增彩色渐变、光斑或壁纸。
- **内容优先**：玻璃服务于导航、悬浮工具层和必要的浮层结构；正文、提示词、参数、角色列表有稳定阅读底色。减少套框和重复强调，不以增加描边、阴影数量代替层级设计。
- **审美必须实看**：覆盖了页面或通过了测试，不代表页面更好看。必须在真实页面、正常背景和完整操作过程中比较。

本计划不重写前端框架，不更换 Tauri，不改变提示词、模型参数、角色/服装绑定、分级、作品存储或生成业务。遇到必须跨越这些边界的问题，单独列出原因与方案，不顺手修改。

## 3. 实施批次

每批状态只能是：**待实施 / 实施中 / 待审核 / 返修 / 已验收**。执行者可以完成下一批的只读盘点，但有依赖的推广应等前一批审核结论，避免把尚未认可的设计铺满全站。

**工作**：记录实际分支、提交、构建标识和运行环境；沿主流程列出控件家族与状态。核对隔壁 `D:/code/Deepseek-harness-destop/docs/apple-design-reference.md`、`desktop-interaction.md` 的当前版本；它们是参考，不是要求照搬的业务和 Electron 实现。

**验收**：样张真实连接；截图没有因测试网关缺配置而误显示离线；能区分现有能力与本批新增。不先批量改 CSS。

### U1：角色选择流程（首个实施批次）

**入口**：`src/components/director/DirectorCharacterPanel.vue`、其组件 CSS、`src/components/popular/PopularCharacterPicker.vue`、`src/components/library/CharacterDirectory.vue`。

**工作**：

- 整理“角色来源 → 当前角色 → 浏览/更换”的层级，减少重复入口和重复边框；保留清晰的更换方式、搜索和来源说明。
- 将来源选择作为一组互斥选项设计。标签长度超出容器时采用可读布局，不压成竖排文字，不靠减小字号塞入。
- 统一作品名的展示策略。优先复用已有名称/别名字段；不编造翻译、不直接修改角色源数据。无中文字段时明确回退，并处理长名称。
- 优先试做角色弹窗的“作品筛选侧栏 + 角色结果区”，窄屏再折叠筛选；若选择其他方案，说明为何更适合当前数据量。

- 明确当前选中、筛选结果、空结果和返回位置；打开后能方便定位当前角色。关闭不丢选择和必要的搜索上下文。

**验收**：鼠标与键盘均完成“打开 → 搜索 → 按作品筛选 → 选择 → 返回工作台”；覆盖长作品名、无结果、跨页、当前角色不在筛选内、反复打开、Esc、焦点恢复。截图必须包括用户指出的选择区和完整弹窗，不只拍一张卡片。

### U2：场景与参数工具区

**入口**：`SceneExplorerView.vue`、`PopularSceneExplorerView.vue`、`PromptBuilderView.vue`、`src/components/director/`、`src/assets/css/director/`。

**工作**：

- 区分分段切换、筛选标签、普通按钮、状态标签、图标按钮；同一语义采用同一尺寸/圆角/内边距与状态语言。

- 检查正常、悬停、按下、选中、禁用、聚焦、忙碌与失败状态，尤其是未选中项不能比选中项更突出。

**验收**：场景/专家模式来回切换不丢草稿；来源/场景/模型区域的状态仍对应业务实际。可用隔离夹具测试任务状态，但不得真实触发模型调用来验证纯 UI，也不得改变参数来配合截图。

### U3：浮层、抽屉与结果查看

**入口**：搜索/确认/任务弹窗、`FluidTransition.vue`、故事抽屉、`CandidateCompare.vue`、样张与作品查看器、参考图灯箱、分镜脚本弹窗、局部换装和备份恢复浮层。

**工作**：

- 区分小菜单、非模态辅助面板、模态表单和全屏图片查看器，不让它们全部使用相同的位移、缩放、遮罩和外观。
- 统一标题、关闭入口、正文与底部操作的留白关系；根据弹窗尺寸设置圆角。图片画布不承受整块玻璃滤镜。
- 检查关闭动画期间内容是否提前清空；反向、重开、切页和隐藏窗口后是否保留过期动画或焦点。
- 分别处理原生 dialog 与普通 Vue 浮层；焦点锁定、背景滚动、Esc、点击背景关闭和破坏性操作默认焦点不能退化。

**验收**：连续快速开关、关闭中重开、三次完整关闭后重开、正在输入时后台刷新、路由离开；结果对比/筛选/缩放不丢状态。用录屏检查衔接，不以动画参数或静态图替代。

### U4：液态玻璃在真实页面中的表达

**入口**：现有玻璃模块及 U1–U3 确认过的结构层。先选主导航、一个悬浮工具栏、一个浮层顶部做小样。

**工作**：

- 背景保持原样。通过材质自身的填充、边缘厚度、高光与适量折射形成质感，不能添加彩色背景来制造效果。
- 在正常内容滚动经过时观察玻璃与背景的关系；如果某区域本来没有背景信息，不应强行加折射或宣称它明显可见。
- 正文和控件文字保持稳定可读，避免多层玻璃叠加。高光不能盖住文字，边缘不能出现断裂、黑边或显著色偏。
- 清楚区分“精细玻璃”和“低效果稳定底色”；减少透明度、高对比、强制颜色模式均有完整回退。

**验收**：相同页面、相同背景、相同滚动轨迹，录制修改前后及效果开关对照；同时给出整页和局部。真实 WebView2 中验证。校准网格的折射差异只能证明技术工作，不能单独关闭本批。

### U5：推广与排版收尾

按已验收的组件规则推广到画册、作品册、角色档案、画风、模型、色彩情绪、剧本、视频、聊天、控制室、维护页和独立桌面窗口。每页登记具体处理、合理保留与未覆盖状态，禁止仅加一份全局覆盖文件就报“全站完成”。

重点核对长文本、中英文混排、图标对齐、标签基线、空状态、错误恢复和高密度面板。检查普通桌面、窄窗口、390px 布局，以及安装版常用缩放；实际 Windows DPI 与浏览器视口模拟分开记录。

### U6：桌面交付与最终复审

使用 [桌面部署指南](../docs/desktop-deployment.md) 的唯一入口。前端变化使用增量流程；依赖或原生 exe 改动使用完整安装。执行者负责准备、部署和清理，审核者复核证据和必要的定向验证。

**完成条件**：

- 实际安装目录的前端文件与交付构建对应；原生变化有正确安装包与重启证据。
- 桌面端使用期望的网关与素材配置，样张索引、缩略图和原图实际可读。
- 深浅主题、降低效果、系统减少动效、缩放恢复、主要流程和退出恢复已检查；任何缺口明确保留。
- 原有偏好得到恢复；临时服务和调试端口得到清理；没有误停用户自己运行的服务。
- 审核者给出明确结论后，才将对应批次改为“已验收”。

## 4. 运行环境与已发生过的失误

2026-09-14 的样张“断连”曾由验收遗留的临时网关导致：临时服务占据 `3000`，桌面壳复用它，但其隔离配置未连接样张。退出临时网关后，安装版服务恢复；当时索引 1,566 条、抽查原图/缩略图及画册显示正常。这个数量是历史检查点，不是后续验收的固定期望。

执行者必须：

1. 为测试使用独立端口和 runtime，记录自己启动的 PID、命令、端口和关闭方式。Vite 代理也必须确认指向谁；不要只改前端端口，后端仍占用桌面默认端口。
2. 测试结束核对桌面正在使用的网关进程路径和素材配置。只关闭自己启动的服务；不要按“所有 node 进程”批量清理。
3. 样张位置优先读取当前配置。历史本机目录为 `D:/AI-CG-Studio/AI/SceneShowcase`，其中有发布集合；不能把该绝对路径写死进产品或要求另一台机器照搬。
4. 检查发布索引及至少一个实际缩略图/原图，并在画册中确认图片解码成功。HTTP 200 的 HTML 回退不算图片成功。
5. 实际安装验收确认使用安装目录的网关；开发服务器跑通不算安装版跑通。
6. 测试录屏/trace 放在已忽略且不触发 Vite 热重载的目录。不要让生成的 trace HTML 造成测试中途自动刷新。

另一个已修复失误：Vue scoped CSS 中不完整的 `:global(...)` 写法曾把“隐藏加载条”编译成“隐藏 html”。系统减少动效回归必须确认页面仍可见，不能只检查动画停止。

## 6. 审核方式

当前 Codex 会话按用户分工负责审核，不继续承担批量实施。收到交付包后：

1. 核对范围、差异、基线与构建标识，确认没有夹带数据、服务、存储或不相关页面改动。
2. 先看同条件前后图，判断层级、圆角、留白和可读性是否确实改善；再看录屏，判断反馈和连续性。
3. 对关键路径做必要的只读/隔离复现，复核焦点、状态与回退。不能仅引用执行者的 PASS。
4. 输出“通过 / 局部通过 / 返修”，每个问题附页面、操作、现象、期望、严重度和证据位置。
5. 返修由执行者完成，再回交。审核通过不等于自动部署或替执行者修改代码；依据该批已有任务授权处理交付。

以下任一情况直接返修：同心圆角退化；用彩色背景替代玻璃材质改进；只给校准方块；双主题只检查一边；用缩略总览掩盖裁切/重叠；浮层丢焦点或内容；素材假断连；缺少最终构建对应关系；把“已实现”写成“全站全部验收”。

无需等待的独立准备：记录文件位置、读取已有契约、准备隔离数据、整理缺口。需要用户审美裁定的分歧，交 1–2 个同条件、可操作的小样和明确差别，不让用户面对未落实的抽象选择。
