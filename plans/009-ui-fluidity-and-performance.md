## 2. 范围与不可牺牲的边界

### 2.1 本专项要改善的体验

- 点击立即确认；请求处理中、任务成功和失败是不同状态，不用乐观动画伪造完成。
- 普通切页时应用框架稳定，旧内容与新内容交接清楚；不先清空页面再无期限等待。
- 新内容可用后能够立即操作，不等待装饰性动画播完；连续导航、取消和返回响应最新意图。
- 场景库、作品册和样张的滚动/筛选稳定；回到列表能恢复合理的位置、筛选和选择。
- 开启桌宠、语音或运行生成任务时，界面仍有可预测的反馈；资源不足时有明确、可恢复的降级策略。

### 2.2 本专项不做什么

不重做 JavaScript → TypeScript 迁移；不全量改成 C/Rust；不更换 Vue/Tauri；不重新设计全站视觉；不新建一套通用动画引擎；不因为“苹果风格”增加全屏模糊、层层缩放、长入场或强制滚动接管。

不修改模型、生成参数、定稿场景、提示词、内容评级或作品存储格式。音频 C/WASM 内核、模型推理加速和数据库迁移只有在独立测量证明必要后另立范围，不夹带进界面专项。

### 2.3 必须保留

保留深浅主题、键盘导航、焦点恢复、减少动态效果与现有低效果偏好。高频动画遵守仓库 `transform` / `opacity` 红线；例外按 AGENTS 留理由和评审证据。保留手绘线条图标、品牌色与内容可读性。

保留 CSP、麦克风权限、任务中断确认、本机/远程内容分级和 fail-closed 行为。过渡快照、缓存和提前解码也不得绕过分级遮罩或加载未授权内容。禁止为无缝切页全局开放 `unsafe-eval`、移除权限策略或无条件取消文档重载。

导航“最新意图优先”只适用于导航与可取消的读取。保存、生成、删除等写操作继续遵循各自事务、幂等和取消契约，不能因为切页就静默丢弃已发出的写任务。

## 4. 测量口径与拟定目标

### 4.1 先区分四种“快”

| 指标 | 起点与终点 | 不允许的替代判断 |
| --- | --- | --- |
| 输入反馈延迟 | 输入事件时间戳 → 按压、待导航或忙碌状态首次可见 | 函数执行完、Vue nextTick 完成不等于已经显示 |
| 页面主要内容就绪 | 本次导航意图 → 主要内容和首个必要操作可用 | route afterEach、占位出现、动画结束不等于内容就绪 |
| 运动稳定性 | 指定过渡/连续滚动时间窗内的帧节奏与渲染开销 | 平均 FPS、rAF 次数、无长任务不能单独证明真实呈现平滑 |
| 稳态资源成本 | 预热后同一使用序列的 CPU、堆、进程内存和 GPU 记录 | JS heap 不是整个 WebView/原生 overlay/GPU 的内存 |

新增测量可使用导航唯一 ID 和 `performance.mark/measure`，建议事件为 `intent`、`feedback-committed`、`shell-ready`、`primary-ready`、`settled`、`cancelled`。它们是**拟新增的契约**，不是现有接口。取消样本单列，不混入成功导航耗时。

DOM 提交、rAF 或双 rAF 只能作为近似信号；首次可见反馈与掉帧判断应结合浏览器 trace 的呈现信息和真机录像。支持 Event Timing/Long Tasks 的环境可补采，缺失时标为 unavailable，不填 0。脚本化单次交互延迟不冒称完整页面生命周期的 INP。

### 4.2 F0 需要冻结的目标与预算

以下是本项目的**初始工程目标，不是 Apple 标准或当前实测成绩**。F0 固定机器、刷新率、数据集和波动范围后登记版本；若目标不可行，保留差距及理由，不悄悄放宽阈值。

| 项目 | 初始目标 / 验收规则 |
| --- | --- |
| 常见本地操作反馈 | 目标 p95 ≤ 100ms；实现上尽可能下一可呈现帧响应，不人为等计时器 |
| 普通热切换主要内容就绪 | 在指定模块、数据与必要缩略图已缓存的夹具上，目标 p95 ≤ 300ms；不等待装饰性动画收尾 |
| 冷进入与跨策略重载 | F0 分别记录分阶段耗时并设路由预算，不套用 300ms 热切目标；之后必须无已确认退化 |
| 60Hz / 120Hz 帧预算 | 显示间隔分别约 16.7ms / 8.3ms；这不是全部可用于应用 JS 的时间。固定前台测试窗内以帧时间分布和渲染 trace 验收 |
| 掉帧候选阈值 | F0 可用静止前台的有效间隔 T 校准：rAF 间隔 > 1.5T 的比例目标 ≤ 1%；必须与真实呈现证据配对，单独达标不关闭掉帧问题 |
| 主线程长任务 | 指定纯过渡/稳定滚动窗口内，目标不产生可归因于应用处理的 >50ms 阻塞；50ms 以下仍可能丢帧，不能只查这一项 |
| 返回现场 | 同一数据版本的夹具中恢复筛选/选中项；布局稳定后同一滚动锚点误差目标 ≤ 2 CSS px；数据变化时按稳定 ID 回落，不强行旧像素位置 |
| 资源生命周期 | 预热后完成 20 轮往返及三组稳态快照；活动监听器、观察器、ticker、可达离屏 DOM 不得因每轮切页持续累积；进程/GPU 趋势单独报告 |
| 安全与可访问性 | 越权、漏遮罩、旧页面误响应、焦点丢失、写任务丢失等正确性回归为 0；性能变快不能抵消 |
| 构建预算 | 沿用当前构建门禁，不通过提高预算、忽略失败或缩减数据夹具制造通过 |

p50/p95 使用全部原始样本计算：每条成功交互路径至少 20 次，记录三轮独立运行及预热方法；不足 20 次的冷启/设备样本保留原值并标记样本不足，不做稳定 p95 声明。新鲜 browser context 不是磁盘/OS 缓存完全冷启动，必须写清“冷”的范围。

比较必须固定源提交/构建标识、数据集、素材模式、浏览器/WebView 版本、视窗、DPI、刷新率、电源状态和并发负载。先 A/B 同条件复测；超出基线波动且超过 10% 的交互延迟/资源成本退化作为调查线索，不直接把机器噪声写成代码结论。反复确认的退化不得直接通过。

| ID | 操作序列 | 重点观察 |
| --- | --- | --- |

## 6. 每批验证与提交规则

本节是后续执行指南，**不是本次已经运行的命令记录**。入口以执行时的 `package.json`、`scripts/workflow.ts` 和工作流手册为准；生成的 `.js` 不手工维护。

| 改动类型 | 必须核对的验证 |
| --- | --- |
| 仅计划/索引文档 | Markdown 结构、相对链接与索引；具备完整工作区时 `npm run wf -- docs:check`；不因文档提交运行真实模型或全量 UI |
| composable/纯状态逻辑 | 对应单测、前端类型检查，导航/取消/激活场景回归；按范围选择 quick gate |
| 页面/CSS/动效 | 受影响页面行为测试、双主题与 reduced-motion 视觉审查、相关样式门禁；引用同一次生产构建做对比 |
| 列表/缓存/Worker | 正确性、失效/取消/释放测试，同数据基准，构建预算；验证预热不产生业务写入 |
| 公共路由/构建/测试配置 | 实际测试发现列表、相关关键回归与构建；按工作流判断是否需要完整门禁 |
| 原生/桌面资源 | 对应构建和契约检查，实际设备/安装验收单列；无设备不能代替通过 |

可复用入口：`npm run typecheck:app`、`npm run test:frontend`、`npm run build`、`npm run test:e2e:performance`、`npm run wf -- gate:quick`、`npm run wf -- gate:full`。不机械逐批全跑，也不把不同工作流入口的“是否自动 build”视为相同；性能入口应指向明确的生产产物。

性能与普通回归分开执行。测试环境使用已核对的隔离端口/runtime 配置和假设备；现有 Playwright 在非隔离开发环境可能复用服务，执行前确认不连生产实例。使用 fixture 的通过不等于真实素材、麦克风、GPU 或模型可用。

提交要求：一个独立改动对应一个可回退提交；写入前检查 `git status` 和 `git diff`，只暂存受控文件，保护其他会话。直接提交 main 时也禁止 force push。远端推进或目标文件变更时重新读取/合并，不覆盖他人修改。测试通过后提交并推送，再核对远端内容。

每批结束必须报告：改动文件、实际测得的收益/代价、测试命令及结果、未执行项、提交标识、下一批前置条件。不能用“编译成功”“没有报错”替代操作流畅度验收。

## 7. 证据、复盘与完成定义

### 7.1 证据存放建议

F0 可建立 `runtime/ui-fluidity/<run-id>/` 保存原始 JSON、trace、视频和截图；该路径是**拟使用的本地输出目录**，写入前确认忽略规则。只在 `docs/evidence/` 提交小型去敏摘要与证据索引，不能把聊天、提示词、凭据、个人作品或绝对素材路径带入 Git。

每份摘要至少包含：批次、场景 ID、基线/受测提交、构建 SHA-256、机器/OS、浏览器或 WebView 版本、显示刷新率/DPI、夹具哈希/素材模式、负载、采样数量、原始结果位置、统计方法、预算版本、通过/失败/未运行和回退决定。字段未知时填写 unknown，不猜数值。

资源证据分 JS heap、WebView 进程、Node/原生进程和 GPU；构建证据分源码、前端产物和安装包。不得将一种标识或指标当作另一种。

“已实现待验收”不改成“已验收”直到有对应环境证据；批次部分延期时列出具体任务 ID、缺失条件和可继续的独立事项，不能让一个设备缺口掩盖其他工作，也不能绕过前置正确性问题。

### 7.3 最终完成的判据

用户在主要流程中能够连续操作：及时收到反馈，加载期间不迷失，返回不丢现场，动画不挡下一步，滚动不出现已知可复现停顿，默认与低效果模式均可靠。与此同时，安全/数据/可访问性没有退化，目标桌面负载和稳态资源有测量依据，后续变更有回归保护。

达到上述覆盖范围后才声明“本专项验收完成”；设备缺口、冷进入或重负载下仍存在的限制必须同时公布。**不承诺所有硬件恒定高刷，不把代码语言、毛玻璃数量或动画时长当作流畅度。**
