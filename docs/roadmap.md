## 后续工作流与内容数据治理

详见 [专项计划 006](../plans/006-workflow-and-content-governance.md)，与 005 衔接，不重复建设用户作品存储或任务系统。W1/W2/D1–D4 已有部分实现，D5 第一批经[保存链复审修复](archive/audits/scene-save-review-2026-09-13.md)；完整阶段状态以 006 文末为准，以下为剩余工作的顺序：

1. **优先**：明确人物、服装、场景和资产的字段归属、稳定 ID 与源／产物边界；同时整理工作流的机器条件、副作用和命名。
   场景添加按 006 的 D5 细化：统一 ID 分配、变更集与版本冲突检测、稳定分片和清单完整性；区分项目自带内容维护与安装版用户自建内容。
   **D5 第一批已实施（2026-09-12 办公机）**：服务端稳定 ID 分配、保存基线版本冲突（409 可解释差异）、增量分片写入与源分片完整性校验已落地并通过隔离测试；剩余为变更集提交协议、越过 sc999 的 ID 格式迁移，以及与 D2 影响预览的衔接。安装版用户自建内容仍属独立产品能力。
2. **随后**：完善已有只读变更影响与交付证据报告，补齐可证明的增量结构检查、证据失效和完整双机交接。
   **资产分发同列优先项**：按 006 的 R1 规划“随包基础图片＋独立高清资源”，确保离线首次进入不空白；先验证回退与下载／离线导入，再减少安装包资源。当前不删除图片或配置外部托管。
   基础资源清点与首页/角色详情缺图回退已部分交付，见 [N1/N2 验收](research/engineering/six-task-review-2026-09-13.md#n1n2-首页与角色详情图片回退)；这不替代独立资源包及全新安装离线验收。
3. **再后**：审核状态与来源证据、维护中断及回滚演练；保持定稿保护与真实出图要求。
4. **按测量结果决定**：资产存储治理、目录加载／搜索性能、现有编辑工具效率和版本兼容性，不默认增加新编辑器或迁移静态内容数据库。

**新增优先修复**：蓝图维护保存目前只写聚合文件，而网关启动按权威源分片重建。真实存储/自愈函数在隔离目录已复现修改被旧源覆盖；完整 HTTP/UI 保存尚未复验。需修复保存/源分片/回滚的一致性及隔离校验根目录，不直接对生产库执行反向导入。后续模型分工见 [GLM 分批任务包](guides/engineering/glm-flash-next-batches.md)。
