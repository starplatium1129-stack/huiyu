## 正式安装与切换

1. 安装前在 D 盘保存当次完整 profile 与 config 副本，分别 814 文件 / 65,836,236 bytes、160 文件 / 197,504,086 bytes；复制前、副本、复制后三方逐文件 SHA 一致。
2. 通过唯一 `deploy-desktop.bat -UseInstaller -QuietInstall -SkipBuild -NoRestart` 安装到 `D:\AI-CG-Studio`，UAC 由用户处理。安装 EXE 与真实解出的 NSIS payload 相同；Tauri 在包内把 bundle marker 的 3 字节 `UNK` 改为 `NSS`，因此不误用未打标 release EXE 的 hash 作为安装 hash。
3. 使用真实默认 C 盘 profile/config，在原 `3002` 来源通过维护屏障、D 盘独立迁移包读回及真实宿主验证，激活 SQLite workspace。没有设置 isolated profile 来绕过发布门槛，没有重导入，也没有合并历史来源。
4. 旧来源实际读取暴露全局 `no-referrer` 与私库 GET 来源校验的冲突。热修仅让私有同源 fetch 发送 origin 根 Referer；私人 JSON 的 session、Origin/Referer 与 Host 校验不降级。DOM 媒体独立使用短期单对象 capability、精确 grant origin/Host 和 same-origin Fetch Metadata，隔离真实浏览器页面已验证 206；正式来源没有媒体，未进行生产视频播放。
5. 热修后的最终包来自干净 `ee53cee0` 隔离工作树，启用经过安装验证的发布标记，未混入原工作区并行修改。再次通过同一部署入口完整安装；EXE 与实际 NSIS payload、41 个运行时文件均逐 SHA 匹配。
6. 在真实旧来源确认私库读写与资料水合后，通过可见的“启用独立启动界面”入口及宿主命令完成备份/恢复核验，正常退出并重启。最终来源为 `http://tauri.localhost`；Atelier、Companion、Companion-chat 三个真实窗口使用同一 workspace，未发生按端口新建库。
