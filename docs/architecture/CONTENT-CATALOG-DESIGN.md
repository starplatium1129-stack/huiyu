# 记录式内容库

更新：2026-10-04。

## 权威与发布

每个运行环境以运行目录下的 content/catalog.sqlite 为唯一可写内容库。Rust 记录服务负责人物、服装、工作室场景、热门蓝图与维护文档；Pinia 和编辑草稿只是缓存。JSON 用于显式快照、初始化和 Git 审查，不与 SQLite 双写。

data/catalog/manifest.json 声明逐条快照，每条包含 kind、id、revision、sortOrder、createdAt、updatedAt 和完整 data。服装以“角色ID/服装ID”为记录键，生成时重建原有 outfits 视图。人物的档案与图像身份分别保留在 profile/popular，英文引擎表达与中文档案不自动互译或拼接。已有字段及扩展字段原样保留。

首次启用优先读取快照；旧安装没有快照时，从现有个人分片导入，保留个人修改。启用标记存在而数据库缺失或损坏时拒绝服务，不用内置内容静默覆盖。既有个人库也不会被升级包的快照覆盖。

参考图片继续使用 data/references/ 与原有审核发布流程；模型运行配置、推理资源与作品 workspace 不属于本次存储迁移。固定 LoRA 控制配方仍由程序配置维护。

## 记录与事务

查询返回分页摘要，详情与修订历史单独读取。索引覆盖类型、角色、分类、分级和展示顺序；查询参数用 SQL 绑定，排序限定于已知模式。

普通修改携带 expectedRevision，可以提交完整 data 或递归字段 patch。缺省字段保持原值，显式 null 保留为 null；稳定 ID 不允许通过普通编辑改名。不同记录的更新独立比较修订，同一记录冲突拒绝整批。预览执行相同规划与约束后回滚，不留下修订历史。

保存将记录、标签改名、下架引用清理和修订历史一起提交。人物、服装及默认服装关联经过校验。定稿字段只允许保持原值，或与真实出图后经 pin-capture 更新的保护基线完全一致；普通请求不能修改保护基线。

下架记录保留身份和历史，不能复用其 ID。JSON 快照包含当前记录及下架记录；恢复快照不会恢复另一台机器完整的本机修订历史。

## 导入与排序

工作库保留初始化/上次导入的种子值。导入比较种子、本地值和新快照：未修改记录可更新；本地修改与未变化的输入可共存；双方修改同一记录且结果不同就报告冲突。缺失记录不隐式删除，下架必须显式声明。

展示顺序独立于文件位置。最近新增使用真实 createdAt；旧内容没有可靠时间则为 null，不以导入时间或 ID 冒充。相同排序值以稳定 ID 收口。智能排序使用策展和已有个人偏好，不再以故事长度或字段数量推断质量。

## 运行与维护入口

前端通过 /api/catalog 查询摘要，通过 record、history、character、changes、import 和 export 子入口维护内容。写入与完整内容查询仅限本机；远程发布仍须通过原有审核和字节绑定，内容变化会撤销旧发布的可服务条件。

原有静态 JSON 消费者读取数据库生成的视图。热门蓝图按角色加载，保留请求去重及过期响应保护。维护页、人物图片绑定和视频蓝图读取使用同一内容库。

维护入口为 npm run wf -- content:catalog --help，详细操作见 [维护手册](../maintenance.md)。旧分片保留为受限的升级导入来源；已经启用记录库的项目禁止旧聚合回写。构建工具读取已提交的快照，因此维护完成后应显式 export，再审查和提交数据。
