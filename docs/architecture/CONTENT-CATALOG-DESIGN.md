# 记录式内容库设计

> 工作权威：`content/catalog.sqlite`（由 Rust 记录服务维护）。Git 跟踪快照：`data/catalog/`。详细读写与补丁操作见 [维护手册](../maintenance.md)。

---

## 1. 权威来源与存储结构

- **唯一可写权威**：每个运行环境以各自运行目录下的 `content/catalog.sqlite` 为权威库，Pinia 与编辑器草稿仅作内存缓存。
- **快照与隔离 (`data/catalog/manifest.json`)**：仅用于显式导出、Git 审查与初始化。已激活库不存在/损坏时直接报错拒绝服务，升级包快照绝不覆盖已有个人库；旧安装无快照时才从历史分片迁移。
- **实体与分离保存**：涵盖人物、服装（记录键 `<角色ID>/<服装ID>`）、工作室场景、热门蓝图与记录文档。人物档案（中文）与图像身份（英文标签）分别保存，不自动互译或拼接，未知扩展字段原样保留。
- **范围外**：`data/references/`、模型运行配置、推理资源与用户作品 `workspace` 均独立存储，不纳入内容库。

---

## 2. 事务、校验与修订保护

- **查询与分页**：摘要接口支持按类型、角色、分类、分级与排序参数（SQL 绑定）分页；详情与历史修订按需单条读取。
- **乐观锁 (`expectedRevision`)**：支持整条 `data` 或递归字段 `patch`（缺省保留原值，显式 `null` 保留）；稳定 ID 禁止通过普通编辑改名；同一批次内单条冲突拒绝整批；预览执行完整校验后回滚。
- **关联与定稿基线**：保存时同事务提交标签改名、下架引用清理及人物/默认服装一致性校验。受 `data/prompt-pinned-scenes.json` 保护的定稿基线只允许保持原值，或经 `scenes:pin-capture` 在真实出图后更新。
- **下架语义**：下架记录保留 ID 与修订历史以防止 ID 复用；恢复 JSON 快照时保留快照内记录及下架状态。

---

## 3. 导入合并与排序规则

- **三向合并**：工作库记录初始化/上次导入种子值。导入时比对种子、本地值与新快照：未改本地值直接更新，本地改而上游未变则保留，双方同改冲突时报告并拒绝静默覆盖；下架须显式声明，不因快照缺失隐式删除。
- **排序与时间**：展示顺序独立于文件物理顺序；最近新增使用真实 `createdAt`（缺可靠来源时为 `null`，不伪造导入时间）；智能排序仅依据策展权重与用户偏好，不再以文案长度推断质量。
- **维护与导出**：通过 `/api/catalog`（本机限写）与 `npm run wf -- content:catalog` 维护。CLI 支持整角色导出与精确单条导出，合并回 `data/catalog/` 时不影响范围外快照。
