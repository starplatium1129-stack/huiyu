# R12 Live2D 独立渲染进程实验

日期：2026-09-26。基线 `cc533b4f15e1f264b544578d902d027fa6f93e51`，延续 [主线交付](R3-R11-EXECUTION-REPORT.md)。本批比较同一套原生渲染内核的线程与进程部署，不替换 Tauri，也不自动把实验配置启用到生产资料。

实现提交：`20eb41669b1711b22ee34897bb963e34c9827239`。结构化记录见 [R12 验证证据](../evidence/architecture-r12-2026-09-26.json)。

## 实现

- 将原约 2200 行的 `live2d_overlay.rs` 拆成 Tauri adapter 与 11 个渲染模块。模型、动作、眨眼、绘制与 hit-test 算法复用；内核用资源上下文和事件回调，不持有 `AppHandle`。
- 同一 EXE 的 renderer 子进程入口在 Tauri 初始化前分流，不启动网关、WebView、托盘或用户资料服务。私有 stdin/stdout JSONL 最长 64 KiB，父进程最多 32 个待答请求；高频意图沿用前端既有背压。
- 子进程通过 Windows Job 绑定父进程寿命。超时或异常退出拒绝该代未完成请求，事件与新代发布共用同步门，旧 ready/motion/stopped 不能干扰新代。正常 Shutdown 先读完回复再收尾。
- `Destroy` 释放模型，保留可复用渲染窗口；Shutdown/EOF 退出内核，GPU/surface 先于 HWND 释放。直接 EOF 遇到正在加载模型时等待当前有界命令；父进程异常退出则由 OS Job 回收。
- 进程实验要求 `AICS_LIVE2D_RENDERER_PROCESS=1`、独立 WebView profile 及独立 config 同时存在。正式安装默认仍走线程；移除此比较入口或改默认须基于后续采用决定。
- 父 supervisor 不自动重放模型命令。前端保留原有的最多 3 次退避恢复；仅在仍启用且可见时重新发起加载。实验不涉及 AI 生成任务重提。

## 同批修复的真实启动缺陷

对上一安装候选做隔离启动时，本地服务晚于 bundled UI 就绪；第一次 Live2D 目录读取失败，后续启用沿空目录退为静态，服务恢复也不会加载。开关为 true 但原生 `active=false`、`frameCount=0`，这不能被先前三窗身份验收覆盖。

现将目录请求合并、取消与连接恢复集中管理：保留用户启用意图，连接就绪后恢复缺失目录；隐藏时不加载，显示后恢复；关闭或卸载不再发起模型请求。合并重复后端选择代码，保持原包体预算。

## 验证

50 项 Rust 测试、17 项生命周期/可见性测试、6 项既有原生接口契约、应用类型检查及定向 lint 通过。Web 与独立 UI 构建通过；ChatView 闭包 679.9 / 680 KiB，预算未放宽。workflow 注册定向检查 22 项通过。保留最初缺少 Windows feature、包体超出 206 bytes 及启动缺陷的失败记录。

正式协议/GPU 验收使用本机已有的两套模型与原始纹理，6 项行为检查通过：模型画面、加载中终止与 pending 拒绝、父进程存活与显式重连、超时整代终止、Shutdown/EOF 清理、父进程异常退出后的 Job 回收。已实际查看两张 800×800 GPU readback 图片，默认服装完整；图片本身不代替桌面窗口合成验收。

| 模型 | 目标 60 FPS | 目标 120 FPS | 目标 165 FPS |
| --- | ---: | ---: | ---: |
| 宁宁 | 58.81 | 116.78 | 119.89 |
| 夏目 | 59.16 | 115.99 | 119.84 |

以上每段约 2 秒，是本机实际帧数/时间；165 FPS 目标没有达到。surface failure/recovery 均为 0。父控制程序与渲染子进程的工作集合计约 1.43 GB，GPU shared counter 约 1.35 GB，不能据此声称降低内存或显存。

真实 Tauri UI 使用同一 EXE、宁宁模型、DPR 2 和 1080×1312 物理渲染画幅，结果如下：

| 模式 | 目标 60 FPS | 目标 120 FPS | 目标 165 FPS |
| --- | ---: | ---: | ---: |
| 原生线程 | 59.35 | 116.44 | 119.64 |
| 独立进程 | 58.85 | 115.86 | 120.27 |

两模式首次启动无需刷新即可显示角色，已查看实际物理像素窗口截图。进程模式中真实终止 child 后，同一宿主和文档保持存活，前端既有有界恢复策略启动新 child 并恢复画面；marker/timeOrigin 不变，整页重载为 0。隐藏时帧数停止，恢复后继续；正常退出无遗留 child 或 GPU 窗口。恢复显示使用已核对的本次 HWND 和窗口定向通知，未冒充托盘入口验收。

最初截图工具误把逻辑矩形用于物理像素捕获，以及把同文档 history 事件误计为重载的脚本失败均保留；最终物理截图与文档身份断言定向补验通过。线程/进程同 UI 的内存对照未采样，不把协议探针内存当作该对照。

结论：独立进程的故障隔离已取得本机实证，画面和帧率与线程模式相当，未证明性能或内存收益。保留已验证的实验入口，正式默认继续使用线程；R12 PoC 完成不等于采用决定，也不是权限沙箱。候选 EXE SHA-256 为 `c11e87a222c80d932b29540161f464d93b4f68db9d1cdf57fb7794dcf8492bed`。本批没有重新安装，启动恢复修复已进入源码与验收候选，现有安装版尚未替换。

## 重现与边界

先按既有流程构建包含 `tauri/custom-protocol` 的候选 EXE，再运行 `npm run wf -- desktop:renderer-process-check --exe <候选EXE> --assets-root <已有assets目录> --out <新的证据目录>`。该命令启动隔离原生窗口并使用本机 GPU，不属于默认 unit；不下载安装模型、不读生产聊天或迁移库、不调用生图/语音模型。

本次不宣称覆盖多显示器、全部 DPI/刷新率、休眠/GPU 驱动重置、长期功耗或所有换装组合；不启用 R13 Electron 对照。原始日志、图片与候选保留在被忽略的 `runtime/refactor-r12/`。
