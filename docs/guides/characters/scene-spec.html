🎞 Scene 数据与写作规范

Scene 是编号和维护单位，Prompt 是随场景一起保存的生成输出。

📋 Scene 模板 — 常用字段

Scene ID
使用仓库现有格式，例如 sc001、sc002；保持唯一且不要重复使用。
标题
有画面感的中文场景名（例如：放学后的等待）
故事
一句话故事描述。谁在什么地方、在做什么、为什么。
情绪
核心情绪 (恋爱、期待、害羞...)
推荐角色
ayachi_nene / shiki_natsume / 通用
Resolution
8 档, 带 VRAM 要求 (详见下方速查)
推荐 LoRA 权重
0.75 (默认) / 范围 0.6–0.8
Positive
遵循 Prompt Spec 的 9 模块顺序。每 Scene 唯一变量。
Negative
基础层 (通用 17 词) + 场景特定层 (3–5 词)
建议参数 作为起点
可记录 CFG、Sampler、Steps 与 Hires 参数；模型或 LoRA 变化后按实测调整。
标签
用于 Scene 库检索的标签

⚙️ 建议参数 先从这里试

这些值适合作为起点，不是固定规则。模型、VAE、LoRA 版本、显存和画面类型变化后，以实际结果为准。

参数参考值调整方向
CFG5–5.5画面过硬或过饱和时降低；提示词跟随不足时小幅提高
SamplerDPM++ 2M SDE优先沿用 WebUI 中已经稳定的采样器
Steps24–30先比较稳定性与耗时，不默认越高越好
Hires Denoise0.35–0.45角色偏离时降低；需要更多重绘细节时提高
Hires Steps12–15按放大器和输出尺寸实测
LoRA 权重0.75 (默认)过拟合 → 降到 0.6; 不够明显 → 升到 0.85

🛡 Negative 速查

📌 基础层（通用质量问题）

作为默认起点；如果底模已有推荐 Negative，请优先比较实测结果。

lowres, bad anatomy, bad hands, text, error, missing fingers, extra digit, fewer digits, cropped, worst quality, low quality, normal quality, jpeg artifacts, signature, watermark, username, blurry, artist name

📌 场景特定层 (每场景选 3–5 词叠加到基础层)

按场景类型查表。对立的东西不能同时出现就加。
