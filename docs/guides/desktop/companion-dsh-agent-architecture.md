# 桌面陪伴：工具与配置

桌宠支持角色聊天、Live2D 动作、语音和本机工具。看屏与绘图分别需要兼容的视觉模型或已准备的绘图模型；源码接线不代表目标安装版和设备已经验收，待验范围见[规划](../../roadmap.md)。

内置角色支持按模型参数切换表情，恢复默认表情时保留衣装；互动好感度按实际动作映射计算，加载、语音忙碌、门控和播放失败有相应反馈。

## 工具与权限

| 工具 | 对应端点/实现 | 说明 |
| --- | --- | --- |
| `capture_screen` / `read_image` | `/api/desktop-tools` | 抓取 Windows 主屏画面或读取工作区图片；性能以实际设备测量为准 |
| `run_command` | `/api/desktop-tools` | 默认关闭；仅操作员启用 trusted 档后按当前系统账户权限执行，不是工作区沙箱 |
| `read_file` / `write_file` | `/api/desktop-tools` | 读写 AI 工作区内的文本、脚本和配置 |
| `generate_character_image` | 桌宠编排 → `/api/tasks/v1` | 复用当前模型和角色绑定，提交私人任务，完成后回送对话并入册 |
| `generate_image_from_reference` | `/api/interrogate/raw` → `/api/tasks/v1` | 使用本机 PixAI 反推参考图，再按所选角色和工作台编译结果生成；可取消 |

文件工具解析实际链接目标，拒绝指向 AI 工作区外的目录联接；通用命令的启用和撤销见[启动与排错](../../../STARTUP.md#运行配置与凭据恢复)。进程起始目录、命令白名单和取消机制均不能当作操作系统级隔离。

## 聊天与视觉配置

在桌宠设置中选择 API 模式，填写所用服务的地址、模型名和密钥。地址可以是本地代理 `http://127.0.0.1:8317/v1`，也可以是兼容服务的端点。

看屏需要图像输入能力，工具调用需要兼容的流式 Function Calling；可用性和延迟按实际服务核对。项目预设维护在 `src/config/chatApi.ts` 与 `ChatApiSettings.vue`。

## 常用操作

### 看屏
* **操作**：在桌宠输入框右侧点击 **看屏幕**。
* **流程**：
  1. 优先通过本机网关调用 Windows GDI 截取主屏并编码 JPEG；失败时尝试浏览器分享屏幕，用户取消或设备不支持时返回失败；
  2. 将画面和文字发送给当前配置的视觉服务，由聊天模型根据角色设定回应。

### 对话绘图与图片反推
* **操作**：直接对桌宠发送指令：
  - *“夏目，帮我画一张你在海边喝汽水的插画”*
  - *“画一张夏目的泳装插画”*
* **流程**：
  1. 模型识别出图意图，发起 `generate_character_image` 工具调用；
  2. 桌宠读取跨窗口共享的工作台绘图参数，复用当前内容库与 Anima/Krea 编译器；角色 LoRA 从受控绑定取得，不接受模型提供的任意 LoRA 字符串；
  3. 将冻结的提示词、参数与来源提交到私人任务队列，对话显示当前阶段；点停止会请求取消原任务，接收状态未知时只查原任务、不重复提交；
  4. 生成完成后图片进入当前角色对话与作品册，点击图片可放大查看。聊天和归档仅保存持久媒体引用，不保存临时 Blob URL 或 Base64 图片；
  5. 中文原意保存在 description，英文画面描述保存在 visualDescription，交给实际编译通道。历史草稿卡仍可到工作台编辑，新的绘图工具直接生成。

独立聊天窗可选择、粘贴或拖入 PNG/JPEG/WebP 图片，先预览、移除，实际发送时保存原图。输入文字后发送会交给当前视觉聊天模型；点击「反推并生成」直接使用本机 PixAI 与绘图模型，不要求视觉聊天模型连接。反推保留服装、姿势与背景，默认以当前陪伴角色重新生成；它不是保留像素的图片编辑。也可在聊天中要求反推最近发送的图片并绘图。「看屏幕」与语音输入继续沿用各自服务；语音检测模型列表不代表真实录音识别已通过。

### 好感度与动作
* 互动按选中动作映射的 `bonus` 加分；部分摸头 / 摸手动作为 +5，专属动作或无奖励动作不承诺每次加分；
* 满分（100 分）解锁原作者专属告白动作（萌萌Q、喝茶邀请、我爱你）；
* 好感度徽章在顶部药丸实时显示当前等级与点数。
