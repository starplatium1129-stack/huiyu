## 发给 Gemini 的提示词

```text
下一轮转向场景创作，目标是提供真正可挑选的场景候选，不再扩写泛泛的工程审计报告。

先读 AGENTS.md、studio-prompt-craft/SKILL.md，以及本文件的第二轮复核。开工检查 git status/diff，保护其他任务。你先在自己的原 G1/G4/G5 报告中更正已指出的统计、错误引文和验收预期；不要改被审查的原文档来迎合错误报告。随后继续创作，无需逐项等待确认。

范围：仅全年龄、非性化的原创候选场景。使用现有角色和已登记、适合全年龄的服装；学校年龄或其他未成年角色只写年龄适宜的日常、冒险等内容，不含性化情节。不自行补成人资格或绕过项目分级。

阶段一：60 份场景设计草案
1. 选择 20 位现有角色，优先身份、服装、原作特征有明确源记录的对象；覆盖不同性格、世界观与服装，不必平均分配作品系列。先列选定角色 ID、服装 ID 和来源文件。
2. 每位角色写 3 个不同的场景概念，共 60 份，分别探索人物与环境融合的叙事 CG、PC 横向壁纸、手机竖向壁纸。三份必须有不同的主要动作、环境关系或视觉重点，不能一张图只改比例。
3. 每份包含：临时 draftId、characterId/outfitId、源记录路径、标题、简短场景描述、一个可见的核心瞬间、人物动作与表情、关键道具和接触关系、环境层次、镜头/光影/色彩、画面焦点、需要保留的空间、主要生成风险。
4. 叙事 CG 要让动作与环境共同表达一个瞬间；单人物壁纸可以靠轮廓、表情和衣装成立，不硬塞故事道具；手机壁纸分别考虑时钟和图标区域，不把画布全留空，也不预画手机框、时钟和 UI。
5. 从现有该角色蓝图读取标题/场景设定，列最相近的已有条目和本候选的实质区别。不是全库语义审计，不改任何已有条目；无法找到对照时明确记录检索范围。禁止批量替换角色名/地点/天气制造伪差异。
6. 小说性的新情节明确标原创构思，不冒充原作剧情；角色稳定身份、精确触发词、服装 ID 不得编造。内容不足时写明缺口，不能为凑满 60 条靠重复填充。

阶段二：挑选 12 份深化为双引擎草稿
1. 从 60 份中选择 12 份，兼顾三种用途与不同角色；说明具体优点和未选相近方案的理由，不打空泛的 95 分。
2. 根据当前 studio-prompt-craft 的 Anima/Krea 参考和项目叙事/桌面/手机壁纸规范，逐条写 Anima 正向草稿与负向策略、Krea 英文 prose 草稿。每份分别为两引擎写作，不能机械换标点。
3. 精确身份词与服装依据来自当前源记录；动作、可见道具、人数、镜头和画幅彼此一致。不要重复堆“电影感/大师级/惊艳”，不要添加未要求的人物或附属物。不同版本模型参数不能混套。
4. 每条附自查：身份/服装是否忠实、动作能否画出来、接触和空间关系是否明确、负向是否排斥所需内容、是否存在上半身与全身冲突、桌面/手机裁切风险。发现冲突就重写，不只标注后保留。
5. 全部标为 draft、未编译、未出图、未视觉验收。你不调用生成服务、不改 checkpoint/LoRA/profile，不把作品描述称作最终编译请求。主任务后续负责抽审、真实编译和出图比较。

交付：仅写 docs/research/prompts/gemini-scene-candidates/ 下的 selection.json、每批独立 JSON、catalog.md 和 shortlist.md/json；临时只读检查脚本放 scripts/archive/gemini-scene-drafts/。每批 5 位角色，即 15 份概念，四批完成。Markdown 索引只摘要，不重复复制全部 JSON 内容。

约束：不修改 data/、assets/、生产场景/蓝图/提示词、pinned 基线、编译器、skill、共享索引和分级；不用正式 scNNN 分配新 ID，不提交或 push。不得恢复旧 467 条场景审计。JSON 数量、唯一 ID、角色/服装引用必须自动核对，合格只代表结构合法，不代表画面通过。

完成后简短汇报：实际概念数、独立角色数、深化候选数、重复淘汰情况、结构检查结果、文件路径和未验证项。先交可评估的候选，不继续自动扩到全库。
```
