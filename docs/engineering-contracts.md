# 工程与角色接入契约

> 整理日期：2026-10-09。与 [AGENTS.md](../AGENTS.md) 配套阅读；此页保留模块约束，当前规模只维护在 [项目状态](project-status.md)。

## 模块边界

- **前端架构**：Vue 3 + Vite + TypeScript + Pinia（`src/stores/` + `src/views/` 路由全懒加载）。
- **组件与逻辑分层**：
  - 复杂业务逻辑与状态机下沉至专属 composable（如 `usePromptSdQueue`、`useAnimaInpaint`、`usePopularPromptAssembly`），保持 View 纯粹。
  - `src/application/` 编排用例与端口，不依赖具体存储、API、Pinia、Vue 或 Node 平台实现；`src/platform/web/` 与 `src/platform/desktop/` 提供适配，`src/api/` 处理传输和响应解码。跨端 DTO 放根目录 `types/` 或对应 runtime 纯模块；runtime 不反向依赖 `src/`，包括纯类型与间接导入。
  - 新页面复用 `fluid-workspaces.css` 的共享布局表面、Studio 控件及 `ArtworkViewerStage`/`ZoomableImageViewer`；页面只排列内容和持有业务状态。原生弹窗由 `useFluidDialog` 开关，观画信息由 `useArtworkInfoDrawer` 管理，Reka portal 由 `useModalPortalHost` 归入所属模态。审查须沿原生 dialog、自定义焦点容器和普通页面的已有调用方核对键鼠、返焦、KeepAlive、双主题与动效偏好；迁移全部消费者后删除被替代的手写开关、定位和焦点路径，保留圆形扩散主题切换。
  - 离散动作菜单复用 `StudioDropdownMenu` 的 Reka 语义、portal、键鼠动效和生命周期；业务只提供触发器与条目，通过其 `run` 先关闭返焦再执行动作，避免新确认框被迟到返焦覆盖。房间与消息菜单共用该路径，导航 popover 和桌宠径向菜单保留各自语义。审查须核对外部点击、Escape、动作打开新弹层和页面停用，不能复制一套开关/返焦状态到新页面。
  - 手动按住说话复用 `useManualSpeechHold` 管理唯一指针或按键及指针捕获，`useVoiceInput` 继续拥有权限、录音与识别资源。房间、陪伴页和桌宠聊天窗保留各自准入、自动监听、唤醒会话及发送规则；按钮和全局 Space 共用同一手势 owner。审查须核对主指针、匹配释放、丢失捕获、失焦、IME 与外部取消；清除手势后再释放捕获，启动中松开取消，录音中松开结束，识别中的按钮失焦不能误取消已交接的识别。
  - 原图查看与未入册成片恢复复用 `imageReadSlot` 的实际读取槽和最新候选；取消等待不释放尚未结束的存储/桥接读取，原图实例独立占槽，绘图恢复在同一窗口跨重建共用槽。`useOriginalImage` 继续拥有 35 秒时限、预览 URL 和页面生命周期，图库、批量作品、聊天与视频首尾槽各自解析来源和回退；恢复后舞台 URL 交现有 Anima/SD 会话持有。缩略图及比较图沿自己的预算，图库墙的两个预览 worker 须等已发存储读取、解码与编码真正结算后归还；滚出视口或离页只阻止迟到结果发布，不能用提前结束等待突破并发数。审查须覆盖切图、重试、关闭过渡、首尾独立读取及完整媒体会话；停止读取与最终释放图片是不同交接，借入 URL 不可回收。
- **网关服务**：产品后端为 `runtime-rs/` 的独立 Rust 进程，桌面与独立服务共用 HTTP/流式协议；依赖锁定于 `runtime-rs/Cargo.lock`。SPA fallback 排除 `/api`，网页优先使用已构建的 `dist/`。旧 `server.ts`、`server/`、`routes/`、`services/` 已删除，不能恢复为产品回退路径。仍有维护用途的纯工具归 `scripts/lib/`；Node/npm 用于前端、开发维护与构建编排。旧协议、任务指纹和存储格式按实际来源、边界转换与当前消费者审查，结合已有日志和必要维护校验；不恢复夹具、假上游或行为测试入口。
- **Rust 任务契约**：`task_contract` 定义持久任务记录、状态与可变字段命令；runtime 和 SQLite worker 在内部使用强类型，HTTP/provider 与持久化边界负责 JSON 转换。更新中的缺省字段保持原值，显式 null 只可清空可空字段；任务命令继续经过身份、取消和 writer epoch 检查。`execution` 持有跨引擎的输出、观察结果与执行 hooks，不依赖具体引擎或存储。前端任务快照与待确认请求由 `src/stores/runtimeTaskState.ts` 持有，API 不再转导出展示状态。
- **原生与交付边界**：libvips DLL 按 `runtime-rs/native-dependencies.windows-x64.json` 的真实字节/哈希暂存；已无产品调用的 ORT 不进入新包。构建回执绑定 Rust 源码、EXE、DLL 与许可证清单，缺失或字节漂移仍拒绝。`releaseReady` 和审批待项如实记录，不阻断经用户明确授权的发布，也不代表材料、真实权重、安装/UAC与设备效果已验收。新运行时的回退不能启动另一后端同时写同一 workspace。
- **原生模型扩展审查**：文件归属由 `generation/native/resources` 统一判定，目录结构由 `model_layout` 与模型声明检查；状态、发现和提交复用同一规则，不各自扫描或缓存就绪结论。`Settings.worker_command` 拥有隔离、离线与显存环境配置，调用方拥有 I/O 和时限。新模型只补声明、特有输入校验及加载/采样/释放逻辑，经现有 `Plan → Engine → worker_lifecycle` 接入；图片、漫画与视频共用准入、串行执行、取消确认和进程回收，不再复制调度器。Anima 与 adapter 共用 `native_memory` 的组件/分层卸载，保留原精度，不使用跨条件分支预取；TeaCache 临时包装置于分层 onload 之后，退出恢复。adapter 仅在同目录、模型、显存策略及持续有效的文件保护租约下复用一组权重，每任务重建管线、scheduler 与 guider；取消/失败丢弃驻留，不支持租约的文件系统逐任务完整校验并释放。漫画内嵌 Qwen 仍在 CPU 后处理前释放；Anima LoRA、漫画 CPU 与 `.pth` 限制保留。Rust/Python 分别校验跨进程输入，不能互删。审查至少沿 Anima、Qwen/Krea、视频和漫画现有消费者核对资源交接；文件就绪与编译不证明模型、显存或性能通过。
- **原生准备与就绪**：隔离、UTF-8、禁字节码及离线环境由 `native_python::command` 统一，Anima/adapter/漫画的 `Settings.worker_command`、本地准备/导入及 PixAI 准备/正式 worker 全部复用，禁止在安装资源旁写缓存；调用方继续持有参数、I/O、路径校验、许可与时限。启用诊断、模型目录校验和正式推理通过 `Settings.worker_command` 追加相同加速/显存设置；PixAI 保留自己的显式依赖路径、预算和串行常驻策略，不并入 Anima 配置。受管启用在诊断前明确 native/offload 目标，环境创建器和目录导入仍拥有自己的准备协议。Anima、adapter 与漫画分别声明实际需要的随包文件，经 `resources.worker_bundle_issue` 检查当前配置的真实入口及所需同目录 helper；Anima 状态、诊断与提交共用 `validate_anima_files`，新增 helper 须同步声明，空文件不可宣称就绪。adapter 目录按 worker 相同的文件匹配规则逐个核对权重，不能因另一个有效文件而放过空文件、目录或链接；保留组件项数上限、分片校验及 Anima 原组件过滤语义。文件检查不导入 Python，不把转换、校准或基准工具变成普通推理前提；模型权重与包依赖仍在原边界校验。adapter、视频和漫画不依赖 Anima helper；漫画仅在选择 Qwen 重绘时检查 adapter，基础 CPU 与线稿不被该可选依赖阻断。
- **准备进程资源归属**：同一准备操作向下传递同一准入许可，PixAI 写入另携原工作区写许可，在启动时与子进程原子绑定。退出未确认时关闭新准入，由现有进程清理链继续持有句柄和许可，确认 reap 后才释放；wait 报错保守隔离，不能因 HTTP、操作 future 或 stop 返回就放行写入。ComfyUI 与 llama 的环境准备同样复用 `setup_permit → spawn_with_permit`，共享暂存目录不能在旧安装进程未退出时重新清空或写入。审查覆盖目录检查/导入、离线准备、受管安装、模型校验、启用和 PixAI；保留 VC/UAC 保护及独立只读探针协议，不复制另一套进程管理。
- **原生任务输入归属**：图片、漫画/线稿和视频的任务临时目录在首次 JSONL 发送前绑定当前 worker，并由同一进程保活链覆盖异常退役、关闭和未确认退出；确认 `ready` 后才可解绑，任务本身继续持有目录直到验证与发布结束。PixAI 私有输入文件同样在发送前绑定其串行 worker，有效匹配回复（含确证图片拒绝）后解绑；取消、超时和协议失败则交进程退役链保留至 reap，不因停止返回错误提前删除。Anima 模型常驻不常驻上一任务的输入，adapter 的逐任务释放仍沿既有协议。审查须核对发送失败、协作取消、超时及 idle/聊天交接；不能因 stop 返回错误或 future 销毁就提前删除目录。历史硬崩留下的未标记目录缺少可靠归属证据，保守保留，不按时间猜测清理。
- **随包模块与错误归属**：adapter、漫画及其可选重绘/线稿步骤经 `worker_lifecycle.load_sibling` 复用同目录已注册模块；隔离入口只引导固定 lifecycle 文件，不扩大 Python 搜索路径。模型特有错误继承该实例的 `WorkerError`，协议只保留已知错误类型的代码，不能靠任意异常的同名属性判定。审查须沿漫画 → 线稿、漫画 → Qwen 和独立 adapter 核对类身份、失败缓存清理与取消/ready；Anima 常驻模块仍由原有冻结及身份租约缓存持有，不并入此缓存。
- **运行时维护**：人物、服装、场景和蓝图以运行目录 content/catalog.sqlite 为唯一工作权威，通过 Rust 记录 API、事务和修订历史维护；data/catalog/ 仅作逐条初始化/发布快照，旧个人分片仅作升级导入来源。已有数据库不被升级包覆盖，启用后的缺库状态拒绝静默重建。静态 JSON 消费者读取数据库生成视图，构建读取显式导出的项目快照。资源事务、pin、参考审核发布及未知状态拒绝保留原契约；内置图片从安装资源根读取，自定义立绘仍在用户 character-art 中原子发布，不覆盖参考库或 Live2D。见[内容库设计](architecture/CONTENT-CATALOG-DESIGN.md)。
- **生图双引擎**：
  - **画面输入**：以角色/服装、场景已写好的词条与画面描述及用户明确选择为依据；Anima 未指定风格配方时不强制平涂、线稿或饱和度，画师词仅由用户显式选择。所选光效可补充相应的受光、投影、反光与明暗层次，不追加光源实体、道具、天气、星空、剪影或景深；显式 Anima 场景描述优先保留。情绪与检索资料不推导机位、光源或色调；台灯、烛光、炉火、晨光不借用其他光照预设。热门场景切换完整替换导演默认值（含 null），手写词条和显式设置按各自流程保留。
  - **场景形态与构图**：SFW 已有时间线形态可在蓝图用 identityTokensOverride / identityProseOverride 声明，角色 ID 保持，成人或手动成人词请求拒绝这种变体。allowRepeatedSubject 仅保留明确要求的镜面／幻影；group 和 triptych 继续区分同伴与分格。衣装不夹带必持道具，避免覆盖场景双手动作。
  - **Anima (ComfyUI / Pencil)**：高质量动漫与局部换装（Inpaint），支持 TeaCache 加速、手绘/CLIPSeg 遮罩与 `ImageCompositeMasked` 像素级原图回贴。
  - **Krea 2（自研 DiT + Qwen3-VL 编码器，非 SD3.5 系）**：当前本地编译使用英文 prose，清理标签堆词、评分词和括号权重，negative 为空；CFG 以实际节点定义为准，不把本地约束泛化为所有版本能力。提示词按 [studio-prompt-craft](../.agents/skills/studio-prompt-craft/SKILL.md) 执行，人物环境融合见 [叙事 CG 规范](guides/prompts/narrative-cg-prompt-standard.md)；历史研究不覆盖当前实现与后续证据。
- **Live2D 双后端**：浏览器走 `wl-live2d`（按需加载贴图，`blinkScheduler` 双眼同步，静止动态降帧节能）；桌面端走原生 Overlay 桥。运行时维护见 [Live2D 指南](guides/desktop/live2d-native-runtime.md)。
- **配音与陪伴**：VoxCPM2 角色 LoRA / GPT-SoVITS + 本机翻译管道，自动剥离台词舞台提示与长句分段。VoxCPM2 分片即播、下一句预取、完整句缓存；GPT 整句播放保留 in-flight 去重。停止播放取消所属 PCM 请求并释放音频节点，半句不作为可重播音频。

作品历史/工作台的纯类型、配方解码、资源所有权和可执行依赖方向见 [可维护性试点边界](guides/engineering/maintainability-boundaries.md)。类型兼容转导出不改变持久化格式。

## 重构期间的任务与持久化边界

以下约束已接入现行主线并继续约束维护；实现、本机迁移与交付范围见 [项目状态](project-status.md)。实际模型、其他设备和历史来源的未覆盖条件在 roadmap 单列。

- **任务所有权**：runtime 已接受的任务由 runtime 持有身份、执行和结果状态；页面卸载只解除订阅、停止页面查询并释放页面拥有的媒体与监听资源。用户明确取消通过独立任务取消命令表达，不能由页面卸载、客户端读取超时或连接断开隐式代替。尚未被接受的交互请求可取消；接受应答丢失属于未知结果，须按稳定请求身份查询，不能据此断言未接受或自动重提。
- **长任务扩展审查**：新任务接入 `submitRuntimeTask`、`waitForRuntimeTask`、取消和任务中心恢复入口；提交必须显式传入调用方已写稳的请求键，API 不再按参数指纹临时生成身份。接收与重试共同使用原 key、原 runtime epoch 的确认协议，不复制 POST 补偿或终态轮询；任务中心漫画重试仍保留来源键、待确认记录与后端 lineage。普通观察读取摘要，漫画/线稿通过同一观察器的完整记录回调投影专属进度；观察超时只停止查看。视频分镜保留 checkpoint、逐镜重试和拼接差异。图片结果经 `archiveTaskResult → saveTaskResult` 入册，所有入口用 `taskArtworkId` 保持身份；视频沿受控结果下载，不强塞进图片作品契约。审查须核对已存在的不同任务调用方、取消回执防倒退及旧路径退出。
- **浏览器图片接收与观察**：单张、批量与分镜首帧经 `directImageRequests` 复用 `directGenerationRequests` 的单次提交与原键查询协议；每次新尝试只 POST 一次，丢回执及恢复只 GET 原键。服务在 `jobs/image-requests` 持有 owner/family/key、规范指纹、拒绝或 jobId 的最小凭据，不保存提示词或结果，不随结果淘汰删除身份；相同键不同参数拒绝，只有确证尚未提交上游的队列拒绝可按原键重新申请。checkpoint 写稳 jobId 后才转交现有执行链，HTTP 离开不取消接收；按键取消先写意图，覆盖尚无 ID 及 DELETE 先到的情形。无键入口仅为实际维护脚本兼容保留，不用于新前端任务。
- **浏览器图片恢复审查**：`directImageJobs.waitForDirectImageJob` 只查询原 ID，`fetchResultImage` 统一有界读取；只有 `upstreamSettled=true` 且 `unknown=false` 的失败/取消才可作为新尝试依据，缺失旧字段同样不能推断已结束。观察超时/离页只停止查看，批量保留当前张完成后停止的差异。分镜首帧在 POST 前将键、冻结参数、传输和归属写稳草稿（运行时资料还须 flush）；刷新后只查询原键，结果读取/导入/存图失败继续使用原身份，已有 imageId 只重挂载。人工换图、清图、重排与草稿还原须核对该身份，不能复制到新镜头。旧计划有 ID 沿原 ID 观察；无 ID 的旧未知请求不猜测重提。服务重启/凭据损坏/任务淘汰时明确保留未知，不宣称可自动恢复图像。
- **恢复入口独立于生成准入**：分镜草稿编辑与首帧查询在 H3 视频模型离线或未安装时仍可达；成片提交继续通过既有模型/在线状态准入。不能用安装另一模型作为读取已接收任务的前置条件。
- **单张图片恢复审查**：绘图页普通生成、重试、高清与局部重绘统一由 `useAnimaTask` 保存原键、冻结参数、传输及资料归属；写稳草稿后才允许首次提交，刷新/离页/重连仅查询原键，恢复入口不能退回新生成。`prepared` 仅表示从未允许 POST，`submitted` 表示可能已发出；未知、取消意图与读取失败均保留身份。浏览器成片经已有临时图或 `pendingCommit` 写稳后才交接生成身份，自动入册不得先清指针后确认接管；私人结果沿持久收件箱和固定任务入册 ID。审查须同时核对工作台三处恢复按钮、工具入口、动态传输加载和工作区草稿键注册。
  原图须在首个持久化等待前登记到既有成片保护，恢复指针尚未写稳时仍显示保存中；显式清图可退出对应已完成请求，不能隐式取消在途任务或清除另一张图的身份。
  未入册成片恢复的两个入口须传入原访问/命令的取消信号与有效性判断，图片请求在清理回执前冻结访问归属；初始化、深链切换、停用、新生成、显式清图及媒体会话变化均使旧读取失效。恢复沿未落稳原图、任务收件箱、旧临时指针的现有顺序，只由当前读取接管一次结果；已发布 URL 不再由读取器撤销。停止观察不清原请求、临时指针、入册编号或唯一 Blob，也不取消已经开始的保存；旧访问不得修改角色、引擎、phase 或提示。
- **批量图片恢复审查**：批次计划是请求身份、冻结配方及资料归属的唯一恢复来源，传输层不另存键或按参数生成替代键。新项 `submitted=false` 才可首次提交；写稳可能提交标记后，刷新恢复只读原键/ID。旧计划缺标记时仍按未知处理，旧 SD 仅查询已接收任务；无归属的旧计划继续受现有存储来源和 runtimeOwned 约束，不伪造迁移归属。浏览器入册在 append 前把现有 `ArtworkCommitIdentity` 写稳到 job，刷新先用原 alias/ID 核对入册；内存 Map 只持有未入册原图与迁移屏障，不能代替持久身份。读取无效计划时阻止新计划覆盖，原图不可读或结果过期时保留未知，不以重生成补偿。
- **聊天图片恢复审查**：房间与桌宠窗通过同一图片工具消费 `imageRequestDraft`；本窗口未决请求优先恢复原冻结配方，其他角色不能另起替代任务，同角色的新绘图要求须明确提示尚未提交。恢复只查询原键，不重新反推旧参考图；图片消息经聊天 `save + flush` 写稳后才确认接管。离页、切角色、看门狗与观察超时只释放读取，主动停止通过原键记录取消；未确认终态继续保留身份。检查两处图片消息消费分支与资料来源，不再以参数指纹 Map 作为刷新恢复来源。
  聊天附件在 MIME 读取前冻结仓储和完整媒体会话，上传前后均核对同一操作；隐藏、换角色和断连不能使旧准备继续上传。跨窗 `CompanionChatCommand` 携带本次图片 authority，Rust 桥接及接收端共用该字段，取得聊天写入权并核对来源后才回接收成功。缓存别名不能跨会话复用；在途上传不以取消观察回滚，原 Blob 及未确认上传标记保留。工具读取在本轮接受时冻结新附件或历史图片的来源，动态加载与后续工具轮不能改绑到新会话，结束释放订阅；历史消息仍只持久化原图片引用，不保存短期 authority，也不因此改写旧记录。纯会话快照由 `platform/imageMediaSession` 供输入准入与查看器共同使用，不能为检查身份同步加载原图读取器；实际 HEAD、Blob 与编码读取沿既有工具懒入口，加载前后均核对冻结归属。
- **漫画与线稿恢复审查**：两类推理共用 `taskRequestDraft` 保存冻结输入、原键及稳定资料归属，写稳后才提交；弹层关闭、刷新和重连只按原键重读当前 epoch 的任务，不重新上传或 POST。共享草稿持久化由 `requestDraft` 负责，图片与聊天消费者也只保留各自配方解码。漫画、独立线稿及附带线稿先接管持久任务中的实际输出，再读取预览；弹层与任务中心入册不依赖 Blob、解码成功或预览加载结束，下载仍要求对应像素。失败任务中已发布的部分结果也按原 taskId/resultIndex 入册，不要求兄弟输出齐全；换任务先清旧像素，同任务重读保留已读预览及保存状态。未知失败不能解锁新处理，后端确认结束后才可显式开始新任务。任务中心漫画重试保留已有稳定来源键与子任务 lineage；导入线稿预览是本地处理，仍需有效 Blob，保留现有保存身份与离开提醒，不当作模型任务重提。弹层输入与本地预览保存复用完整媒体会话检查，不能仅凭运行时地址或同一仓库实例跨工作区换代继续准备、上传或入册；保存重试沿原作品编号、图片别名与 flight，未知回执不释放原图。持久原请求可经原归属检查显式重连，不能借此改绑本地预览的保存归属。
- **视频恢复与扩展审查**：文字成片、图生及首尾帧、整批分镜与重抽共用 `useVideoRequest → videoRequests`，首次 POST 前通过 `taskRequestDraft` 写稳原键、冻结输入、传输和资料归属；刷新、离页、重连只查询原键。单视频与批次浏览器接收凭据复用 `generation/receipts`，初次写盘及取消转交由现有服务 TaskTracker 持有，HTTP 只观察；禁止另建 POST 补偿循环。裸 HTTP 4xx（含冲突、限流）、404/410、旧响应缺终止字段均不能证明原请求可重提；只认持久拒绝、写稳的未接收取消或原任务确认结束。
  分镜提交同时写稳行 token，接收后按原 token 交接来源、flush 并保存 adopted 回执；任务终态不代替来源交接成功，离页/重排/迟到回执不绑定新行。私人多镜重抽一次形成独立批次，冻结原镜头位置与 lineage，旧单镜 stepIndex 仅作历史读取；不自动替换原批次或续拼接。取消原请求与取消当前展示任务显式区分。旧 ID 记录只保留查询/取消/结果读取，已移除新写入与 404/410 自动清除；视频无键提交及单镜裸重抽入口已退出，图片无键接口仍供现有维护脚本使用。视频结果仍由任务收件箱与共享播放器/下载控件持有，读取或下载失败不能触发重生成；下载离页中止观察，播放授权跨工作区清除，同工作区重连再取得。后续审查须同时核对单任务各模式、分镜提交/重抽、任务中心与媒体消费者，确认旧入口退出。
  原请求恢复、深链选择与轮询共用视频读取归属；提交、取消、换任务和页面停用必须使旧观察失效。观察结果进入接收日志前及写稳后均核对信号与命令代次，分镜同样先确认读操作仍有效再更新接收状态；迟到的运行中或拒绝响应不能覆盖取消回执、退休新身份或修改隐藏页面。停止观察不清请求日志，也不取消模型。
  任务摘要的发布与操作由同一个 owner 持有；已知后端 ID 的单视频与分镜隐藏后交还任务中心查询和取消，重新进入须等当前访问的新鲜读取或新命令，不能重放缓存状态覆盖后台终态。同一后端身份复用原摘要；尚无后端 ID 的未知接收标为待核对，回原工作台按既有日志恢复，不伪造 ID 或补提交。拼接等仍由页面执行的操作完成前保留控制权，owner 明确缺少取消入口表示禁止，不回退后端取消。首帧、图片批量和反推的页面工作保留各自取消策略；任务数量与需要阻止离页的页面工作分别计数。桌面持久任务权威启用后，旧摘要只读，反推保留真实页面控制。新增长任务须沿此交接检查隐藏、重入、刷新及旧记录，不再复制后台查询或取消分支。
  单视频首尾帧输入、上传和提交准备归 `useVideoFrames`，两槽预览复用 `useOriginalImage` 的读取和 URL 生命周期；草稿只持久化参数与原图 ID，页面使用来源是否存在判断就绪和移除。离页或媒体会话变化中止准备并回收预览，耐久图片按 ID 重读，未落盘的唯一 Blob 保留并接入既有迁移/离页保护；读取或准备失败不能消费输入。显式提交复用现有工作区导入或上传协议，不能把内容寻址的受控名当成单次输入。读写前后均核对逻辑资料归属与当前媒体会话，迟到清理不得写向新工作区；正常离页仍可保存原归属草稿。审查须覆盖本地上传、绘图跨页导入、刷新恢复与首尾两槽，删除其他草稿/页面的 URL owner。
- **单一持久权威**：每个领域在每个数据域只有一个可写权威。Web adapter 是长期合法的平台实现，继续拥有独立浏览器数据；桌面 workspace 激活后，旧作品库仅作受控迁移来源或只读保留，不得因 runtime 不可用自动回落写入旧库，不得双写两份主库。Pinia 保留编辑和展示状态，缓存不构成第二份持久事实。
- **备份与图片导出**：绘图页与作品册共用 `useBackup`；逐张原图与 Web 完整备份复用同一导出来源守卫，整次冻结仓储、完整媒体会话与来源模式，会话变化单向停止后续读取、编码、下载与资料标记，同字段重连不能续用旧快照；普通首次重连也可能激活资料适配器，不能只依赖显式维护的 busy 参与者。桌面逐张导出保留当前历史引用范围，Web 保留浏览器全部原图范围（含未入册与旧库图片）；正常缓存页离开不撤回已发起操作，用户取消或卸载停止后续，已开始的浏览器下载及其 URL 宽限释放规则保留。完整工作区备份、恢复候选与旧 Web JSON 继续使用各自现有协议，未知备份回执沿原操作编号核对，不能套用 Web 导出的会话取消方式。
  恢复与导出复用 `captureBackupSource`：选文件前固定来源及 Web/桌面模式，覆盖文件读取、解析和覆盖确认；已接受恢复独立持有原来源，不因预览关闭或普通离页中止。Web 存储入口必须接收原 `check/signal`，作品锁、归档锁、逐图暂存、设置与 KV 发布均在异步交接核对，失败回读和补偿同样受原来源约束；失效不向新资料回读、回滚或删除暂存图，保留原操作编号供核对。设置的最新值和补偿基线在所有读取结算后、同一同步发布段采集，合并不能覆盖等待归档期间其他页面新保存的普通偏好。KV 明确提交后保留提交事实，后续失效只停止通知及自动刷新；700 ms 刷新回调结算前继续持有单向失效订阅。历史别名重映射、原图保留、Web JSON 合并/覆盖及桌面独立恢复候选协议保留，不能复制无归属的恢复入口。
- **任务媒体读取审查**：原图、保存预览、聊天图片、首帧、视频下载与播放授权均通过 `resolveRuntimeResult` 解析原路径、当前任务输出及完整工作区来源；已有 TaskRecord 只省略重复 GET，不能省略归属校验。结果描述复制并冻结，不向播放器共享可变任务。二进制读取始终核对媒体头、完整字节/MIME及读取后的来源；播放授权在应答后同样核对原来源。保留漫画部分输出和旧消息路径读取，不以整个任务已完成作为读取已有结果的前提；读取/授权失败只沿原结果恢复，不能触发新生成。审查全部消费者和直接媒体分支，删除路径拆解及可选来源的弱校验分支。
- **作品入册身份**：同一成片的重试复用记录编号、媒体引用与操作编号；自动失败后转手动保存沿用原身份。`archiveTaskResult` 冻结作品库与 `imageMediaSession`，运行时订阅使会话变化单向取消本次操作；同字段重连不能复活旧保存，健康轮询与令牌续期不制造失效。读取、追加、失败回读、漫画侧稿核对与交付标记由 `saveTaskResult` 在异步交接前后检查原归属；相同 workspaceId 不代表同一会话，不能在读后采用新 epoch、代次或服务继续写入。已发出的写入仍保留原编号供显式重试核对，不以取消观察代替撤回。兼容成片先写稳结构化恢复指针再提交，未知回执或一次空查询不能证明旧提交已停止，不能据此释放媒体或重新编号。历史回执保留当时提交事实；再次入册返回成功前仍核对当前作品存在、未删除且媒体一致，不隐式恢复回收站作品。
  陪伴页的文件选择、拖入与剪贴板入册共用 `importLocalImages`，整个批次冻结仓储和完整媒体会话；解析、测量、追加、回读及清理均沿原归属，失效后停止剩余项，不转用新会话。只有尚未派发追加且归属仍有效的上传才可清理，未知追加按原编号核对并保留媒体；离页或换角色不撤销已明确发起的入册。底层桌面上传自行持有同一次会话失效控制器，覆盖摘要、锁等待、分块、提交与回执交接；同字段重连不能复活旧上传，未确认的恢复标记继续由既有协议核对，不以中止观察释放它。
- **迁移前成片保护**：切换候选工作区前，沿现有维护锁核对各来源窗口的任务、保存与未落稳成片；会话内尚无可靠恢复来源的原图也必须参与，不能只凭任务计数归零允许迁移。封存快照前暂停各来源窗口编辑，刷新已有草稿保存参与者，再取得资料排他锁；保存失败或未确认准备的窗口阻止导出与激活。已确认的 runtime 输出和已写稳的临时指针仍沿各自恢复来源处理。
- **旧 SD 等待队列**：新生成已经退役，已接收的旧任务保持查询、取消与结果收集；旧记录仍按窗口角色保存稳定请求身份，不再新增 SD 意图；重建窗口默认暂停，未知接收只查询原 key。已接受项的执行与结果仍由 runtime 持有；删除未知提交须先确认取消意图，取消回执丢失保留待确认标记。清空等待不取消在途任务，旧浏览器队列不回灌为桌面权威，多窗口共享编辑不在此契约内。
- **迁移适配的窄例外**：允许读取旧数据格式和旧来源的 importer，但须记录支持的来源/版本、用途和退出条件；其保留期由支持的升级跨度决定。此例外不允许新增无限期 deprecated shim、任意错误 fallback 或双主写入，也不要求删除仍在使用的真实 Web adapter。
- **依赖方向**：runtime 不反向依赖前端，包括纯类型；纯领域类型不引用 Store、展示层或 Vue。保留现行 [ESLint 规则](../scripts/lib/module-boundaries.mts)，审查实际调用与所有权，不维护已无消费者的扫描器、历史豁免清单或测试门禁。正常 unsubscribe 不视为任务取消。

分镜手选、绘图导入与生成首帧共用现有单镜请求归属，按镜头对象核对访问代次与完整媒体会话；会话失效永久终止原准备，撤销临时受控名和预览，保留耐久图片 ID 与原生成请求。手选首帧发布后立即保存草稿并确认写入，未知保存仍保留图片；仅原媒体归属有效时可清理本次未发布图片，不删除被替换的借入别名。整批新提交须等待已有首帧挂载，不能将待处理图片静默降为纯文本；提交写稳期间的会话变化同样终止本次派发，恢复继续沿原请求身份。

绘图成片与历史单张/多选导入视频复用 `useVideoBridge` 的媒体暂存、待办发布、写稳确认与清理；Store 只保留载荷和持久状态。点击时先冻结参数、仓储及既有页面/媒体归属，四个图片入口共用一次迁移 flight，动态加载与读取不能改绑来源。未知发布保留原 ctx 和别名，显式重试只核对原待办或已有消费回执并 flush，不顺带重做新要求；批量未知时停止后续，保留已确认前缀。单视频唯一待办未消费时接回原导入，不能覆盖；历史图继续独立暂存，因为现有 `imageId` 同时承担导入回执身份，不能直接借原 ID 吞掉之后明确新增的同图镜头。

分镜角色参考图的原 Blob、预览 URL、上传与受控名归 `useReferenceCards`；选择后先登记图片再上传，失败或离页保留原图供显式重试，停用释放预览、重入重建，移除/换角色/删卡/卸载统一取消并释放。复用工作台媒体代次使旧回执永久失效，断连撤销受控名但保留图片意图；就绪检查与批次取名共用同一出场角色集合，待上传参考图不能被静默省略。图片仅属当前窗口，接入既有重载/迁移保护；文字草稿及原任务恢复协议不变，不声称刷新后能恢复未持久化的参考图。

## 任务与阅读交互

分页角色目录的搜索确认以当前可见页为准：Enter 选择当前页首个结果，与方向键进入列表的目标一致；查询或系列变化仍回到第一页，输入法确认不触发角色选择。

控制室的聊天/ComfyUI 兼容配置与图库的画册、智能画册编辑、候选对比按首次使用加载，并提供加载失败反馈。访问后保留实例以完成关闭、返焦与资源释放；比较弹层即使尚未加载也由工作区在离页时关闭意图。控制室已有持久准备操作，以及后续准备/资料同步通知，必须唤起恢复 owner，不能因折叠区未展开而延迟恢复；核心服务状态与原生配置不随此延后。

任务中心的操作占用按任务身份隔离；同一任务的冲突命令继续互斥，其他任务取消、状态查询和待确认请求取消不被长时间拼接/重试全局锁住。结果收件箱与待处理列表的首页随实时成员变化重新读取有界权威页，保留仍在页内的卡片顺序；历史翻页不因轮询自动重置，读取失败沿显式刷新恢复。

控制室操作进度仅表示已完成步骤：运行/失败时只计入当前阶段之前的步骤，确认成功才全部完成。等待时间和服务在线状态不能伪造进度增长；无步骤清单时只显示真实状态、活动标记和消息，不显示虚构百分比。

角色房间完整聊天仍由原存储与分支协议持有。长归档阅读只挂载最多 120 条消息，以 60 条重叠窗口前后翻阅，保持可保留消息的滚动锚点和键盘焦点；返回最新、发送与重新生成沿同一阅读入口。重生成资格按历史变化一次线性计算，不能为限制 DOM 截断历史、导出或上下文。离开底部即提供返回入口，流式回复不抢走旧消息阅读位置。模型发现反馈和配置保存反馈分开显示，发现成功不能遮蔽保存失败。

图库原图下载在读取、整理元数据及本机保存交接期间显示真实忙碌状态，重复点击不创建第二次下载；仍按点击时捕获的作品身份取图和命名，不能因查看器切图改绑结果。

配音工作台的翻译与生成持有各自请求取消信号，允许在页内取消并立即恢复编辑；取消说明不把停止本页等待等同于后端已停止计算。编辑文本/参数或离页使旧回执失效。重新生成失败或取消保留上次成功音频与文件名，新音频 URL 准备好后才替换并回收旧 URL；显式切换场景字幕仍沿原逻辑清除不再匹配的音频。

分镜页的剧本待办须可见并提供显式重试；已有镜头优先，未导入剧本不能覆盖它们，已保存回执的确认重试无需清空镜头。角色资料读取失败在对应参考卡提供重试，保留手动编辑的标签、身份描述与图片；重复选择当前已解析服装不清空参考图。

Qwen 与漫画处理的入册、导出反馈绑定操作开始时的结果身份；旧结果完成保存不能把新结果标记为已保存。漫画原图读取期间不允许重连旧任务，避免迟到结果回填到新输入。

原生准备面板的显式重新检查同时恢复当前工作区的后台准备操作；首轮清单读取失败后重试成功，仍须恢复进度与取消入口。内部清单刷新不重复启动观察器，失败或已被替代的清单不用于恢复操作。

角色语音的活动状态与实际发声分别表达：合成/加载期间继续保留停止入口，角色说话与口型只在播放开始后启用。队列和重播切片先清除上一段发声状态，慢加载反馈归当前音频请求，聊天页展示已有语音进度。

## 普通图片资源

单 URL 的普通图片复用 `useRuntimeImage`；简单图片或循环卡片使用 `RuntimeImage`。它们沿用平台 URL/CORS 解析，按资源来源与 runtime epoch 重置状态，以每次加载身份拒绝旧事件；正常健康轮询不重载图片。不要在页面重复维护同一图片的失败集合，也不要让未解析的 `srcset` 覆盖已解析 URL。响应式 picture、画布采样、临时 Blob 所有权和原生 Live2D 仍由各自专用消费链管理，分级判定留在业务层。

首页 Hero 与场景维护预览共用 `useHomeHeroes`，默认使用内置 `*-home-cg-1024.webp`。只有当前样张目录中由维护上传写入 `source: "upload"` 且文件存在的条目才覆盖内置图；历史无来源清单保留原文件，但不再视作当前首页替换。恢复操作移除该角色覆盖记录，两页均回到同一内置图，不回溯旧样张版本。

## Live2D 生命周期

destroyRuntime 保持全库唯一、Pixi-first 销毁顺序；双后端 capability 分支及 lifecycleToken 语义不能在重构时改变。拆分已完成，见 [Live2D 运行时契约](guides/desktop/live2d-native-runtime.md)，不再列入未来待办。

桌宠显式隐藏或舞台停用时，经同一 destroyRuntime 取消在途连接并释放模型，保留启用、角色、服装和画质偏好；重新显示时按需恢复。普通浏览器标签页后台及减少动态效果仍只暂停。原生 Destroy 保留轻量 HWND、线程和命令通道，但释放 GPU context、设备资源池和模型；下一次 SetCharacter 懒建，不把正常卸载广播成故障 stopped。无模型的迟到帧和输入不得恢复渲染或新建 GPU 资源。

桌面工作台不进行全库缩略图预热；桌面 repository 缩略图缓存受 96 项、8 MiB 双上限约束，Web 持久缓存预热独立保留。图库按视口及可见画册封面读取缩略图，后台缓存也采用 96 项、8 MiB 预算；当前画面必需的预览单独保留，离开可见范围后参与裁剪，不累积整个浏览历史。图库 KeepAlive 只保留页面状态与缩略图，停用时撤销高清原图和查看器 Blob URL，重入后按可见范围读取；迟到异步结果不得填回旧激活代次。

图库首批作品可先显示，但画册和智能画册预览须传播索引未完成状态；保留已知手动画册并将计数标为待完成，不把部分结果显示为确定的空库。虚拟列使用累计位置索引构建可见区间、焦点保留项与占位，不能因每次滚动窗口变化扫描整列；排序游标使用与 SQLite 二进制顺序一致的既有比较器。

## 角色接入

场景蓝图的 `compositionIntent` 可取 `single`（默认）、`group` 或 `triptych`。只有明确标记的 SFW 蓝图会放行多人或三格叙事；正文、人物数量、标签、镜头和画幅必须一起描述该构图。核心编译器与候选生成入口共用构图规则，不能在一端放行后又在另一端补回矛盾的单人/禁分格负面词。成人蓝图仍使用原有主体限制，构图字段不改变项目内角色的成年创作设定。未知取值视为无效蓝图。场景真实生成后由人工验收，不以参数通过替代画面通过。

项目内角色统一按成年创作设定处理；成人内容不按本机、远程、内容开关或成年资格字段门控。列表缩略图保留 R18 默认模糊遮罩，大图预览直接展示并保留立体观画及原图缩放；设备、私人文件及工作区操作继续遵守各自权限。

角色接入必须同步完成以下六层：

1. **数据层与大盘**：人物记录保存 profile/popular，服装和蓝图通过稳定 ID 关联；通过内容维护或 content:catalog 保存，显式 export 到 data/catalog/ 后进入项目构建。参考权威源仍为 data/references/<人物ID>.json 与 manifest，两个旧参考 JSON 仅为兼容聚合产物；资源登记、渲染和发布继续走各自入口；
2. **UI 主题与强调色系统（必做项）**：通过人物记录的 `profile.accent_color` 维护有效十六进制颜色，保存到工作库，项目构建前显式导出 `data/catalog/` 快照；`data/characters.json` 为消费视图。由 `src/utils/characterTheme.ts` 和 `src/assets/css/director/tokens.css` 的通用令牌派生主题。既有 `CHARACTER_THEME_OVERRIDES` 调校优先，缺失或非法颜色回退默认强调色；普通新角色无需新增 CSS 选择器，特殊调校才加入例外。核对角色切换、默认/缺失/非法颜色及两主题实际效果，保留 WCAG AA 与图片叠字视觉验收；
3. **全量场景蓝图（SFW/NSFW 姿势解剖防崩）**：每位角色配齐 10~11 套场景蓝图（6~7 SFW 唯美日常 + 4~5 R18 成人专属）；成人蓝图严格遵守**「后入/俯身 $\rightarrow$ 强制 `1536x1152` 横画幅 + POV扶腰受力」**与**「仰卧/POV $\rightarrow$ 强制 `1152x1536` 竖画幅 + 揉胸/分腿层级」**黄金法则，杜绝悬浮器官与断腰；
4. **立绘原图与 WebP 紧凑头像缩略图**：在发布样张原图（`assets/characters/popular-<id>.png`）后，**必须同步执行 `python scripts/maintenance/build-character-thumbs.py`** 编译生成 `assets/characters/thumbs/popular-<id>.webp`，确保生图左侧选择器、首页横条卡片不掉头像；
5. **可选参考素材**：新增角色和服装无需登记或补齐固定机位图库；档案不展示图库与完整度，分镜的身份/服装文字从内容目录读取，图片按项目需求手动上传。只有确有需要且已授权制作参考素材时，才使用以下旧参考库工具。先用 `reference:register --dry-run` 预览，再显式登记 pending（写源）；`reference:render`/`reference:design` 调用模型，仅写隔离候选。经 `reference:inspect` 只读核验、人工查看图片、`reference:review` 写入绑定当前候选的审核决定，再 `reference:publish` 预览，显式 `--apply` 发布到新版本目录。缺审核保持 pending，发布不自动激活或安装。参数以[候选审核与版本发布](workflow.md#参考库候选审核与版本发布)为准。旧 `sync-multi-outfit-standards` 与 URL 修复仅用于已核验旧库维护，不能代替新候选发布；
6. **审查与桌面端同步**：按实际影响选择类型检查、产品构建与人工验收。安装获授权后使用唯一入口 `deploy-desktop.bat`；只有匹配构建才加 `-SkipBuild`，纯资源同步显式加 `-ResourcesOnly`。Git 提交、推送与发布分别按本次授权执行。

自动化辅助入口见 [接入工作流](guides/characters/character-onboarding-workflow.md)。脚本执行成功不等于主题、头像、按需制作的参考图和真实样张全部验收通过；必须逐层核对。场景数量是接入目标，不能为凑数覆盖已定稿内容；现存更多场景无需删减。

内容回归核对每位角色拥有可选 SFW、已编排蓝图的角色／衣装关联有效，以及当前分级与列表缩略图的默认遮罩。衣橱可保留未编排或仅用于成人场景的服装，默认衣装不要求另配 SFW 蓝图；coverageTags 为可选技术元数据，不按 iconic/daily/special_nsfw 强制类别配额。道具保真核对当前已写入的模型载荷，不从检索标签补入已退出的形状或其他美术细节；编译通过仍不代表真实渲染验收。
