## 2026-09-18：作品清理与备份安全修复

本批基于 `cf279ff`，不迁移用户库、不触碰提示词/评级/模型参数，也不安装或发布桌面程序。此前 `cf279ff` 的 Quality 四条执行道及 Summary 已通过（运行 `35312868036`）；该结果不自动覆盖本批存储改动。

- **未引用图片清理**：确认只授权当次候选 ID；真正删除前，在跨窗口保护内重新读取作品、项目、回收站、隔离记录、当前本地/会话草稿与旧版待迁移数据。新增引用和后来创建的图片不按旧名单删除；读失败、损坏草稿或无法取得互斥时不删除。
- **跨窗口与暂存保护**：当前版本应用在挂载前持有共享文档锁；清理要求独占访问，再取得现有作品写锁。其他窗口的私有会话草稿无法枚举，因此有其他绘遇窗口或未完成图片暂存时明确拒绝清理；关窗后可重试。保存原图到发布历史/临时结果/视频引用之间也受保护。过期回收站懒清理复用此保护，并保护项目、隔离记录与草稿引用。普通保存不要求关闭其他窗口。
- **备份导出**：沿用 v2 JSON 格式；导出/导入共用 512 MiB 字节上限，导出前计算 Base64 膨胀与 UTF-8 元数据开销，逐图编码组装 Blob 并再检查实际大小，避免全量 Base64 数组加整份 JSON 字符串的重复峰值。增加图片进度与取消；失败/取消不下载半成品、不改上次备份时间，读取失败不跳过图片。

保护适用于更新后的同源应用窗口及已接入的写入路径；更新后需保存工作并重新打开旧窗口。它不承诺控制仍运行旧代码的窗口、浏览器扩展、外部写入器或物理断电。缺少 Web Locks 的环境不执行清理，页面浏览保留原有回退。大型分卷/流式恢复尚未实现，512 MiB 上限未提高，编码优化不等于总内存恒定；真实大图库容量、桌面多窗口与设备验收仍须单列。

验证入口：`src/storage/artworkSession.spec.ts`、`src/utils/backupExport.spec.ts`、`src/composables/useBackup.spec.ts`、`src/storage/artworkRepository.test.ts`，以及 `tests/e2e/library-concurrency.spec.ts` 的原生 Web Locks/IndexedDB、多窗口和双主题取消回归。最终测试状态按本批受测源码/构建及 GitHub Actions 记录核对，不将测试设计计为已通过。外部参考素材继续按 CI 的 structure 范围检查，不记作实物或图像审核。
