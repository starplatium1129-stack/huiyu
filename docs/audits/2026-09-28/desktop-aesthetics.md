# 桌面页面美观与实用审计

2026-09-28。用户选择“角色档案的整体质感与信息层次”作为参照，桌面客户端优先、同时支持桌面浏览器。本轮交付为审计结论与改进顺序，未修改产品界面。

## 结论

现有二次元视觉已经成立。最值得继续统一的是：内容与工具的主次、集合与详情的层级、进入页面后第一个有效操作的位置。增加装饰、扩大圆角或给各页都加粒子效果，不能解决这些问题。

角色档案值得沿用的做法：

- 页头明确说明“在哪里”，数量与辅助入口保持低权重。
- 书架、角色列表和详情有清楚的进入/返回关系，主内容不会同时铺成多套完整视图。
- 画面、名字、故事先建立人物认知；绘制、房间、相关场景围绕同一人物组织。
- “素材与模型”后置并折叠，技术信息不会和人物本身抢主视觉。
- 以背景、薄边框和间距区分层次，保留角色色与手绘图标作为强调。

保留角色档案的展示特点；工具页继承其信息秩序，按各自任务决定密度。这里没有把用户喜好解释成访问频率，也没有假定先前参考项目的名称。

## 优先处理的发现

以下均为 P2/P3 的体验改进建议，本轮没有发现新的 P1 页面阻断；排序按改善收益，而非测试失败数量。

### 1. P2：画册和作品页同时铺开集合与内容，首屏让位给重复导航

有内容夹具已复现：1440×1000 下，参考画册的首排样张从约 y=823 开始；我的作品的首排图片约从 y=836 开始。单个相册也占据完整横向区块，后面再叠搜索、筛选、列表标题；点击封面改变下方筛选后，上方相册概览仍保留。数量少时大片空白、数量多时重复浏览层级都会挤压作品。

**建议：**采用明确的“画册概览 → 当前画册”层级，或让“全部作品 / 按画册”成为两个视图。进入画册后，上方收成名称、数量、返回/切换入口，优先把图片呈现出来。保留现有封面与拼图的质感。

**验收重点：**分别用 0/1/多个相册和少量/大量作品复核；桌面打开列表即可看到完整的第一排主要内容，进入/返回画册保留筛选与阅读位置。

依据：[GalleryView](../../../src/views/GalleryView.vue)、[GalleryProjectAlbums](../../../src/components/gallery/GalleryProjectAlbums.vue)、[ShowcaseView](../../../src/views/ShowcaseView.vue)、[ShowcaseAlbums](../../../src/components/showcase/ShowcaseAlbums.vue)。截图：`light-1440-gallery.png`、`light-1440-showcase.png` 及深色版本。

### 2. P2：故事短片页在编辑之前堆叠过多说明与导航

当前顺序是档案状态条、标题说明、四张模式卡、步骤跳转，再到编辑区。1440×1000 首屏中，主要编辑区标题约在 y=579，输入框约在 y=657；生成操作位于更后方。1280×800 的桌面窗口更明显。页面能表达功能丰富，但重返创作时仍需经过完整介绍。

**建议：**合并重复页头与状态；模式使用紧凑切换，仅解释当前模式；镜头输入与预览成为工作区主体，将画幅、时长和生成操作整理为持续可达的操作带。技术状态继续保留在次级区域，错误时再突出。

**验收重点：**1280×800 和 1440×1000 下，当前模式、主要输入、输出预览与生成入口形成连续路径；四模式的首帧、尾帧、分镜内容不能因压缩外框被隐藏。

依据：[VideoStudioView](../../../src/views/VideoStudioView.vue)、[视频页样式](../../../src/assets/css/video-studio-view.css)。截图：`*-1440-video.png`、`*-1280-video-short.png`。

### 3. P2：模型资料把历史评测放在实际使用之前

卡片依次显示文件名、说明、权重与标识胶囊、触发词、评测面板、指标小卡，最后才到“复制触发词 / 用此角色绘制”。评测通过状态很显眼，而本机可用性和入口实际作用在卡片后段。信息完整，但卡内层级多，难以快速比较“适合什么、怎样使用”。

**建议：**卡片顶部用角色/用途与适用引擎建立识别，文件名作为次级信息；靠近顶部放操作及本机状态说明。历史评测默认展示一句摘要，方法和指标按需展开。继续明确历史评测通过不代表本机已安装；现有入口只选择角色，不能被包装成已加载该版本。

依据：[LoraView](../../../src/views/LoraView.vue)。截图：`*-1440-lora.png`、`*-1440-lora-details.png`、`*-1280-lora-short.png`。

### 4. P2：色彩情绪页把阅读材料放在选择工具之前

页面先展示完整光色观察文章和参考图，再到情绪色板。选择后的强主按钮是“复制 Prompt”，直接带入工作台反而是次按钮。对来选色调的人，选择和应用要经过多层阅读。

**建议：**先呈现情绪选择、当前色板和“带入工作台”；观察文章作为当前选择的说明，或独立的可展开阅读区。复制和导出保留为辅助操作。保留现有手帖气质与内容，不需要删除学习材料。

依据：[ColorScriptView](../../../src/views/ColorScriptView.vue)、[ColorLightNotebook](../../../src/components/library/ColorLightNotebook.vue)。截图：`*-1440-color.png`。

### 5. P2：资料四页的二级导航统一了，外围框架仍在跳变

画风、色彩、模型、剧本使用同一个导航组件，但容器最大宽度分别为 1120、1000、1100、1450px；页头又分别组合返回链接、ArchivePageHero、WorkspaceArchiveBar 与普通标题。切换同一组资料时，导航位置、长度和正文起点明显变化。

**建议：**统一这一组的页头/说明/二级导航起点与宽度；正文按“资料卡 / 阅读 / 分幕编辑”的实际需要展开。标题只保留一个主要层级，去掉重复的章节号和介绍层，避免再加一套装饰容器。

依据：[StyleView](../../../src/views/StyleView.vue)、[ColorScriptView](../../../src/views/ColorScriptView.vue)、[LoraView](../../../src/views/LoraView.vue)、[ScenarioView](../../../src/views/ScenarioView.vue)。

### 6. P2：找角色、看档案、选场景的导航关系可以更连贯

一级导航有参考画册、角色场景、灵感、绘制、房间；角色档案在“更多 → 发现”。档案详情实际上已经集中了绘制、房间、场景与分镜入口，是自然的人物任务中心。同时，详情页内“浏览相关场景”保留人物，而页头“浏览角色场景”直接去总库，会丢失当前人物上下文。

**建议：**把“角色”作为明确的一级概念，人物内提供“档案 / 场景”二级切换，并双向保留当前人物。仍保留场景直达及最近使用路径，避免增加熟练用户的步骤。页头跳转可以先修上下文，再决定主导航调整。

依据：[AppNav](../../../src/components/AppNav.vue)、[CharacterView](../../../src/views/CharacterView.vue)、[PopularSceneExplorerView](../../../src/views/PopularSceneExplorerView.vue)。

### 7. P2：灵感场景的当前范围需要比分类“全部”更明确

新用户默认范围为“人设核心”，有使用记录时默认为“我的常用”；层级筛选放在收起区域，默认范围也不计入精细筛选徽标。页面的选中分类显示“全部”，虽然结果旁另有范围文字，仍需要读多个位置才能理解当前可见集合。

**建议：**把“推荐 / 常用 / 完整库”作为明确的浏览范围，分类作为其下一层。当前范围与结果数并列，只保留必要的计数。“全部”可明确为“全部分类”，避免误解成全库。

依据：[SceneExplorerView](../../../src/views/SceneExplorerView.vue)、[useSceneExplorerWorkspace](../../../src/composables/scene/useSceneExplorerWorkspace.ts)。截图：`*-1440-scenes.png`。

### 8. P2：控制室应把服务状态与对应动作放在一起

顶部四张状态卡、绘图/聊天模式卡与下方服务启停列表重复表达服务状态；四张状态卡还都跳到同一个资源区。“绘图优先”实际描述的是让显存给 WebUI。从 Anima/Krea 未连接提示进入的人仍需自行判断该操作哪个服务。

**建议：**每个服务的状态与主操作放在同一单元；从创作页进入时带上当前引擎，突出所需服务。“绘图优先”明确适用对象，其他服务及高级资源操作后置。继续保留已有确认、取消和权限边界。

依据：[ControlView](../../../src/views/ControlView.vue)。截图：`*-1440-control.png`。离线是隔离夹具状态，不能据此断言真实服务有问题。

### 9. P3：陪伴页未启用动态立绘时存在重复入口

浏览器陪伴视图的“加载动态立绘”和“启用 Live2D”都调用同一个处理函数，在人物两侧形成两份视觉强调。

**建议：**保留一个靠近角色的启动入口，启动后原位显示状态；按需下载说明进入提示或设置。原生桌宠会隐藏部分浏览器控件，因此不能将这条直接推广为原生窗口缺陷。

依据：[ChatCharacterStage](../../../src/components/ChatCharacterStage.vue)、[原生陪伴样式](../../../src/assets/css/companion-surface.css)。

| 首页 | 角色主视觉、两个层级明确的主动作；已有继续创作入口 | 保留主体，只随全站导航调整入口命名 |
| 角色档案 | 书架/列表/详情关系、克制材质、人物内容优先 | 作为基准；详情展台较长，可考虑在页头补创作快捷入口，不改变展示特点 |

| 绘制工作台 | 三栏职责明确、画布为主体、生成条独立 | 保留三栏；上一轮宽度修复有效，不为填空增加装饰 |

| 色彩情绪 | 手帖内容有解释价值 | 选择与应用前置，见发现 4、5 |
| 模型资料 | 历史信息完整、可用性边界写明 | 第一批调整摘要/评测/操作顺序，见发现 3、5 |
| 剧本模式 | 剧本选择到分幕的顺序明确 | 保留分幕层级，统一资料页外框，见发现 5 |
| 场景维护 | 目录与检查器的桌面工具结构合理 | 保持工具密度；主线刚更新桌面写入能力，旧只读审计结论已剔除 |
| 聊天房间 | 人物与会话分区清楚，模型未加载仍可交流 | 保留主体；设置入口可进一步按角色/会话/连接分组，作为后续细化候选 |

| 陪伴聊天窗 | 独立窗口的阅读/输入关系简单 | 保留；不把全屏打开产生的留白当作设计缺陷 |
| 控制面板 | 固定目录与操作区便于桌面定位 | 按当前创作任务改善状态/动作关联，见发现 8 |
| 404 | 角色插画与明确返回动作 | 保留，无需额外包装 |

## 实施顺序与统一准则

1. **第一批：参考画册 / 我的作品、故事短片、模型资料。**解决首屏核心内容后移和主操作不突出，收益最直接。
2. **第二批：资料页外框、色彩情绪、灵感范围、人物导航。**统一同类页面的阅读节奏与路径。
3. **第三批：控制室任务引导、陪伴重复入口。**分别按服务权限和真实桌面窗口复核。

共同准则：同页有一个明确的主任务；同类页面保持稳定的标题与导航位置；同一集合的概览和详情有明确层级；技术说明靠近相关决策且按需展开；角色/作品承担视觉特色，状态色只表达状态。深浅主题保持同一信息层次，桌面小窗与显示缩放仍需检查。

## 当次证据与边界

- 视觉基线为 `codex/layout-audit@82bf197d`，包含前一轮布局修复和桌面优先规则。另对主工作区 `main@3073cd61` 的新增界面差异做源码核对；其桌面场景维护已启用可写用户内容，旧版本“桌面不可保存”不计入本次问题。
- 本次新增 **54 张桌面截图**：18 路由的双主题首屏，角色详情/阅读区、专家工作台、画面参数、LoRA 细节，以及首页/工作台/视频/LoRA 的 1280×800 桌面小窗。其他首屏为 1440×1000。没有运行手机/平板矩阵。
- 使用隔离 Rust 网关和浏览器临时存储。画册/作品用现有本地图像填充明确标注的布局夹具；重复样图、测试缩略缺失和离线状态不当作生产内容缺陷。真实用户的大作品库及服务在线状态需在实施时补验。
- 未调用生成、视频、音频或 Live2D 模型，也未修改内容和生产存储。浏览器页面不等于 Tauri 原生窗口实测，独立桌宠/聊天窗需按实际尺寸验收。
- 截图与观察数据保留在被忽略的 `runtime/ui-aesthetics-2026-09-28/`：`overview-light.png`、`overview-dark.png`、各页原图和 `observations.json`。此次 54 次截图状态没有文档横向溢出；这项只说明布局边界，不代表审美通过。
- 本轮不以历史 211 项功能测试替代审美判断。产品源码未改动，交付只新增此报告并登记索引。
