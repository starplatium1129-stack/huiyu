# 性能优化报告

日期：2026-09-28。实现提交：`9a94f072`。环境为 Ryzen AI 9 H 365 / Radeon 880M 办公机；4070 Ti S 主力机尚未实测。未降低完整模式画质、帧率目标或生成质量，未改变内容分级与存储安全边界。

## 改动与实测结果

以下均为对应场景的局部结果，不能相加为全应用提速比例。

| 优化 | 测量范围 | 结果 |
| --- | --- | --- |
| 图库筛选 | 1 万作品、5 千项目成员、6 次连续查询，5 轮热缓存中位 | 缓存排序/搜索文本、Set 成员查找：577.56 → 51.33 ms；结果一致 |
| 搜索缓存释放 | 万条作品，5 轮 Node/Vue 显式 GC | 清空搜索后额外堆留存：24.74 MB → 约 38 KB；非空查询仍复用索引 |
| 任务轮询 | 100 个未变化任务、20 次轮询，7 轮 | 深复制 6000 → 0 次，状态处理 109.41 → 0.537 ms；保留快照隔离，不含网络开销 |
| 原图取消 | 标准 fetch、本地 HTTP、4 MiB 分块传输 | 最后读者取消后止于 256 KiB；只取消一个共享读者时，另一个仍完整读取 |
| 上游 JSON | 1.25 MB 正文，release，每样本 10 次解析、20 样本 | 去除同容量重复原文分配；中位 11.736 → 6.980 ms；纯文本兼容行为保留 |
| Rust 行解析 | release，新旧交替 7 轮 | 8192 条短行：11.77 → 0.64 ms；碎片长行：67.25 → 0.46 ms；输出及大小/超时限制不变 |
| 同图解码合并 | 8 个同图冷请求、7 轮 | CPU 中位 218.75 → 125 ms；墙钟 82.46 → 87.53 ms，输出一致；节省 CPU，不宣称单图更快 |
| 项目反查索引 | 10 万关系、200 次查询、3 轮 | 查询中位 449.03 → 0.293 ms；不含首次建索引和完整删除事务，保留 v3 数据协议 |
| Live2D 指针合帧 | 同帧 100 次指针事件 | 布局读取 100 → 1 次，保留最新坐标、平滑和生命周期行为 |
| 粒子提交 | 1000 点、8 色、60 帧 | bounds 分配 960 → 16，浅色 uniform 调用 11520 → 5940；绘制次数及上传字节不变 |

原图取消覆盖预览关闭、换图、离页、PhotoSwipe 邻域与候选对比；同时修复任务媒体迟到查询借用新请求 signal 的竞态。原图保留 35 秒总超时，已完成的大 Blob 不加入长期缓存。

## GPU 与空闲资源

880M / ANGLE D3D11 实测：深浅主题、运动/缩放/静止共 24 组旧新像素一致。960 个有效 GPU timer query 未显示稳定 GPU 时间改善，因此只认定减少分配和提交工作，不宣称完整模式 GPU 加速。

修复应用内“减少动态效果”未停止粒子绘制的问题。在隔离应用中实际切换 full → reduce → full，主 renderer 单核 CPU 约 16.97% → 0.077% → 20.21%；独立浏览器 GPU 进程的 3D 引擎采样分别为 4–6%、全 0%、5–7%。合成隐藏信号下也停止绘制。窗口约 6.7–12.5 秒；这些数值不是整机占用、真实最小化或跨机器功耗结论。

未采用两项候选：容量 256 的 LRU 在循环扫描场景增加约 59.6% 未命中，简单老化 LFU 在大热集切换增加约 52.6%；静止 GPU 缓存则需要额外缓冲或改变驱动保留方式，显存和运动成本尚不足以支持采用。

- Rust 格式、Clippy、97 项默认测试通过；4 项原生专项和 4 项手动基准默认跳过，相关性能基准单独执行。
- 完整前端测试、1171 项 Node 单测、39 个契约文件通过；最后调整的 23 项定向测试通过，原有媒体/缩略图回归保留。
- 类型、体量门禁、Web 构建预算及 Rust release 构建通过；图库/粒子双主题浏览器 12 项、release 后端冒烟 2 项通过。
- 深浅主题各 100 次页面往返与预览通过，200 次合成隐藏检查没有待执行动画帧，未触发真实 API 写入。
