## 已实施的热点优化

| 路径 | 问题与改动 | 证据口径 |
| --- | --- | --- |
| 图库连续搜索 | 每次输入重复排序、拼接长提示词与分词；项目成员用 `includes` 嵌套扫描。将排序和规范化搜索文本独立缓存，项目成员用 Set，查询只分词一次；保留字段原位修改的响应式更新与 ID 严格匹配。 | 1 万作品、5 千项目成员、6 次查询、5 轮，热缓存中位 577.56 → 51.33 ms，逐条结果一致。[原始样本](../../evidence/gallery-filter-performance-2026-09-28.json)。新增字符串缓存有内存成本，未把该结果当作冷进入或真实大图库堆峰值证据。 |
| Live2D 指针输入 | mousemove/桌面指针事件每次同步读取布局。合并到已有凝视 rAF，以当帧布局和最新坐标计算目标。 | 隔离回归中同帧 100 次事件：100 次矩形读取 → 1 次；后续平滑帧不重复测量。保留 clamp、平滑、mouseleave、隐藏与会话更换行为；不是实际高刷设备 FPS 测量。 |
| 聊天流解析 | 逐行 `Vec::drain` 搬移剩余字节；碎片长行每次从头扫描。改用消费/扫描游标，只在追加 chunk 时压缩残尾。 | Release、新旧交替 7 轮中位：8192 条短行 11.7744 → 0.6405 ms；256 KiB 行分成 128 B 小块 67.248 → 0.4634 ms。全部输出一致，保留 1 MiB 帧、16 MiB 总量、UTF-8 容错和读取超时。只测解析，不代表模型响应加速。 |
| 粒子减少动效 | 浏览器发现应用内 reduce 设置未接入粒子生命周期，仍持续绘制。统一读取应用/系统偏好，观察 data-motion；隐藏或停用页不因偏好变化唤醒。 | 深浅主题均验证 reduce 后 1.2 秒无新增绘制、full 后继续、隐藏停止/恢复继续；保持实际渲染计数探针，不以 CSS 状态代替停止绘制。 |
| 同图冷缓存并发（沿用前批） | 同一图片只保留一个实际解码器，其他请求等缓存；不同图片仍可使用两个名额。 | 8 请求、7 轮 CPU 中位 218.75 → 125 ms；墙钟 82.46 → 87.53 ms，输出字节一致。主要节省 CPU，不宣称单图变快。 |
| 项目成员反查（沿用前批） | 为 `project_artworks(artwork_key)` 补充反向索引，旧 v3 库打开时幂等补齐。 | 10 万关系、200 次查询、3 轮中位 449.03 → 0.293 ms；不含索引建立和完整删除事务。[存储证据](../../evidence/rust-storage-performance-2026-09-28.json)。 |

## 检查后保持的机制

- 路由/字体/重功能已经按需加载，现有构建预算继续执行，不通过搬动 chunk 或抬高预算制造通过。
- 图库已分页渲染，媒体 HTTP 使用 64 KiB 按需流；本轮不全量预加载高清图，也不减少文件身份/哈希校验。
- 隐藏页、低动态效果及 Live2D 释放已有生命周期逻辑；新增指针合并复用现有帧调度，不引入第二个循环。
- 写入事务、同步落盘、模型参数、显存调度和分级边界保持原契约。未安装依赖，未调用真实模型或操作用户作品库。
