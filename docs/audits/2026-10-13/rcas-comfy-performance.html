锐化、蒙版合成与 Comfy 节点查询优化

2026-10-13。本轮优先处理普通出图／Latent 高清的锐化内存、蒙版大图合成，以及默认 ComfyUI 后端的重复全目录查询。改动 4 个 Python 与 3 个 Rust 源文件，无新增依赖。下面的内存数字均为源码与尺寸推导，没有本轮设备性能实测。

范围优化收益及边界
RCAS 锐化按 128 行加上下真实邻接像素计算，只在整图边缘 reflect。保留五点极值、RGB 最小 lobe、FP32 表达式顺序、clamp 和最后的 dtype 转换。强度零仍直接返回输入。4608² RGB 的每份全图 FP32 中间值为 243 MiB；核心行带约 6.75 MiB，边缘及 pad 另占少量空间。多份中间值均变为行带，但输入、最终输出和分配器缓存仍存在。更多内核启动与逐带写回可能抵消部分收益，不能宣称已提速。
蒙版合成复用私有转换参考图和新结果，仍分别执行乘、减、乘、加；不改成融合运算，不覆写调用方图片、PIL 原图或蒙版。4608² 时，表达式的活跃张量理论峰值约从 1296 MiB 降至 891 MiB，少约 405 MiB。此估算仅计算相关张量，不含模型、PIL、分配器缓存或整个进程。
PIL 转 FP32新建的私有 NumPy FP32 数组原位除以 255，随后按原方式转张量；Lanczos／uint8 量化边界不变。4608² 参考图或 resize 后目标图的归一化阶段少一份 243 MiB 全图浮点临时数组。这与合成峰值属于不同阶段，不能直接相加为任务峰值降幅。
Comfy 可选节点检查状态刷新和可选节点生成准入只并行查询 AP_CLIPSeg_TextMask、ConditioningKrea2Rebalance、ComfyUI-Krea2T-Enhancer 三个节点。继续每次读取新状态。由一次全节点目录请求变为三个定向请求，避免枚举、传输和解析不相关节点及其模型下拉目录。没有本机响应大小或延迟数据；服务不支持定向端点时保持 unknown。

边界与执行身份

RCAS 多 batch、非连续输入、FP16／BF16／FP32 的契约保留；正强度下高度或宽度为 1 仍由 reflect 拒绝。内部行带接缝读取真实相邻行，不把接缝误当作图像边缘。源码保持逐像素算式，不等于已证明 GPU 输出逐位相同。

正 rcasStrength 的 TeaCache 档位新增 sampling.rcasExecutionRevision=rcas-fp32-rows128-v1；旧正强度档位 auto 回退完整计算，严格启用／验收拒绝失配。零强度档位不新增该字段，不自动改写既有档位。实际执行锐化成功后，nativeRuntime.refinement.rcasExecutionRevision 记录新标识；旧 worker 缺字段仍兼容，坏字段继续标为未验证。

Comfy 定向响应只有成功状态下的空对象判为 missing；仅一个指定节点且 input 为对象才判为 ready。网络／HTTP 错误、错名、额外键和坏结构判为 unknown。Krea 任一节点不确定则该组不确定；自动蒙版与 Krea 独立判定，不再受无关节点坏结构连带影响。生成前仍要求所选组 ready。

三个查询复用现有共享客户端、每响应 2 MiB 上限、网络读取 5 秒超时、取消及解码跟踪；不创建后台任务，不加缓存，不退回全目录。定向端点与缺失节点空对象行为见 ComfyUI 官方 server.py（2026-10-13 查阅）；仓内视频模块也已使用该端点。这些是源码依据，不代表当前用户服务已验收。
