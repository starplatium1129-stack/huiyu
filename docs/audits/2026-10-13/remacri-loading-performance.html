Remacri 加载与高清放大优化

2026-10-13。本轮消除放大网络的重复复制、高清像素转换的全图临时分配，并将放大模型接入现有有界上传器。以下规模均由源码与固定结构推导；没有本轮 GPU 提速或峰值内存实测。

瓶颈本轮改动可核对的规模
Remacri 分块重复复制DenseBlock 的首个卷积直接读取输入，删除单张量 cat；其余卷积、激活、残差顺序和 FP32 保持。23 × 3 = 69 次复制／完整 512² 分块；每次 64 MiB，减少约 4.31 GiB 的累计写入及相应读取。这不是峰值显存下降量，也不是耗时实测。
高清像素转换内存Lanczos／PNG 的 RGB 转换改为每 128 行处理，保留 FP32 乘 255、裁剪与 uint8 截断；输入不修改，非有限值仍阻止发布。6144² RGB 的旧乘法、clip 临时数组各 432 MiB；现在对应浮点 scratch 为 9 MiB，另有少量逐行有限性检查空间。原 FP32 图、108 MiB uint8 图和 Pillow 等存储仍存在。
放大模型参数逐个上传严格验证后复用现有 packed uploader；不适用的 CPU 布局保留 module.to，CUDA 错误继续上抛。模型只存活于当前放大阶段。351 个卷积、702 个参数，载荷 66,791,948 bytes，对齐后 66,827,276 bytes。布局适用且 pinned 分配成功时，由逐参数上传改为 2 次不超过 32 MiB 的传输；最多 64 MiB 活跃 pinned staging。实际策略与次数以新观测为准。

完整性、兼容性与观测

固定文件名、完整键集合、FP32／形状及有限性校验均在上传前完成；既有 TeaCache 条件下的加载前后 SHA 校验保留。没有新增常驻权重缓存、精度降级或模型下载。512／32 分块和 CUDA OOM 后 256／128 重试策略保持。

固定依赖中，每个 safetensors 张量取得独立 storage 切片；PyTorch 的切片拥有独立 StorageImpl，并引用原映射。因此共享同一个文件并不必然触发上传器的共享 storage 回退。依据为 safetensors 0.8.0 源码与 PyTorch 2.8.0 源码；这是源码适用性审查，设备行为仍待验收。

nativeRuntime.refinement.upscale 新增执行标识，以及 loading.readWallSeconds、loading.uploadWallSeconds 和上传策略／字节数／调用数／staging。计时是 CPU wall span，读取阶段包含模型结构及权重检查，不含外层 SHA；各阶段不能直接相加成任务耗时。旧 worker 缺少新字段仍兼容，存在但无效的字段继续标为未验证。

Remacri 执行标识为 remacri-no-single-cat-packed-v1，仅在既有 Remacri 权重身份范围加入 sampling.upscaleExecutionRevision。旧 Remacri 档位在 auto 模式回退完整计算，严格启用／验收时拒绝失配；不改写档位。Latent 与非高清任务的身份保持。

剩余限制

主模型冷加载仍承担完整文件校验与反序列化，Remacri 仍每次装载和检查全部权重。可选 compiled-fused-sage 模式切换 LoRA 时，基础权重恢复仍以 32 MiB 缓冲串行读取和阻塞上传；本轮未修改该设备同步路径。上述路径与当前优化的耗时占比，需用对应主力机观测判断。
