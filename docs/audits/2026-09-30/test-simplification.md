# 日常测试精简（2026-09-30）

## 范围与决定

本轮调整测试选择、隔离夹具启动及弱断言，不修改产品逻辑。工作区有其他会话的文档与 ComfyUI 启动脚本改动，保留其已有改动；本文只记录本轮测试工作。此前 E2E 已在 9 月 28 日逐项缩减，本轮不以测试数量为目标继续删掉实际故障回归。

- 新增 `npm test`，复用 `gate:quick`。自动 UI 检查通过 Vitest 的导入图选择相关单测；纯 CSS 只执行字面值、对比度、颜色、动画四个扫描，不跑无关类型检查/单测。显式 `ui` 和其他静态资源保留完整前端套件；未找到相关单测时明确提示验收边界，样式仍需受影响页面的实际视觉验收。
- 已登记的 critical/nightly E2E 文件自身变化仅跑所改文件，复用当前 dist；混合 UI/style/data 变化先构建。共享 runner/fixture、未知或删除路径仍触发 full，设备和真实模型保留专项入口。
- Node 的 check/unit/contract 支持精确文件参数，源文件与生成入口去重；未知文件、跨套件文件、非法选项失败。无参数仍执行完整清单，既有契约并发策略和超时不变。
- Windows 部署 PowerShell 集成夹具从并发单测批次移至批次后的单独阶段：首轮并行全套超时，独立同一用例 6.5 秒通过。只处理已观察到的这一文件，其他单测仍并发 4，Linux 保持原顺序；总 300 秒上限、所有断言和逐阶段报告保留。负载是推测的影响因素，不冒称已证明底层超时原因。
- 普通页面精确选择仅启动 web Rust 服务，省去第二份临时应用复制、gateway 与五个上游服务。flows 精确选择仅启动 gateway 栈。显式访问 gateway 的 desktop 文件与未知过滤保留双栈；隔离目录、拒绝服务复用、真实 Rust 后端和清理逻辑不变。
- 删除 `test-native-controls` 的 checkbox/radio 计数加 `>= 0` 空断言，并复用一次源码读取；容器级约束继续由 `companion-focus` 浏览器检查。
- 删除 `test-ux-regressions` 仅确认队列常量存在的断言（无法验证实际持久化），及固定 `min-height: min(560px, 100dvh)` 写法的断言。队列恢复行为测试及桌宠小窗输入/按钮几何测试保留；不把删除常量检查说成持久化已经被完整验证。
- 场景滚动测试的固定 600ms 等待改为等待专家模式状态。异步重试不循环、取消、权限、分级、并发存储及双主题对比度断言未删减。

## 日常命令

```sh
npm test
npm run test:frontend -- src/utils/characterTheme.spec.ts
npm run test:unit -- test-api-client.ts
npm run test:contract -- test-anima-routes.ts
npx playwright test tests/e2e/scene-scroll-profiles.spec.ts --project desktop --workers 1
```

浏览器命令需要与产品源码匹配的 dist 和 Rust release；测试源码改变不要求重建 SPA。跨域、构建链、依赖或未知影响面使用 `npm run wf -- gate:full`；全量 E2E、性能、设备与实际生成按受影响范围另选，不作为所有小改动的固定步骤。
