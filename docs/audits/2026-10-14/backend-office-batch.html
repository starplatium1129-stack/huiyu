办公机后端批量优化与修复

2026-10-14。办公机可以继续优化后端的内存、磁盘写入、请求调度和数据库读取。本轮集中完成 7 项改动，涉及 9 个 Rust 源文件，包括任务输入滞留和统计快照不一致两项 bug 修复。范围覆盖任务生命周期、重启恢复、下载、存储与本地上游请求；没有把此前已完成的优化重复计入。

本机为 AMD Ryzen AI 9 H 365，10 核 / 20 线程，约 32 GB 内存。以下数量来自源码中的上限和操作路径，不是性能实测；本轮没有可报告的端到端提速百分比。

本次完成的 7 项改动

问题与触发条件现在的行为与收益依据适用边界
1. 原生任务输入内存滞留
内存 bug 修复		图生图和蒙版的原始字节此前被历史任务持续持有，随任务记录保留约 30 分钟。现在写入任务私有文件后释放该内存；排队取消和提前失败也会清理。按每份输入 16 MiB 上限，一份带蒙版的任务可避免滞留最多 32 MiB 的压缩图片载荷。32 MiB 是两份输入长度的源码上限，不是进程内存实测。受保护原图、任务配方和私有输入文件继续保留原有生命周期；没有改变模型输入字节或推理算法。
2. 重启重复写恢复记录
启动磁盘开销		已有有效 lostAt 的恢复记录再次启动时不再重写。对 N 份内容未变的有效记录，原来 N 次记录写入和文件同步变为 0 次；初次记录丢失时间或修正异常时间仍写入。仍读取记录并校验归属、状态、有效期；保留 WebUI 可回收结果优先级与 256 条保留上限。启动耗时尚未实测。
3. 模型下载细碎写入
磁盘与线程调度		增加 1 MiB 写缓冲，将小网络分片合并后交给 Tokio 文件工作线程。正常完成、协作取消和传输错误均先冲出已接收字节，再执行原有后续处理。单个获准下载增加 1 MiB 缓冲。续传范围、大小与完整 SHA-256 校验、刷盘及不覆盖同名文件的发布约束保留。异常终止仍可能丢失尚未写出的尾部缓冲；未实测下载吞吐或磁盘调用数。
4. 大对象指纹的额外整份副本
存储内存开销		规范 JSON 字节直接经过 8 KiB 缓冲进入 SHA-256，不再先分配完整规范 JSON 再计算指纹。大草稿、聊天历史和作品配方可少持有一份完整序列化副本。原有 JSON 值及排序所需键集合仍在内存中；8 KiB 不是整次操作的内存上限。逐项源码复核保留数字格式、数值键顺序、UTF-16 排序及字符串转义；未运行指纹等价测试。
5. 操作重试重复解码历史输入
SQLite 读取与分配		通用 start_operation 重试路径只读取操作标识、种类、指纹、状态和回执，不再查询、分配、反序列化整份旧 input_json。请求越大，避免的重复工作越多。仍按用户与操作 ID 查询，校验当前输入指纹、类型冲突和已中止状态；正常回执保持。需要原始输入的其他操作读取路径保留；没有新增索引、迁移或修改已存数据。
6. 大响应解析阻塞异步请求线程
服务响应能力		通用本地上游 JSON 传输对 ≥512 KiB 响应使用后台解码，全局最多同时 2 个解码任务。外层截止时间覆盖下载、等待解码名额和解析等待；取消后后台解析保留名额至退出，避免持续堆积脱离请求的解析工作。同步解析开始后不能强行中断，退出前会检查取消。小响应仍直接解析；原响应大小上限和文本回退保留。生成专用传输此前已有后台解码，不计作本轮新增收益。
7. 内容统计跨快照混读
并发一致性 bug 修复		统计数量、内容版本和下一个场景编号现在共用一个 SQLite 读取事务，避免并发导入时返回彼此不一致的状态。内容检查已有事务时复用其快照。5 个种类分别计数合并为 1 条限定种类的分组查询。独立统计只提交自己创建的事务，不嵌套或提交调用方事务。缺失种类继续返回 0，返回字段不变，保留既有索引可用的种类条件。下一个编号仍是当前快照的建议值，不构成写入预留。
