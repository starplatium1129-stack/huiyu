## 二、已确认问题与优化决定

### 012-F01 · P1 · 剧本选择夏目后，绘制入口回到了宁宁

**确认，双主题浏览器复现。** `src/views/ScenarioView.vue:45` 的“前往工作台绘制”只带 `scenario`；`src/composables/prompt/usePromptDeepLink.ts:70` 在缺少 `char` 时默认宁宁。选择夏目后，链接为 `/prompt-builder?scenario=promise`，实际 `article.pb[data-character]` 为 `nene`。这不是模型画质问题，是点击承诺与实际创作上下文不一致。

落实：链接携带当前已选择角色；以稳定 ID 处理，不从显示名猜。覆盖两角色 × 三本剧本、首次直达、同页切换、后退/重开，并核对第一幕故事、角色、画幅和手动语义词条与所选来源一致。视频分镜交接已有独立路径，不因修绘制链接而改写它。保留“只带 scenario 的历史链接默认宁宁”的兼容行为。

修复不改剧本文本或编译策略；若范围扩到提示词/服装/编译参数，按 AGENTS 与提示词 skill 另补真实画面证据。普通链接修复可先用浏览器状态与模拟最终请求验收，不宣称真实生成通过。

### 012-F02 · P2 · 9 个当前文档页面的浅色主题没有真正生效

**确认，截图、计算样式和源码一致。** 10 页中只有 `/docs/getting-started.html` 引入 `light-theme.css` 并得到浅色 `--bg-base:#fff8f4`。其余 9 页即使 `data-theme=light`，基础色仍为 `#211c30`，页面保持深色；品牌/导航部分又会响应主题，造成局部混合。例：`docs/index.html`、`docs/roadmap.html`、艺术/场景/提示词/标签指南。

落实：复用统一文档主题加载与图标/导航体系，补真正的浅色样式，核对首次加载、站内跨文档、主题切换和系统高对比回退。不要仅把 html 属性设为 light 就算通过。当前文档中的旧品牌、Emoji 装饰、重复导航文案可同步改为现有绘遇品牌和线条图标；规则/提示词示例正文保持原语义。

验收：10 页两主题实际计算色与画面一致；长表格/代码块在 390 和 320 CSS px 下有明确自身滚动边界，正文无需左右滚动。历史归档的共享外壳可受益，但不重写历史报告内容。

### 012-F03 · P2 · 绘制页窄屏默认顺序未体现画布优先

**当前布局已测，属于设计契约偏差。** 390×900 下，两主题均为素材区从 y=311 开始、高 527px；画布从 y=854 开始。首屏主要看角色选择，画布与生成动作进入下一屏。已有“创作素材/画布预览/输出设置”跳转可用，应保留；不能描述成画布不可达。

DESIGN.md 要求窄屏优先画布、再场景/决策。落实时保留当前角色摘要，将默认素材区收拢或按真实阅读/焦点顺序重新组织画布与选择入口，避免 CSS 视觉顺序和键盘顺序相反；同一个画布/状态实例不重复挂载。桌面三栏和结果大画面保持。

验收：390/768/900/1280/1440 中主要结果、服务状态和下一步清楚可达；基础/专家、空/生成中/有结果分别复验。不能为了“首屏更短”隐藏必要输入、缩小正文或削减成品展示。

### 012-F04 · P2 · 缺素材时大幅占位压低了仍可用操作

**缺素材基线已测，优化建议。** 隔离环境未配置样张/参考素材；画风、色彩手帖、剧本封面和场景卡正确显示占位，没有把 pending 伪装成图片。画风页 390 下第一张占位高 255px，首个“用这个调子绘制”在 y=984；两主题相同。默认缺素材时，文字和配色仍可用，却被空画片占用较多空间。

落实：只对缺图/未连接状态使用更紧凑的图标、说明和可用操作，或让配色/主要操作上移；有图状态继续完整构图、保持角色和图像为主角。明确“目录未连接、文件加载失败、等待审核、无匹配”四种不同状态。不要用无关图替代某个未交付服装/样张，也不为了演示默认下载素材。

验收：同页有图/缺图/加载中/失败后恢复均能使用；缺图状态主要操作更早出现，有图状态不被压缩；不出现布局跳变导致误点。此结论不证明主力机缺少这些文件。

### 012-F05 · P2 · 模型资料页的资料、安装状态和使用入口需要分开

**源码事实 + 产品闭环建议。** `LoraView.vue` 展示 `sceneStore.loras` 静态资料、推荐权重、触发词和既有评测；`loadCatalog()` 调用全量 `sceneStore.load()`。当前不是磁盘模型安装探测页面，也没有卡片级“到工作台使用”或触发词复制操作。页面却使用“本机目录/已就绪”等容易被理解为可立即运行的语句。

落实：把“资料已收录”“本机已检测可用”“引擎不兼容/未检测”分别表达；不凭静态 JSON 或历史评测声称当前安装成功。为具有明确映射的模型提供安全的工作台入口，为触发词提供复制反馈；无法映射的项目明示资料用途。读取资料只加载实际所需数据，避免顺带载入无关蓝图。

验收：模型未安装时不显示虚假可用，兼容入口能定位正确角色/引擎而不替换用户草稿；目录失败有重试；复制失败有反馈；历史评测注明其日期和范围。不得为让按钮可点而改变受控模型白名单。

### 012-F06 · P2 · 导航、浏览器标题和页内称呼仍有多套名字

**源码确认，易用性建议。** 路由 meta 的“画师风格/色彩脚本/作品展/完整房间”，与页面和导航的“画风/色彩情绪/参考画册/房间”不完全一致；模型页还混用 MODEL SHELF、CATALOG READY 等机器状态。各页面已有标题和导航，不重复实施“全站加 h1”。

落实：建立简短稳定的页面名称映射，区分导航短名、页内诗意标题和浏览器标题；同一功能在搜索、帮助、通知、深链回退中应可辨认。诗意文案保留在副标题，不承担错误恢复或危险动作的唯一说明。英文只在风格装饰或技术信息确有用途时出现。

验收：从首页、全局搜索、更多菜单、相关内容导航到同一页面，用户看到的是同一类对象；已有 URL 和旧搜索别名保持兼容。

### 012-F07 · P2 · 离线和未就绪状态要提供“现在能做什么”

**已查看默认/缺资源画面，完整失败链待执行。** 视频当前是四种模式：文字、图片、首尾帧、分镜；后二者由 H3 能力决定。聊天、画册、LoRA、控制台也有各自未就绪入口。已有错误/禁用机制，不能简单宣布缺失错误处理。

落实：对每一种禁用/未连接说明具体缺什么、去哪里检查、是否保留草稿及还可做什么；辅助说明应能被键盘/触屏访问，不只藏在禁用按钮 title。将“模拟上游可用、资料登记、真实服务连接、已完成结果”分开。控制台真实启停、资源下载/安装、聊天凭据保存均有副作用，使用隔离服务与桥接替身验收。

验收：空/错/忙碌/取消/权限拒绝/未知新版保护均有明确恢复路径；没有反复点击产生重复任务、取消后被迟到结果覆盖或没保存却提示成功。011 和上一轮的可靠性保护保持。

### 012-F08 · P2 · 美术验收要与每个功能的状态结果绑定

**验收方式建议。** 默认截图 112 项无溢出不意味着编辑弹窗、任务失败、长回复、图片缩放、管理写入等已经全部通过。当前已有很多专项 Playwright 和组件测试，应通过功能 ID 映射复用，不能为报告数字重复运行或用静态源码字符串测试替代行为。

落实：新任务逐项更新配套功能矩阵，每个功能写清触发、输入、结果、保存/取消/失败/返回、两主题证据和所用测试。新增状态按风险补用例；已有证据只有在源码/构建对应时复用。需要真实设备的项保持 D，不能通过删掉矩阵行得到“全部完成”。

### 012-F09 · P2 · 独立聊天窗与多数文档缺少主内容地标

**确认，实际 DOM 检查。** `/companion-chat` 与除 `/docs/index.html` 之外的9个当前文档，在四个默认组合中均没有 `main` 或 `role=main`；页面和h1正常显示。这是与应用其他页面不一致的语义结构，不代表视觉空白，也不能仅凭此宣布整站违反全部无障碍标准。

落实：按实际内容分区补充唯一主内容区域和可用的跳过导航入口；独立聊天窗的标题栏、消息阅读区与输入区语义清楚，不嵌套多个main。原生拖动区域和焦点规则保持。文档的主题与主内容语义分别断言，避免一个通过掩盖另一个缺失。

验收：这些页面均有可访问名称清楚的主内容地标，键盘跳转后落点可见、不卡在固定导航下；已有消息log、状态通知和输入标签保留，屏幕阅读器实际播报仍需对应环境补证。

## 四、采用的实现依据

1. 品牌与布局的第一依据仍为仓库 [DESIGN.md](../../../DESIGN.md)；Apple 风格只提供层级、可读性、材料节制和反馈方法，不把本项目变成通用管理后台。
2. [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)强调字号、字重与信息层级及不同情境可读性。本次通过官方文档 JSON 读取正文；借用原则，不把原生 pt 数值直接照搬成网页 CSS px，也不安装/嵌入 Apple 字体。[官方 Layout](https://developer.apple.com/design/human-interface-guidelines/layout)用于对齐、层次与适应窗口的设计判断。
3. [WCAG 2.2 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字 4.5:1、大字 3:1；项目对禁用文字另有更严格令牌要求。[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)的 AA 基线为 24×24 CSS px 或适用例外；本项目粗指针共享控件目标是 44×44，不混淆二者。
4. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)用于窄屏、缩放和固定工具条核验；[拖拽替代](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)用于分镜调序、滑块等需要评估的单指替代操作。
5. [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)用于焦点进入/约束/Escape/返回；优先复用现有 Reka 与 useFocusTrap，避免新增第二套弹窗机制。
6. [web.dev 的 INP 优化](https://web.dev/articles/optimize-inp)用于测量交互延迟与长任务。本次未做真实用户 INP 采集，不能把脚本截图耗时、动画时长或包体数字当成 INP。

不增加新依赖作为审美前提；确需新增库时先证明现有原生控件/Reka/业务组件不能满足，并检查退出方式、包体和许可。用户授权自主查资料，不要求套用网上某一套模板。
