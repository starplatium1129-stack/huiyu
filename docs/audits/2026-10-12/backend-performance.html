后端性能优化续报

2026-10-12。本轮落实四项优化，当前改动已集成。以下收益来自源码操作量与分配量推导，尚无本轮真实耗时、RSS 或模型对照，不给出提速百分比。

范围实际改动与收益保留边界
相册批量整理 / 撤销事务内维护虚拟成员与位置，事务末尾每个受影响相册只删除一次最终变更后缀，再统一插入最终存活行。万张相册移出前 200 张时，源相册重插入量由 1,979,900 行降至 9,800 行；这是操作量推导。保留逐作品 before/after 回执、全局插入顺序、后续 rowid 相对排序、稀疏与负位置的 no-op、坏引用提前拒绝、逆序撤销 / skip、修订冲突、取消及原子回滚。数值 rowid 不承诺相同，仓库无此消费者。脏相册保留至事务结束，可能超过 32 相册 / 8 MiB 软阈值；线性成员计算和完整回执仍有成本。
内部生成文件入库已打开的内部文件句柄通过一次入库请求交给后台线程，连续写入后一次 sync_all；省去每 MiB 的 SQLite 往返、完整任务解码、文件重开及刷写。首次写入 100 MiB 文件的暂存刷写由 100 次降为 1 次，不含数据库和发布目录同步。沿用 Pending、单写入许可、任务 / 工作区身份、GC 保护、取消和 Close 等待；仍保留原源摘要、暂存及最终对象完整摘要校验。恢复时核对已写前缀，不一致则从源重写，最终对象未验证前不提交。源文件保留，物理 I/O 失败仍报错；外部 HTTP chunk 协议与内存字节路径保留。
普通语音完整句缓存POST /api/tts 在入队前及排队后复查完整 WAV；同配置、同台词命中时直接复用，省去整次合成。Legacy GET 在释放队列前写入缓存，覆盖排队 POST 的复用窗口。延续 60 项 / 128 MiB 上限，同 key 替换正确扣除旧字节数。只保留完整上游 EOF、格式合格、未取消的 WAV；PCM 明确格式并按真实 data chunk 回放，保留采样头检查。首片转发、断连取消及 180 秒 deadline 保留。普通 POST 超限只停止捕获、继续转发。证明上游音频完整，不证明客户端播放完成；首次未命中无缓存收益。
角色立绘派生无 alpha 图片跳过透明检测，RGBA8 直接借用像素；避免 3,200 万像素上限下约 128 MB 的额外 RGBA 临时分配。边长不超过 560 的图片直接复用已编码 portrait PNG，省去整图克隆及第二次 PNG 编码。其他 alpha 格式保留原 RGBA8 转换；尺寸 / 分配限制、方向、粒子计算、取消、修订摘要与大图缩放算法保留。128 MB 为缓冲大小推导，未测实际 RSS。
