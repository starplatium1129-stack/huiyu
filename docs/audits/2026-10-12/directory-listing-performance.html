目录列表调度优化

基于 PR #74 的 86f9421cf2b20b42ffdd64750231a0ecc1ae7387，独立分支 perf/backend-scan-20261012-pr74。本轮只改桌面工具 list_files 的目录读取调度及关闭时的工作跟踪；没有改 UI、任务列表、回收站、Live2D、图像正文读取、resize 或 PNG 编码。没有编写或运行任何测试、断言、行为验证脚本或夹具。

明确的热点与改动

基线通过 Tokio 分批枚举目录，随后对首屏最多 200 个非目录项分别等待 tokio::fs::symlink_metadata，造成多次阻塞池投递 / 唤醒；ICU 部分选择与排序仍占异步请求线程。大模型 / 素材 / 源码目录中，文件数量和首屏非目录比例会放大开销。本轮将同一请求的枚举、ICU 部分选择、排序与所选 metadata 检查集中到一个阻塞 worker；不省略文件系统检查，也不跨请求缓存状态。

每个 DesktopToolsService 的目录 worker 上限为 4，超出并发的请求等许可；关闭后等待者被取消。请求拥有 shutdown 子令牌和 drop guard；HTTP 被丢弃时令牌取消，worker 在枚举与逐项 metadata 检查之间退出。worker 持有许可和 TaskTracker token，实际工作退出前不提前释放；登记与 close 共用互斥门，避免 close 漏掉迟到登记。进程回收和目录工作等待并行启动，目录退出等待不会推迟命令进程的取消。

真实普通 API 观测

云环境 Linux x86_64、Intel Xeon Platinum 8573C、5 个可见 CPU；Rust 1.99.0，两个版本均为相同配置的 debug 构建。正常 POST /api/desktop-tools 请求 name=list_files，只读云工作区已有文件，不访问用户电脑、不读图像正文或凭据。没有 strace、并发负载或输出正确性比较。编译结束后，每目录每版本 20 次交错请求；大目录以基线 / 候选交替，小目录交换顺序为候选 / 基线。各组首个观测单列，重复中位数取其余 19 次；OS 缓存已暖且未清理，不称为磁盘冷启动。

语义与所有权源码审查

范围源码结论
路径与类型原 paths::resolve 的相对路径、父穿越、canonicalize 与工作区包含判断不变。原文件类型读取改用同一 std::fs::DirEntry 实现；逐所选文件仍以目录拼接同一 lossy 名字执行 symlink_metadata，不改用追随 symlink 的 metadata，不从跨请求缓存获得字节数。
顺序与字段仍目录优先，使用同一 system locale / ICU comparator；枚举索引仍是同分稳定次序。select_nth_unstable_by(200)、截断后排序、目录末尾斜杠、文件大小及 metadata 失败时省略大小、空目录文案、总数与输出字段均沿用原代码。没有输出匹配测试或行为验收。
取消与关闭等待许可可取消；close 与新 token 登记在同一锁下，锁不跨 await。队列中的 blocking task 启动后先查取消；运行中的任务在每个枚举项 / metadata 前检查。已取消 HTTP 的 token / 许可由真实 worker 持有至退出。新四 worker 限制会给高并发读取增加等待，避免无界占用阻塞池；并发 / 取消场景仅源码审查。
固有限制一次 OS 文件调用及一次 ICU 选择 / 排序不能安全中断，关闭需等其返回。目录集合仍全量保存，内存仍随目录项数增长，未新增逐项流式 top-200 堆。路径解析仍走原 Tokio I/O，目录变更与路径替换的原时间窗口未宣称修复。
