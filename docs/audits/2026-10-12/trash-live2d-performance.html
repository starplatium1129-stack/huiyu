实际改动

范围改动保留的契约
桌面回收站listTrash() 请求 deletedOnly=true，SQL 直接筛选 deleted_at IS NOT NULL。新增与活跃索引对称的 artworks_deleted_id，v3 打开及旧备份恢复后按原入口补建。旧 includeDeleted=true 仍读全量；新增参数只接受 true / false，为 true 时优先。完整 body、ID、revision、deletedAt、每页上限 200、id_key / limit+1 游标、workspace revision / artworkRevision、取消和 TrashEntry 原映射保持不变；不改读 trash.snapshot。前后端须一并交付。
Live2D 健康探测健康 worker 改用布尔可用性扫描，首个完整可用模型后停止，不构建完整 catalog JSON。提取原内置模型检查供两个入口共用，导入模型继续调用原完整检查。内置清单格式、每个依赖文件与目录边界检查不变；导入根 no_links、身份、receipt、完整文件与依赖清单及 disabled 判断不变。没有可用模型时遍历全部候选。完整 catalog 与实际资源访问仍走原检查；4 秒 TTL、60 秒期限、工作许可、取消、refreshing 去重、revision 失效及 shutdown 等待不变。

真实性能观测

云环境 Linux x86_64、Intel Xeon Platinum 8573C，5 个可见 CPU；Rust 1.99.0，cargo build --locked debug 构建。实际数据为仓库两套内置模型 nene / natsume、零导入模型，没有创建或修改模型夹具。正常网关 /api/health 每 5 秒请求一次，共基线首组 4 轮、完成编译后基线控制组 4 轮、候选 4 轮。只采集时刻、HTTP 耗时和文件系统调用，不核对返回值或设置通过条件。
