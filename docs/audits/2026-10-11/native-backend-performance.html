完整 API 测量中，Worker 自身中位数 6.106 秒、指纹检查约 2.6 毫秒，24 次调度器更新全部执行；每个任务实际跳过 22/48 个 CFG 分支计算，即 616 个 block。原始峰值为 PyTorch 已分配约 9.37 GiB，不代表设备总显存。

不同计时边界不能混作同一指标。Native 使用 Torch 2.8.0+cu128、Diffusers 0.41.0、SageAttention 2.2.0 Windows cu128/torch2.8 维护者版本和 Triton 3.4.0.post21；ComfyUI 0.39.0 使用 Torch 2.13+cu130 与其现有 Sage 2.2 环境。模型来自同一源权重，但 RNG（CUDA/CPU）、噪声和 sigma 离散化不同；同名 Euler/simple 不证明数学等价。Tea 阈值 0.15 与 0.08 也不能直接比较强弱。

这是热驻留、重复提示词的小样本结论。直接 Worker 首次请求实测 15.48 / 17.11 秒，已有磁盘编译缓存，不能当作新机首次编译耗时。新形状或 LoRA 强度/组变化可能重新编译；超出 Torch 编译次数预算可回落 eager，仍正确但可能变慢。

本次解决的瓶颈

  1. 权重校验。Windows CNG 完整 SHA256 保持摘要一致；1.993 GB 实际权重分片的 ABBA 测量从 hashlib 中位 4.125 秒降至 1.280 秒。驻留时，以禁止所选权重写入/删除的文件句柄、NTFS 文件 ID 和持续目录通知保护已有摘要，热任务不再扫描数 GB。临时改动后恢复原状也会失效；保护不可用时仍完整哈希。
  2. Transformer 执行。真实 CUDA 分析显示矩阵乘法约占 53.6%、attention 约占 21%。只为 Cosmos 启用 Sage，省去 repeat factor=1 的 K/V 拷贝，并编译原 block.forward。保留原始 PEFT 投影和强度，不融合基座或 LoRA；conditioner 和 VAE 保持原路径。
  3. Tea 校准。复用现有 polynomial 策略，在本机训练轨迹拟合，再用独立提示词/seed 留出评估。首尾步全算、连续最多跳一次；24 步不变。已安装的档仅覆盖 compiled-sage、832×1216、24 步、CFG 4、无 LoRA。
  4. 真实集成修复。首轮完整 API 测到 7.688 秒，发现 Rust 的 \\?\E:\... 路径被误判为网络路径，触发逐任务全量哈希。新增真实 Windows 回归后修复，完整 API 中位数降至 6.280 秒；UNC、Volume GUID 和设备路径继续不使用身份缓存。

身份租约还修复了两处实际验证发现的问题：目录保护曾阻止原子 PNG 保存；临时增删文件可能绕过仅比较最终清单的检查。现在目录允许子项写入而仍禁止目录删除/改名，并保留不重置的成员和属性事件；加载后的事件即使摘要相同也拒绝接受。

未采用的实验：VAE 编译增加约 41 秒首次开销且输出偏差明显；CUDA graph 先遇 Windows 启动问题，修正实验后仍出现巨大数值误差；cuBLASLt 与交叉注意力 K/V 额外缓存收益不足。产品代码未启用这些路径。

画质与现有 LoRA

原本机图片是 832×1216 的同 seed 留出对照。左为相同 compiled-sage 执行模式的完整计算，右为 Tea 候选。两例的主体和绘画风格保留，局部清晰；木屋形态、灯光和装饰有所改变，按本次标准接受。PSNR 为 18.98 / 18.61 dB，仅描述像素差异，不是语义画质评分。

两个原有 Kohya Anima 角色 LoRA 在 compiled-sage 下实际生成：宁宁强度 0.8 → 0.4、换夏目 0.8、卸载恢复基座。相同请求重复出图像素一致，卸载后基座像素恢复一致，强度切换确实改变像素。图生图与手绘蒙版同时完成验证，黑色保护区域像素保持、白色编辑区域改变。共 9 个真实任务，原始 LoRA 文件未修改。

LoRA + Tea 的组合尚未单独校准验收。上述 LoRA 功能检查关闭 Tea；不能把无 LoRA 的速度优势推广给全部角色。未知 Kohya 格式、DoRA 与不支持的权重形状仍明确拒绝；已测的两份权重不能代表整个 LoRA 生态。
