已排除或撤回的候选

  • SQL instr 预筛选在真实 Storage 样本中没有提速，已撤回。
  • 直接给所有查询套三字符索引会使常见查询退化。保留先检查最新 32 条的路径，并强制用已有排序索引避免把全部正文送进临时排序；候选覆盖超过一半记录时继续原扫描。短查询用字符存在候选，所有情况都保留最终精确检查。
  • 同步建完子串索引才响应会提高首次等待，已改为先响应、再后台预热；阶段性同步版本的暖读收益不能代替终版首读测量。
  • 目录冷读的额外数据库重开及整段正文标签哈希有额外成本，已改为领导请求复用首次快照、标签绑定原缓存权威键和编码器代次。只有等待中的冷随从重开权威；媒体/远程内容的完整性哈希没有省略。
  • 目录混合类型新排序索引没有实测收益，不增加该索引。授权/撤销逐字节校验、可靠落盘及未来未知 GPU 负载不作为省略检查的理由。

子串候选使用现有 SQLite 的 FTS5 trigram，大小写敏感且不移除重音，仅索引三字符候选，最终用既有 Rust 子串规则确认；没有引入新依赖或把词项匹配替换成产品搜索语义。
