# 后端可靠性、任务生命周期与桌面宿主审计

审计日期：2026-09-20。代码基线：`main` 的 `39d955e`。本报告覆盖 Node 网关、生成/视频任务、结果生命周期、进程监管与桌面健康检查；没有修改生产实现或进行安装、模型推理、设备操作。访问授权与隐私问题见 [安全审计](security-privacy.md)，不在这里重复计数。

## 方法与已有基础

先阅读当前仓库执行边界、工程契约与工作流，再跟踪路由到服务、上游请求、任务状态、结果文件和关闭路径。隔离验证使用现有网关夹具、临时目录、动态端口、模拟 SD/ComfyUI 与注入的 ffmpeg 替身，所有结果均为中性哨兵。主会话独立重跑同一脚本，结果一致。

当前可靠性基础较好：`SerialQueue` 有真实在途上限、FIFO、失败隔离和排队取消；HTTP 客户端有响应大小、超时、Abort 与回环连接复用；Anima 有固定工作流、任务所有权、提交不确定性处理、原子结果落盘、磁盘错误映射；维护事务有读取屏障和恢复入口；日志有保留期、单日体积限制和脱敏导出；桌面存在网关协议校验、端口冲突回退和退避重试。这些防护在各引擎间尚未完全一致。

证据等级 A：行为已在隔离夹具复现且独立重跑；B：代码级事实；C：推断的用户影响需设备或故障注入确认。本轮没有确认 P0；下列问题没有通过修改代码消除。

## BE-01：WebUI 分支的任务准入与状态不一致

**证据。** [server/generation/constants.ts:4](../../../server/generation/constants.ts#L4) 声明 `MAX_PENDING=4`；[server/generation/service.ts:36](../../../server/generation/service.ts#L36) 的状态仅报告 `comfy.status().pending`。同一服务在 [service.ts:83](../../../server/generation/service.ts#L83)、[service.ts:112](../../../server/generation/service.ts#L112)、[service.ts:117](../../../server/generation/service.ts#L117) 直接创建 WebUI 任务，[server/generation/webui.ts:166](../../../server/generation/webui.ts#L166) 立即发起上游请求，未经过有界队列或共享在途计数。

隔离夹具将模拟 SD 的生成响应延后 800 ms，远程同 token 同时提交 6 个普通请求。6 个均返回 202、模拟上游收到 6 次 `txt2img`；同时状态返回 `maxPending:4, pending:0`。模拟上游并不执行模型，该复现只证明网关准入与状态行为。

**影响与现有保护。** 路由 token bucket 仍生效，HTTP 连接池也有限制；它们限制速率/连接，不限制业务任务总数。慢上游期间任务仍可持续积累。本机免速率限制，误触发重复提交同样受影响。不能据此宣称已经发生 GPU OOM，具体上游还可能自行串行处理，但网关的四任务承诺没有被执行。

**落实步骤。**

1. 建立 WAI 所有提供方共用的准入器，在探测和创建任务前原子占槽；记录排队、提交中、运行中、取消中，终态释放，失败/断线必须恰好释放一次。
2. WebUI 分支改用有界队列与可取消请求；不要只在返回状态里补计数。确认 WebUI 全局 `interrupt` 只作用于当前实际执行任务，取消排队任务只出队。
3. 状态分别返回 WebUI/Comfy 活跃与排队，并提供聚合值；前端排队文案按相同定义使用，保留既有字段兼容期。
4. 复用慢响应、失败、取消、服务关闭、提供方切换夹具。并发提交超过上限时断言明确的 429/503、上游调用数不超预算、结束后计数归零；同时验证准入失败不会留下幽灵任务。

**验收。** 第五个在途任务不会越过四任务边界；状态与实际任务一致；队列中取消不干扰正在运行的其他任务；上游恢复后可继续生成。定向运行生成路由、serial queue、HTTP client 与网关契约，按后端跨域改动要求补相应门禁。

**回滚。** 用提供方功能开关将流量收敛到已验证分支，或暂时限制 WebUI 并发为 1；保留明确错误。不要通过恢复无限准入掩盖兼容问题，也不清除已经完成的作品。

## BE-02：服务器发送结束不等于浏览器持久化完成

**证据。** [routes/generation.ts:59](../../../routes/generation.ts#L59) 的 Buffer 分支 `res.end()` 后立即 `consume()`；文件分支在 [routes/generation.ts:69](../../../routes/generation.ts#L69) 的 `finish` 事件消费。消费函数位于 [server/generation/service.ts:168](../../../server/generation/service.ts#L168) 与 [service.ts:176](../../../server/generation/service.ts#L176)。该结果路由还未设置与其他私有结果一致的 `Cache-Control:no-store`。

同一夹具完成一个中性 70 字节 PNG 响应后，以相同身份连续取图：第一次 200，第二次 404，首响应没有 Cache-Control。客户端收到响应后解析、生成 Blob、写 IndexedDB 或写文件失败，不会恢复服务端已消费的结果。相比之下，[routes/anima.ts:138](../../../routes/anima.ts#L138) 已明确允许 TTL 内重读。

**落实步骤。**

1. 统一 Anima/WAI 的取图契约：GET 不产生销毁副作用，结果在有界 TTL/总字节预算内允许所有者重读；响应标明 `no-store`，不要依赖浏览器缓存补偿已删除结果。
2. 如要提前回收，增加幂等 ACK：客户端成功持久化后确认，服务端仅在 ACK 或到期后回收。ACK 丢失可以重试，不能把 HTTP `finish` 当成 ACK。
3. 对大结果优先使用受控磁盘文件与原子落盘，避免为了可重读而无限保留内存 Buffer；统一资源归属、TTL、磁盘满和容量驱逐错误码。
4. 补齐“HTTP 已返回但客户端保存失败”“下载中断后重试”“重复 ACK”“TTL 到期”“无权身份读结果”的行为测试。至少验证 WebUI 与 Comfy 两条 WAI 路径。

**验收。** TTL 内第二次下载仍为同一哈希和内容；保存失败后可重试且不重复生成；跨身份不能读取；到期/ACK 后资源确实回收；响应始终 no-store。浏览器持久化故障夹具应验证用户可以恢复作品。

**回滚。** 保留旧 GET URL 和返回类型；新 ACK 失败时退回 TTL 回收，而不是退回读取即销毁。不要在回滚时删除尚未确认保存的结果目录。

## BE-03：视频拼接需要在途去重、容量与取消

**证据。** [routes/video/batch.ts:317](../../../routes/video/batch.ts#L317) 只在拼接完成后用 `batch.concat` 去重；完成前每次请求都会写同一个列表文件和 MP4 目标。[routes/video.ts:270](../../../routes/video.ts#L270) 未挂提交用的限流器；[batch.ts:36](../../../routes/video/batch.ts#L36) 的默认 `execFile` 只有输出上限，无总时限、Abort 或登记的子进程句柄；[batch.ts:355](../../../routes/video/batch.ts#L355) 关闭时只清批次记录。

隔离服务用两个已成功的中性镜头记录，同时调用同一批次 `concat()` 两次，注入的 ffmpeg 替身被调用两次，目标路径相同。没有启动真正 ffmpeg、没有做 CPU/GPU 压测。数据竞争和残留子进程属于代码支持的风险，具体文件损坏/残留进程未在真实设备复现。

**落实步骤。**

1. 在开始任何 I/O 前按 batch ID 记录拼接中的 Promise/操作 ID；同批请求返回同一操作，避免只用完成结果做去重。
2. 配置独立、有界的转码队列；远程拼接和分镜重试同样进入明确预算，但不要将速率限制当成并发锁。
3. 每次操作用唯一临时列表/输出路径，成功核验后原子发布；失败只移除本次临时文件，保留此前可用结果。
4. 接入项目现有受控子进程执行器，添加合理总超时、取消信号、进程树清理与服务关闭等待。首次带音轨失败后的无音轨重试也必须共用同一预算与取消状态。
5. 用延迟替身验证 20 个同批并发请求只启动一次；跨批超过转码并发数排队；超时、取消、关闭后没有未结 Promise 或临时文件。真实 ffmpeg 验收另用中性短片完成。

**验收。** 同批拼接恰好一次，最终文件有完整哈希；重复请求和重试不会互删列表；关闭能回收自己启动的转码进程，其他应用 ffmpeg 不受影响。

**回滚。** 可以暂时禁用远程拼接或限为单个本机操作；保留分镜结果供重试。不可用全局按进程名终止的方法清理。

## BE-04：桌面不健康重启没有先处理旧自有进程

**证据。** [main.rs:44](../../../desktop-tauri/src-tauri/src/main.rs#L44) 连续健康失败后，在 [main.rs:60](../../../desktop-tauri/src-tauri/src/main.rs#L60) 调用 `supervisor.start()`。[gateway.rs:202](../../../desktop-tauri/src-tauri/src/gateway.rs#L202) 在原端口仍被占用时寻找其他端口；成功后 [gateway.rs:262](../../../desktop-tauri/src-tauri/src/gateway.rs#L262) 直接替换 `self.child`。该路径没有先取出、停止并等待已有自有 Child；正常 stop/drop 的清理代码只保留了最后一个句柄。

**触发与影响。** 原进程仍存活、监听仍在，但连续未在健康期限内给出合格响应；新进程成功启动时可能失去旧进程的管理句柄。多个进程随后可能共用同一 runtime。Anima/视频服务的启动/关闭有输出目录清理，因此双进程问题还可能影响结果文件。这里是静态高置信路径分析，未运行安装版的卡死/重启实测，不声称已经观测到遗留进程或作品删除。

**落实步骤。**

1. 区分 `ensure_started` 与 `restart_owned`，避免一个 start 方法同时承担附着和重启。显式记录自有 PID、实例 ID、端口和生命周期状态。
2. 健康失败后，若为自有进程，先阻止重复重启，取出旧 Child，尝试有界优雅关闭，超时再终止并 wait；旧实例收敛前不复用同一 runtime 启动新实例。
3. 若为附着的外部兼容网关，只报告失联或按明确策略重新发现，不杀外部进程。换端口时原子发布新 URL，三类窗口都等待新实例就绪。
4. 给监管器注入探测/进程接口，覆盖“存活但不健康”“已退出”“端口被无关进程占用”“重启过程中退出应用”“连续两次重启”序列。
5. 在 Windows 临时 profile 和中性网关中进行故障注入，记录 PID 树、监听端口、runtime 写入者与停止时间，不使用操作员当前实例。

**验收。** 每个桌面实例始终最多持有一个自有网关；旧 PID 与句柄被回收，新窗口连新端口，附着外部进程保持不动；退出无自有后台残留。依赖/exe 变化按仓库唯一桌面部署入口发布，并保留实际设备验收记录。

**回滚。** 若自动恢复不稳定，可临时禁用自动重启并展示可操作的恢复错误；不要保留反复生成新子进程的恢复方式。回滚安装包不删除用户运行目录。

## BE-05：健康探测只限制单次读取等待

**观察。** [gateway.rs:20](../../../desktop-tauri/src-tauri/src/gateway.rs#L20) 用同步 TCP 请求实现健康检查；设置 socket 读写超时后，[gateway.rs:34](../../../desktop-tauri/src-tauri/src/gateway.rs#L34) `read_to_end` 到 EOF，未设置响应大小上限或整个请求绝对 deadline。返回健康 JSON 的真实网关通常很小；但一个持续分段输出、始终不结束的本机服务可能使外层启动总时限来不及得到控制，或让累计内存增长。该影响未在本轮原生运行时测试。

**落实步骤。**

1. 使用受支持 HTTP 客户端或实现受限读取，限制连接、响应头、响应体与整个请求总时限；健康体可设较小上限，如 16 KiB，并处理 Content-Length/chunked/错误状态。
2. 避免在异步监管循环直接执行可能长时间阻塞的 I/O；保证关闭与启动取消可以打断健康请求。
3. 用回环夹具覆盖持续滴流、超大响应、不闭合连接、半响应、坏 JSON、正常健康响应；对每个测试断言耗时上界与响应字节上界。

**验收。** 在总时限内返回明确不健康结果、内存占用有界，正常服务和端口回退不退化。

**回滚。** 可恢复上一版健康解析器，但保留总 deadline 与字节上限；健康失败只触发受控恢复，不扩大为反复重启。

## 跨模块优化与实施顺序

1. **先修准入与结果可靠性（BE-01/02）。** 这两项已有确定的用户行为复现，分别提交，避免将“加队列”和“结果 ACK”揉成一次大重构。共用任务类型，但保留各引擎能力差异。
2. **再统一进程生命周期（BE-03/04）。** 将 ffmpeg 和桌面监管纳入明确的拥有者/取消/退出契约；新增测试验证行为，不仅匹配代码字符串。
3. **补强健康、指标与恢复证据（BE-05）。** 记录各引擎准入拒绝数、活动/排队数量、取消耗时、结果 TTL/容量回收、恢复次数和上次成功时间。指标使用匿名任务 ID，不记录完整提示词、图片、API key。
4. **推进持久任务与作品恢复。** 当前 [server/job-snapshot.ts](../../../server/job-snapshot.ts) 只保存精简恢复线索，视频重启以 lost 状态通知；Anima/视频输出会在生命周期清理。应复用已有持久化原型，先做到重启后识别状态与保留已完成结果，再考虑恢复上游任务，避免未知提交被自动重复执行。该项是明确的架构增强，不在本报告额外计为新漏洞。

每一步都应记录：受影响提供方、迁移前后接口行为、隔离测试、真实设备补证、退回方式。报告交付不等于这些实现已获测试通过。
