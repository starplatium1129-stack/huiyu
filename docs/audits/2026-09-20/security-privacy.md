# 安全、隐私与访问边界审计

审计日期：2026-09-20。代码基线：`main` 的 `39d955e`；结论针对该版本。本文只提出修复方案，没有修改生产代码、开放隧道、调用真实模型、读取操作员秘密或执行桌面安装。

## 范围与方法

审查网关中间件顺序、Host/Origin/token、远程内容分级、静态/预压资源、聊天上游访问、桌面工具、Tauri IPC 授权及凭据持久化。依据当前 [AGENTS.md](../../../AGENTS.md)、[工程契约](../../engineering-contracts.md) 和 [工作流](../../workflow.md)，历史审计只用于定位模块。

代码路径以 TypeScript/Rust 为准；HTTP 复现使用当前编译的 JavaScript、仓库现有 `gateway-test-stack`、系统临时目录、动态回环端口与模拟上游。没有请求正在运行的生产网关。首轮自定义夹具因样张目录与运行目录重叠被维护边界拒绝；调整为隔离的合法目录后完整复现成功，这不是生产故障。

证据等级：**A** 为隔离行为复现且主会话独立重跑；**B** 为代码级确定事实，完整用户场景未运行；**C** 为需要实际部署补证的风险推断。P0–P3 是修复优先级，不是 CVSS 分数。没有发现可据此确认的 P0；也没有证明无 token 的互联网请求能够越权访问。

## 已有有效防护

- [server.ts:72](../../../server.ts#L72) 在静态资源之前安装 Host 与 token 门控；[server/security.ts:23](../../../server/security.ts#L23) 同时检查回环地址、转发头和浏览器来源，防止仅凭 `127.0.0.1` 来源就把隧道当本机。
- [server/sd-proxy-policy.ts:15](../../../server/sd-proxy-policy.ts#L15) 将原生 SD 写接口与双向升级限制为本机；应用生成使用固定工作流、参数白名单、任务所有者检查，不向浏览器直接开放 ComfyUI 工作流提交接口。
- 远程用户自配聊天 API 经 [services/public-upstream.ts:32](../../../services/public-upstream.ts#L32) 校验公网 HTTPS 与解析结果；[services/http-client.ts:225](../../../services/http-client.ts#L225) 将已核验地址用于连接，降低 DNS 解析后重新绑定风险。
- 桌面通用命令要求操作员环境 `AICS_DESKTOP_COMMANDS=trusted`；默认文件工具使用 [server/workspace-path.ts:31](../../../server/workspace-path.ts#L31) 校验实际路径。该模式明确为系统账户权限，不伪称工作区沙箱。
- 站主配置 GET 不回传 API key；服务端配置以临时文件、`fsync`、重命名保存。诊断导出已有 token、Bearer、URL 用户信息和敏感字段脱敏。桌面更新配置了固定端点与签名公钥。

上述为代码审查结果。全量套件执行状态以本轮总报告为准，不能将防护存在理解为所有攻击面均已验证。

## SEC-01：视频批量请求绕过远程分级校验

**问题与影响。** 单任务 [routes/video.ts:147](../../../routes/video.ts#L147) 传入 `isLocal: security.isDirectLocalRequest(req)`。批量入口 [routes/video.ts:220](../../../routes/video.ts#L220) 只传请求体与配置；[routes/video/validation.ts:402](../../../routes/video/validation.ts#L402) 又不带来源上下文调用单任务校验，而 [routes/video/validation.ts:80](../../../routes/video/validation.ts#L80) 将缺省上下文解释为本机。因此批量请求中的 `adultEnabled:true` 足以进入本应由传输层拒绝的分支。

**复现证据。** 在 `AICS_ADULT_REMOTE=0`、有效 token、`x-forwarded-for:198.51.100.8` 的同一身份下，以单词 `nsfw` 作为纯校验标记，不生成图像或视频：

```json
{"modelId":"wan2.2-ti2v-5b","adultEnabled":true,"aspectRatio":"landscape","shots":[{"prompt":"nsfw"}]}
```

单任务对应输入返回 `403 / ADULT_REMOTE_NOT_ALLOWED`；上述批量输入返回 `202`，注入的中性 batch 替身接收到一次提交。真实视频服务没有被调用。真实模型是否安装决定后续能否生成，不影响路由授权上下文已丢失的结论。

**落实步骤。**

1. 为单任务、批量、重试统一定义不可由 JSON 覆盖的 `RequestAccessContext`，从实际请求生成；将缺省、未知上下文改为远程/拒绝。优先堵住 `/api/video/batches`，不要先扩大重构范围。
2. `validateBatchInput` 接收并逐镜传递上下文；内部重放显式传服务器已核验的权限状态。移除“没有参数就视为本机”的隐式约定。
3. 批次仅保存服务端认可的权限，防止重试时重新信任最初请求体。同步核对单任务/批量/重试与本机 UI 的分级契约；历史环境兼容开关不得替代用户当前要求的本机边界。
4. 增加 HTTP 矩阵：本机、远程带 token、远程无 token、各种转发头、未知来源；对单任务、批量和重试分别验证。使用中性 marker 与服务替身，不调用真实模型。

**验收。** 未授权远程批量与单任务返回同一拒绝码，batch 替身调用数为 0；普通内容与本机合法请求仍正常。运行视频与网关相关契约、类型检查；若后续确实修改提示词/编译或生成行为，再按仓库红线单独取得真实画面证据。本次审计不声称已完成这些修复验收。

**回滚。** 回退故障实现时可暂时将批量视频入口限制为本机；不能回退到缺省本机的授权判断。保留现有请求格式和批次数据，避免为修复权限删除作品。

## SEC-02：私有候选目录拒绝发生在预压响应之后

**问题与影响。** [server.ts:91](../../../server.ts#L91) 先挂载预压中间件，私有候选目录拒绝位于 [server.ts:204](../../../server.ts#L204)。[server/precompressed.ts:37](../../../server/precompressed.ts#L37) 允许 `assets` 下文本类型，只对 `data` 应用文件白名单；若候选模型目录带有可用压缩兄弟文件，请求可在抵达目录拒绝前返回。

**复现证据。** 临时目录仅放 `assets/live2d-candidates/fixture/model.json` 与对应 `.br`，内容为中性哨兵 `{"neutralPrivateFixture":true}`。同一远程已授权请求：`Accept-Encoding:identity` 返回 404，`Accept-Encoding:br` 返回 200 和哨兵。没有访问真实候选模型。

**边界。** [scripts/maintenance/precompress.ts:32](../../../scripts/maintenance/precompress.ts#L32) 默认只处理 `dist` 与 `data`，所以这不是每次常规构建都会自动产生的泄露。需要候选源带压缩文件或其他维护流程生成它们；本轮未核查操作员私有素材内是否存在该条件。token/Host 门控仍然生效。该缺陷违反的是“候选原件不进入静态资产路由”的目录隔离，不是匿名访问漏洞。

**落实步骤。**

1. 在所有静态处理器之前集中拒绝私有资产命名空间，确保普通、预压、安装资源投影共用规则。
2. 将共享策略做为纯函数传给预压处理器；统一解码、大小写及路径分隔处理，避免复制另一份易漂移的正则。
3. 以 `.json/.txt/.svg` 与 identity/br/gzip、HEAD、编码路径组成小型矩阵；同时验证公开模型与正常预压资产仍可读取。
4. 打包检查维持候选资源排除，不将“安装包不含私有资源”当成源码网关访问策略的替代品。

**验收。** 所有私有候选路径稳定返回 404，不返回压缩哨兵；正常资源协商压缩与 ETag 回归通过。

**回滚。** 共享策略若产生误拒绝，可暂时关闭候选相邻目录的预压服务；保持私有目录拒绝位于静态服务之前，不以重新开放目录恢复性能。

## SEC-03：远程发布资源缺少分级投影

**问题与影响。** [server/public-data.ts:13](../../../server/public-data.ts#L13) 允许完整场景、热门角色与蓝图 JSON；[server.ts:235](../../../server.ts#L235) 按文件白名单直接发送，未按请求身份过滤记录。[server.ts:216](../../../server.ts#L216) 的参考图目录和 [server.ts:253](../../../server.ts#L253) 的样张路径规则检查来源与路径，但没有关联内容分级。前端筛选/模糊可以维持产品展示，却不能阻止已获通用资源权限的用户直接读取源数据或已知 URL。

**复现证据。** 临时 `scenes.json` 只含中性文本和 `mature:true`，远程带 token 读取返回 200 且保留该标志；中性 PNG 头组成的参考图、样张资源也返回 200。没有查看真实成人素材，也没有验证具体生产 URL 的分级映射。

**判定边界。** 这是当前“共享 token 可读取通用资源”能力与产品“远程本机分级边界”之间的缺口。既不是无 token 的公开互联网访问，也不等于本轮证明了某幅实际成人图片泄露。如果产品有意公开部分分级元数据，仍应在契约里明确元数据、提示词、原图各自的分享范围，避免把前端模糊当作原图授权。

**落实步骤。**

1. 明确远程可发内容的最小集合：公开元数据、SFW 提示词、缩略图、原图分别判定，未知分级拒绝。基于当前内容登记构造只读发布索引，不改动定稿源字段。
2. 在发送完整数据或压缩文件之前选择本机/远程投影；远程 JSON 移除受限内容和对应原图定位信息。该投影与预压内容必须一致，避免普通路径过滤而 `.br` 返回整库。
3. 图片由登记 ID 与分级决策映射到受控文件；参考图/样张未知映射 fail-closed。保留前端模糊与拒绝体验，作为第二层展示约束。
4. 对角色参考资源、样张原图/缩略图、HEAD、Range、304、br/gzip 和安装资源覆盖路线验证，防止缓存跨身份复用；按身份输出适当私有缓存策略。

**验收。** 远程拿不到受限记录和图片原始字节，本机完整库保持可用，公开内容依然正确缓存；双主题展示不因缺失数据出现破图或文案错位。此项需要后续浏览器与资产登记验收，当前夹具只证明服务端现状。

**回滚。** 使用可切换的服务端发布投影；出现误判时暂时限制受影响的远程媒体访问，保持本机资源可用。不能通过放开完整静态根回滚。

## SEC-04：桌面本机服务信任仍可进一步收窄

**观察。** [capabilities/default.json:7](../../../desktop-tauri/src-tauri/capabilities/default.json#L7) 授予 `http://127.0.0.1:*/*` 业务 IPC；[gateway.rs:56](../../../desktop-tauri/src-tauri/src/gateway.rs#L56) 只核对服务自报的 `ok/app/desktopProtocol`，随后 [gateway.rs:198](../../../desktop-tauri/src-tauri/src/gateway.rs#L198) 可附着该服务。窗口构造未见针对当前网关 origin 的导航限制。这些是代码事实；未证明存在从互联网到该 IPC 的完整利用链，同账户恶意进程也不是现有本机工具沙箱承诺的威胁边界。

**建议与落实。** 先给网关健康响应补充构建标识与启动实例身份；由桌面持有随机启动凭据，与自有网关握手。合法开发网关附着保留明确模式。再按实际选定端口注册 capability/命令来源校验，限制窗口导航到当前网关 origin；外部链接交系统浏览器。避免仅加另一段易伪造的固定 `app` 文本。

**验收。** 两个临时本机服务中只有受信实例可取得业务 IPC，其他端口/外部导航被拒绝；合法开发附着、端口回退、Live2D 与更新命令正常。需 Windows WebView2 实测，本轮未执行。

**回滚。** 保留经过明确选择的开发附着模式；校验失败时提示恢复或重启网关，不静默退回所有回环端口授权。

## SEC-05：个人 API key 与聊天资料一起明文持久化

**观察与影响。** [useChatStorage.ts:255](../../../src/composables/chat/useChatStorage.ts#L255) 将 `apiKey` 放入完整设置，[useChatStorage.ts:362](../../../src/composables/chat/useChatStorage.ts#L362) 写入 localStorage。服务端 [chat-host-config.ts:46](../../../server/chat-host-config.ts#L46) 使用原子文件与 `0600` 模式，但并未加密静态存储。前端同源脚本或浏览器资料副本可能读取个人密钥；这不证明存在 XSS、跨用户文件权限错误或实际密钥外泄，本轮也没有扫描真实凭据文件。

**建议与落实。** 桌面版将个人凭据迁入操作系统凭据库，网页端优先使用本机站主托管配置或仅会话保存；浏览器设置只保存引用/是否已配置。迁移采用“安全存储成功 → 读回验证 → 删除旧明文字段”，失败不销毁可用配置。诊断与聊天导出须明确排除凭据，提供独立清除操作。

**验收。** 新保存后浏览器持久化内容无 key；旧版本升级不丢配置且清除成功；GET/诊断/聊天备份不含中性测试密钥。Windows 凭据库不可用时有可恢复错误，不静默降级成明文。

**回滚。** 保留旧版本可识别的非秘密配置与迁移标记；不要自动将安全存储中的密钥重新写回 localStorage。
