# 全面审计落实计划

本计划针对 `39d955e` 的发现，执行状态均为 **待实施/待验收**。本轮已完成的是审计、证据与报告提交。各项详细根因和局部步骤在 [总览所列八份报告](README.md)；这里规定跨模块顺序、依赖和完成出口。

## 优先级与执行边界

P1 优先解决授权失真、潜在用户数据损失、任务资源失控和持续检查阻断；P2 改善可靠性、覆盖与可维护性；P3 为低风险体验/加固。内容资产的 P1 是发布出口要求，不意味着必须立即批量补齐所有形态。未确认 P0，不能据此作“项目无严重问题”的安全保证。

继续使用现有 Vue/Pinia、Express、IndexedDB、Tauri 和内容发布流程。每批单独审查 diff、保留明确回退边界；同一工作区只由一个会话做 Git 写操作，并行实现使用隔离工作区。每次受控提交后推送。无需先购买服务、升级全部依赖、迁移用户库或下载模型。

## A0：让检查与承诺一致

1. 从固定提交创建隔离工作区，保留锁文件与本次失败证据；确认 CRLF 仅是当前工作文件差异，规范化后不得产生业务内容差异。
2. 统一 E2E 无输出类型配置并给 Canvas mock 的 this 明确类型；检查所有类型子命令实际执行到结束。
3. 检查 ColorLightNotebook 的两个特殊断点，以合适的现有档位整理并双主题复验。
4. 修正样式扫描编排的唯一拥有者，使用故障夹具证明四项扫描均能阻断。现有测试只检查文件名出现的断言改为检验真实执行范围。
5. 为 74 份浏览器 spec 建立 lane 归属，优先包含本次修复及近期新增粒子/导航/图片恢复。对当前关键回归失败先核对产品意图与组件条件，禁止只删断言或整体 skip。
6. 定向检查通过后运行一次完整门禁与需要的浏览器集合，记录构建身份。若任何已有失败尚未处理，提交说明保留其状态。

验收清单：类型 7 个错误清零；UX 断点规则通过；四类样式违规均可使隔离门禁失败；测试无未归类文件；原阈值不变。回退按配置/样式/测试编排三个提交分别处理，保留失败可见性。

## A1–A3：先消除安全与数据损失条件

**A1 文件边界**：`routes/video.ts`、`routes/video/validation.ts`、`server.ts`、`server/precompressed.ts` 与对应路由/静态夹具。先给批量入口传服务器访问上下文并 fail-closed，再集中静态资源拒绝规则。用有/无 token、本机/转发、单任务/批量/重试、identity/br/gzip/HEAD 的中性矩阵验收。SEC-03 的发布投影单独设计，不能临时删除源记录或去掉本机能力。

**A2 文件边界**：`backupRestore.ts`、`backupSettings.ts`、`backupCore.ts`、artwork 解码器、聊天/偏好写协议及定向 UI 预览。先建立确定性竞争测试，再决定共同锁/修订方案；普通写者必须参与协议。合并仅改导入涉及的键，补偿不能回滚他人后写。预检应给出“可恢复/将隔离/缺原图”的准确数量；旧格式需要迁移测试。最后用两个真实同源浏览器页复验，再到 WebView2。

**A3 文件边界**：`server/generation/*`、`routes/generation.ts`、前端结果持久化适配器。准入占槽发生在提交前、终态只释放一次；取消排队任务不发送全局中断。结果 GET 在所有者授权和有界 TTL 内幂等，持久化 ACK 若采用必须可重试。测试断线、浏览器保存失败、磁盘满、过期与清理，不重复模型生成。

共用验收数据：中性小图、小型假任务和临时存储，不使用用户素材。修复本身不改 prompt/outfit/编译参数；若后续范围扩大到这些字段，才进入真实 Token 与出图验收。回退时可限制受影响远程入口/恢复入口/提供方，不能退回已确认的开放授权、无限准入或读取即销毁行为。

## A4–A5：可操作性与生命周期

1. 无图上传改原生按钮、事件提醒增加同级导航按钮；不要嵌套关闭按钮。验证 Tab/Enter/Space、Escape 和返回焦点，保存深浅主题 390/1440 截图。
2. 本机角色目录区分 in-flight、成功缓存、失败重试；保留合法空目录缓存和远程禁载。场景共享请求加入明确时间边界，保留代际隔离，不因单个消费者离开取消所有人的数据。
3. 逐条定性 companion 浏览器回归：旧设计断言应按明确的新行为更新；真正隐藏/无入口的操作修组件。不能用“桌面不同”一并豁免网页可访问性。
4. 同批拼接在 I/O 前登记在途操作，限制跨批并发，使用独占临时输出和原子发布。取消/关闭仅终止本操作启动的进程树。
5. 桌面监管拆出自有重启与外部附着；存活但不健康时先停旧实例并 wait，再启动新实例。健康读取同时限制总时限与字节数。
6. 任务摘要按 ID/修订合并并保留删除语义；保存补偿区分确定失败、提交未知、清理失败，不因异常就盲删或重发生成。

完成出口：键盘主流程成功；HTTP/结构错误恢复成功；20 个同批拼接仅一次实际调用；两个窗口摘要均保留、删除不复活；桌面自有 PID 不残留。最后一项必须有原生故障注入证据，静态 Rust 审查不够。

## A7–A9：测得收益后再做长期改造

性能先固定 source/build、设备、DPI、刷新率、数据量与冷热缓存，独占资源跑现有 performance 入口。新增页面 JS 并集指标先报告后设阈值，保留旧指标；不能直接扩大现有预算。后台缩略图与 KeepAlive 先测前台/后台、单窗/双窗、1k/10k 记录，再决定调度与去重复杂度。

恢复 journal、分块备份等复用既有原型和 STORE-01 的写协议。用阶段强杀验证完整旧状态、完整新状态或明确待恢复状态；大包测量不能直接读取用户生产库，也不能把升高 512 MiB 上限当方案。

同步 README/工程契约/工作流的描述，CONTENT-03 与 GOV-02 合成一个文档任务。退役旧审计自动写工作流时先核对使用情况。npm/Rust/SDK 的发行依赖清单和构建身份进入既有回执；每次漏洞命中按实际调用路径评估。凭据库与网关身份加固在临时 Windows profile 验证迁移失败与回退，再实施真实安装。

最终桌面仅使用 `deploy-desktop.bat`；依赖/exe 变化完整安装，UAC 由用户操作。办公机浏览器通过后，仍需主力机真实生图→入册→备份→新环境恢复、视频、ASR/TTS、Live2D、4K/150% DPI、多屏/休眠和资源成本验收。每个设备条件独立记录，不打包称“全功能已验收”。
