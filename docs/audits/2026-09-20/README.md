## 总体判断

项目已有可用的模块分层、任务/数据契约、资源候选发布与多层测试，适合在现有架构上分批修正。主要风险集中在不同入口未共享同一授权/准入/恢复规则，以及检查编排与实际覆盖之间的差异。大规模换框架、换存储或重做 UI 不是当前优先事项。

**当前基线不能认定为全量验收通过。** 这既包含本次检查明确失败，也包含已用隔离夹具复现而现有测试仍漏掉的问题。没有确认到必须立即停用整个本机项目的 P0；P1 应在相应功能的下一次交付前修复。这里的 P0/P1 不是 CVSS 评分，也不是“已发生事故”的断言。

优先处理：

1. **权限一致性**：远程视频单任务拒绝时，批量入口仍可接受同一分级标记；需让请求来源不可由请求体/默认值替代。私有目录的压缩响应与远程媒体分级投影另有条件性缺口。
2. **用户数据与成品保全**：合并恢复能覆盖其他窗口新聊天；无效作品 ID 能通过备份预检；WAI 成功结果首读即消费，不支持保存失败后的重取。
3. **任务与进程边界**：WebUI 分支 6 个并发请求全部进入上游，但状态仍报 pending=0、maxPending=4；拼接去重和桌面旧进程回收需补齐。
4. **持续检查可信度**：E2E 类型检查当前失败、样式扫描四项未真正接入 full/CI、多个浏览器用例不在自动清单。新增测试文件或历史通过不能弥补这些缺口。
5. **内容交付真实性**：一个参考服装正文的源/投影不一致；357 个热门服装缺参考登记、1,974 个条目 pending。非 pending、有 URL、结构检查通过均不代表实际图片完成。
