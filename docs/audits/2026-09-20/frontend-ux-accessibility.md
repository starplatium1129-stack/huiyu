# 前端交互、体验与无障碍审计

审计日期：2026-09-20。源码基线：`main@39d955e`。本报告为审计与实施建议，不表示问题已修复；本轮未修改 UI、主题、业务数据或生成参数。

## 范围与方法

覆盖路由与页面壳、主导航、焦点管理、弹窗、换装导入、桌宠提醒、深浅主题及相关浏览器测试的实现。先读取 `AGENTS.md`、工程契约与工作流，再以当前源码核对历史问题是否仍存在。使用 Vue SFC 编译器 AST 枚举带点击事件的非原生交互元素，逐条检查键盘替代入口；AST 枚举是筛选工具，不自动把装饰容器或事件代理判为缺陷。

本报告的“确认”指源码或当次隔离验证能够证明的行为；“风险”指存在触发条件但尚无当次实机后果；“待测”不计为失败。优先级中 P0 为数据/核心运行紧急阻断，P1 为关键功能对一类用户不可用，P2 为局部体验或回归防护缺口，P3 为低风险完善。本范围没有确认的 P0；不据此宣称全项目没有 P0。

主会话负责当次完整门禁、构建及浏览器核验，最终状态以本目录总报告为准。完整门禁已发现基线 TypeScript 和仓库卫生问题，本报告不将其他分项通过写为全量通过。

## 已有能力与应保留的设计

- 路由全部通过动态导入加载，未知地址有兜底页；主要页面共用 skip link、真实 `main` 地标与焦点落点。证据：`src/router/index.ts:59`、`src/components/AppLayout.vue:3`、`:8`。
- `useFocusTrap` 已支持顶层陷阱、嵌套弹层、Escape、焦点恢复、滚动锁及 KeepAlive 失活释放，不能再重复建议“全站新增焦点陷阱”。证据：`src/composables/useFocusTrap.ts:30`、`:104`、`:131`、`:168`。
- 键盘导航后已有内容焦点恢复，F6 可切换导航与主内容，且避免鼠标导航时抢焦点。证据：`src/composables/useDesktopInteraction.ts:83`、`:97`、`:125`。
- 动画取消、减少动态效果切换和路由失活有实际清理逻辑；离场页设置 `inert`。证据：`src/composables/useRouteTransition.ts:77`、`:109`、`:126`。
- 双主题、多视口、部分动态组件文字对比度已有浏览器回归；图片故障恢复已有独立测试。现有覆盖是基础，不等于每个业务状态或真实设备均通过。证据：`tests/e2e/ui-layout.spec.ts:5`、`:41`、`:120`，以及 `tests/e2e/resource-recovery.spec.ts`、`tests/e2e/image-fallback-visual.spec.ts`。

### UX-01：无图上传入口缺少键盘操作

**证据与触发**：`src/components/AnimaInpaintModal.vue:258` 的 `.dropzone-empty` 是只有 `@click="triggerUpload"` 的 `div`，没有 `tabindex`、键盘处理或原生按钮；`:174` 的真实文件输入在 `src/assets/css/anima-inpaint.css:190` 被 `display:none` 隐藏。有图分支在 `:246` 提供了原生“更换外部图片”按钮，空图分支没有同等入口。焦点陷阱已在组件 `:46` 启用，它会正确跳过这个非可聚焦元素，因此不能补救选图功能。`tests/e2e/ui-layout.spec.ts:120` 当前只检查这处弹窗的颜色、选项及关闭，没有键盘上传断言。

这属于键盘功能缺口；WCAG 2.2 SC 2.1.1 为 Level A，不能用文字 AA 对比度检查代替。[W3C 键盘可操作性说明](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)。

**当次浏览器证据**：2026-09-20 23:12（北京时间），复用主会话已构建产物与隔离端口 `25000`，以 Edge `153.0.4234.48` headless、全新非持久化 context、1440×960 视口、减少动态效果运行。深浅主题分别打开无图换装弹窗，均实际确认 `.dropzone-empty` 为可见 `DIV`、`role=null`、`tabIndex=-1`、`display:flex`；文件输入为 `display:none`。每种主题连续 30 次 Tab 均未到达上传区域或文件输入，焦点一直保持在弹窗内，Escape 正常关闭，页面运行错误为 0。没有点生成或调用真实模型，没有访问用户浏览器资料。

已分别读取两张当次弹窗截图，上传区与文字在两主题中可见；这只确认当前桌面空态外观，不构成完整 AA 数值检测或全站视觉通过。原始焦点链与截图位于本机忽略目录 `runtime/comprehensive-audit-2026-09-20/keyboard-evidence.json`、`keyboard-dark.png`、`keyboard-light.png`。对应构建 manifest SHA-256 为 `76b4a53622b8490137985395f684dc1a3713445a0ec3424529454d58e16204ea`。

**落实步骤**：

1. 将空态入口替换为 `button type="button"`，沿用原样式与上传函数；保留外层拖拽入口，并确认按钮中只有允许的非交互内容。
2. 为焦点状态补充现有令牌驱动的可见描边；检查深浅主题，不靠降低整块 opacity 表示状态。
3. 用现有 Playwright 打开全新无图工作台，进入换装弹窗，Tab 到上传入口，通过 Enter 与 Space 各触发一次文件选择事件。使用中性本地图片夹具进入预览，确认 Escape 关闭并回到触发按钮。
4. 复用图片恢复和 inpaint 弹窗相关回归，检查窄屏下按钮尺寸与文本换行。此修复不改变提示词、遮罩或模型调用，不需要为验证入口而真实出图。

**验收**：空态存在可访问名称明确的按钮；仅键盘可完成选图、看到预览、关闭；拖拽仍可用；双主题 390/1440 宽度可见焦点且无文字遮挡。当前浏览器核验复现了缺陷，没有执行修复后的上传验收。

**回滚**：回退组件与对应样式/定向测试的同一提交；不涉及数据迁移。若临时回退样式，应保留按钮语义，避免重新引入不可达入口。

### UX-02：桌宠提醒卡导航缺少键盘入口

**证据与触发**：`src/views/CompanionView.vue:157`、`:353` 两处提醒卡均以 `div @click="openReminderRoute(reminder)"` 承担操作。仅关闭按钮是原生按钮，导航区域没有键盘或链接语义。`src/composables/useCompanionBehaviorRuntime.ts:194` 证明该操作在 `kind=event`、有 `eventKind` 且存在 `desktopBridge` 时调用 `openAtelier(route)`。因此这是桌面事件提醒分支缺口，不能泛化为普通问候或浏览器模式都需要可点击。

**落实步骤**：

1. 在桌面事件提醒上增加明确的原生“查看结果/打开对应页面”按钮，复用现有 `openReminderRoute`，让关闭按钮成为同级控件；不要把包含关闭按钮的整个卡片变成嵌套按钮。
2. 普通问候保留文本语义，不提供无效导航控件。已知事件种类使用用户能理解的名称，避免所有入口都叫“打开”。
3. 在隔离浏览器中注入桌面桥及三种事件提醒，验证 Tab、Enter、关闭操作分别调用正确目标；导航和关闭各发生一次，普通问候不调用桥。
4. 补桌面实际焦点、透明窗口、穿透开关下的人工验收；浏览器模拟桥只证明前端事件归属。

**验收**：键盘可分别打开事件目标和关闭提醒；不会误触相邻提醒、重复开窗；普通问候和浏览器模式不出现无效按钮；双主题提醒文字与焦点可见。

**回滚**：回退提醒控件变更，保持事件检测、通知去重和路由映射原样；不改用户行为配置或通知历史。

### UX-03：路由标题缺少区分

**证据**：`index.html:11` 只有固定品牌标题；`src/router/index.ts:59` 的路由表没有标题元信息。本轮搜索 `src` 内的 `document.title`、`useTitle` 未发现页面标题同步实现。键盘内容聚焦已经存在，本项不应扩展成重新实现导航焦点系统。

**落实步骤**：

1. 在路由元信息或小型展示映射中维护稳定中文页面名，例如“作品册 · 绘遇”，未知页使用“页面未找到 · 绘遇”。
2. 在路由成功提交后更新 `document.title`；首次直达也应用。取消导航、异步失败和同页筛选不写入错误页面名。
3. 保持原生窗口标题与网页标题的职责分离；如果要同步原生窗口，需要单列目标窗口验收，避免顺带更改桌宠窗口行为。

**验收**：直达、站内切换、后退与 404 各有准确标题；取消切换保持当前页标题；不会将用户提示词、聊天或私有文件名写入标题。使用现有路由测试和浏览器标题断言即可。

**回滚**：撤回元信息与更新函数，恢复品牌标题，无数据影响。建议在前两项完成后作为小批次交付。

### UX-04：把未覆盖状态明确排入验收

这是已知验收边界，不是新发现的全站视觉失败。`tests/e2e/ui-layout.spec.ts:41` 的主矩阵重点断言横向溢出与页面错误；额外对比度断言只覆盖指定控件。`docs/roadmap.md:74` 已保留业务弹窗、图像叠字、高密度及错误状态待验，不另建重复治理项目。

**落实步骤**：

1. 依照本次 UX-01/02 涉及流程，先列正常、空、加载、故障、禁用五种状态；优先复用已有中性夹具，不启动真实生成。
2. 对每个新增/修改状态保存双主题桌面与窄屏截图，人工查看焦点、遮挡和图片背景文字，记录实际前景/背景组合的对比度。
3. 在目标 Windows WebView2 执行键盘与屏幕阅读器抽样，至少包括导航、文件选取、嵌套弹层、事件提醒；记录操作步骤、实际播报与设备版本。
4. 将每次发现回填现有测试入口；仅在新增缺口不能被已有行为测试表达时增加测试，避免以截图数量代替质量。

**验收**：每条状态有具体操作与证据，失败单列，不用历史截图或零横向溢出关闭全部无障碍事项。测量阶段无需回滚；后续 UI 修改按独立小提交回滚。

### UX-05：桌宠回归失败要分别处理交互契约漂移与语义缺口

**当次证据**：主会话本次 `browser-critical.log` 中，`companion-focus.spec.ts:30` 的深浅主题、360/480 宽度角色窗用例停在 `:34` 的 `.companion-chat-chip` 可见性断言；DOM 有该按钮，但为 hidden。`a11y-device.spec.ts:84` 对 `/companion` 的一级标题断言实际得到 0，`ui-layout.spec.ts:12` 同样因找不到 `h1` 未进入后续布局检查。本报告读取了对应 error-context，并查看 `companion-focus-companion-character-window-dark-360-desktop/test-failed-1.png` 与 `ui-layout-layout-dark-1440-companion-desktop/test-failed-1.png`。完整结果总计以主会话最后收集为准，不能把中途日志当最终通过率。

**可以确认的分类**：

1. **聊天快捷按钮隐藏：旧测试前提与当前明确设计冲突。** `src/assets/css/companion-surface.css:104`–`:107` 明确要求桌面 pure-pet 默认不画工具栏和聊天按钮；`src/composables/chat/usePetGestures.ts:5` 初始化 `controlsOpen=false`，`:9` 提供右键开关，`:39` 提供 ContextMenu/Shift+F10，`:30` 提供角色双击打开聊天。`usePetGestures.spec.ts:15` 的单测也明确验证默认无工具栏。旧浏览器用例打开页面后立即要求按钮可见，没有使用任何新入口；该失败不足以证明“聊天功能已不可用”，也不应为了让旧断言通过而恢复永久工具栏。
2. **一级标题缺失：真实 DOM 语义与既有项目验收契约不一致。** `src/views/CompanionView.vue` 已无 `h1`，角色名改由 `CompanionCharacterPicker.vue:2` 的 select 展示，`ChatCharacterStage.vue:54` 的名称是 strong。`CompanionView.vue:111` 仍有带名称的 main，截图也有角色舞台与输入，因此不是整个页面未渲染。应恢复适合透明角色窗的页面标题语义；“每页恰好一个 h1”是本项目的既有测试契约，不能夸称为 WCAG 直接要求的唯一结构。
3. **尚未验证的边界**：仅据源码可以确认新右键/键盘入口存在；本次失败用例在其之前停止，未证明设置面板、聊天桥调用、焦点顺序及后续对比度在新入口下通过。本次只读分析没有追加浏览器运行，不把潜在后续结果写成通过。

**落实步骤**：

1. 保留当前 pure-pet 设计，把桌面与普通网页两种入口写成明确测试前置状态，避免按桌面按钮常显的历史样式判断新设计。
2. 为 `/companion` 恢复准确的一级标题。桌面透明窗可使用现有 `.sr-only` 保留语义，普通浏览器布局可使用适当的可见标题；标题包含当前角色时需随选择同步。不要用 `display:none`、`aria-hidden` 或把 select 改成假标题来凑断言。
3. 更新 `companion-focus` 流程：先断言默认工具栏隐藏，再分别以右键和 Shift+F10 显示，Tab 到聊天/设置控件；实际激活后断言桌面桥的调用目标与次数，Escape 收起后焦点可继续操作。未加载、加载失败和模型已就绪均须能进入控制区。
4. 将布局矩阵的“页面已就绪”与“一级标题语义正确”分离：前者检查有名 main 和页面舞台，后者独立检查标题；这样语义回归不会让所有后续溢出/对比度断言完全失去执行机会。保留标题断言，不能直接删掉失败检查。
5. 在双主题 360×520、480×720 定向复跑角色窗流程，保留设置面板不越界、可读性、提醒和聊天切换的原有断言；再补本次失败的 a11y/layout 项。仅在这些证据通过后重新执行关键入口确认最终状态。
6. Windows 实际透明窗仍需验证右键、键盘菜单键、双击、拖动阈值、穿透切换与焦点，不用浏览器模拟桥替代设备验收。

**验收**：默认纯角色外观保留；不用鼠标也能显式打开控制区并进入聊天；该路由有一个可访问的一级标题；更新后的测试既覆盖新入口又能继续执行原布局与对比度断言。不得以延长超时、跳过用例或仅修改 selector 名称关闭本项。

**回滚**：语义补丁和测试流程调整拆为可审查提交；如回滚交互方案，应同时恢复与之匹配的测试契约，不回退角色注册表、模型资料、聊天历史或桌面安全边界。测试调整不能单独被描述为生产功能修复。

## 建议实施顺序与未覆盖项

先明确 UX-05 的当前交互契约并恢复可用回归证据，同时处理 UX-01，再处理 UX-02；每项交付组件改动、键盘行为证据与双主题截图。UX-03 为低风险独立改进，UX-04 接入已有 UI/真机待验清单。无需引入新组件库、重做页面或替换现有焦点系统。

本报告没有进行屏幕阅读器、真实触屏、Windows 高 DPI/多屏、原生穿透窗或真实模型画面的当次验收；没有证明全部动态图层、禁用状态和图片叠字均达到 WCAG AA。UX-01 当次浏览器复现仅覆盖桌面双主题空态，其他主会话浏览器结果应与具体测试和构建身份一起读取。
