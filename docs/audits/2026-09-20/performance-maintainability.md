# 前端性能、架构与可维护性审计

审计日期：2026-09-20。源码基线：`main@39d955e`。本轮交付报告与落实步骤，不修改运行时代码、缓存、数据格式或依赖。

## 范围与证据方法

审阅前端入口、懒路由、组件生命周期、场景数据加载、图库资源、角色注册目录、包体预算与相关定向测试。读取当前工程契约及路线图，已实现的作品保存边界、路由拆分、缓存失活和图片 LRU 不重复列作待开发事项。

除静态源码核对外，执行了两个无网络、无生产访问、无持久化写入的隔离复现：一是将 `localCompanions.ts` 在内存转译并以模拟 fetch/注册表运行；二是调用包体预算的纯 `evaluateManifest` 函数输入构造 manifest。它们证明指定逻辑，不代表真实服务器、生产构建性能或浏览器使用体验。

完整门禁、构建输出和浏览器检查由主会话统一执行，见本目录总报告。已知本轮完整门禁发现基线 TypeScript 与仓库卫生阻断，不能引用历史通过替代。本报告不另行并发启动性能测试，避免污染测量。

## 已有架构优点

- 18 个路由定义均懒加载；字体异步加载、框架分块、入口/路由/懒块预算与预压已有工程入口。证据：`src/router/index.ts:59`、`src/main.ts:15`、`vite.config.ts:113`、`package.json` 的 `build`。
- 复杂图库业务已下沉至 composable 与存储仓储；当前单体基线 `scripts/tests/monolith-baseline.json` 为 `{}`，没有需要继续容忍的已登记超限豁免。实际门禁结论以本次主会话输出为准，不用物理行数替代有效行数规则。
- 场景 store 已有代际隔离、在途去重、必需/可选元数据区分与逐资源成功缓存。证据：`src/stores/sceneStore.ts:113`、`:156`、`:170`、`:213`。不建议为“统一”抹掉这些语义。
- 图库已有 60 条渐进渲染、可见区域 HD 加载、并发上限、LRU、查看器 URL 释放及失活停读。证据：`src/composables/gallery/useGalleryWorkspace.ts:131`、`:276`、`:289`、`:395`、`:410`、`:461`、`:634`。没有证据支持立即替换为虚拟列表。
- 路由预取区分悬停模块预热和明确意图资源预热，取消旧资源请求，错误后可重新尝试。证据：`src/router/prefetch.ts:43`、`:61`。Live2D 文档策略切换保留安全边界，性能改善不能以取消隔离换取。

### PM-01：路由预算没有度量实际初次打开页面的完整并集

**证据**：`scripts/maintenance/check-bundle-budget.ts:33` 注释声称路由闭包含入口链；实际 `:95` 仅调用 `staticClosureSize(manifest, entry.key, sizeOf)`，其 `:64` 起的遍历只沿路由自身静态 imports。入口另在 `:167` 独立核对，`AppLayout` 又是 `src/router/index.ts:62` 的懒父组件。独立入口、布局与叶路由之间没有求并集。`scripts/tests/test-bundle-budget.ts:64` 还明确断言无 imports 的 Home 闭包等于自身 40 KiB，未算夹具入口的 100 KiB。

**当次隔离复现**：构造入口 380 KiB、叶路由 100 KiB、仅被叶路由引用的共享块 200 KiB；当前 `evaluateManifest` 返回路由闭包 300 KiB、零 violations。入口也小于独立 390 KiB 预算，但首次页面的互异 JS 为 680 KiB，超过注释描述的 580 KiB 页面预算。此为预算盲点的构造证明，不是声称本次真实构建已经达到 680 KiB。

**当次真实构建测量**：对主会话完成的 `dist/.vite/manifest.json` 使用现有 `routeEntries` 枚举全部 18 个路由（包括没有 `src` 的 Gallery/PromptBuilder 命名块），逐项求入口、AppLayout（独立窗口除外）及叶页面静态 JS 文件的去重并集，未改构建与预算。入口闭包为 243.9 KiB；最大的页面如下：

| 页面 | 当前路由自身闭包 | 入口 + 布局 + 页面并集 | 当前指标未计入 |
| --- | --- | --- | --- |
| ChatView | 560.1 KiB | 575.4 KiB | 15.4 KiB |
| CompanionView（独立页面） | 560.0 KiB | 560.0 KiB | 0 KiB |
| PromptBuilderView | 518.9 KiB | 535.0 KiB | 16.1 KiB |
| ShowcaseView | 463.1 KiB | 479.5 KiB | 16.3 KiB |

最大并集 ChatView 精确为 589,248 字节，仍低于名义 580 KiB（593,920 字节），因此本轮结论为“口径不完整且新口径余量较小”，不是“预算已超限”。这些未压缩 JS 数字不含字体、CSS、图片或运行后继续请求的懒模块。原始文件集合保存在本机忽略目录 `runtime/comprehensive-audit-2026-09-20/page-closure-evidence.json`；manifest SHA-256 为 `76b4a53622b8490137985395f684dc1a3713445a0ec3424529454d58e16204ea`，与 UX-01 浏览器核验相同。

**落实步骤**：

1. 保留“路由自身静态闭包”指标并准确命名，新增“初次页面 JS 并集”指标：入口闭包 + 路由匹配链中的布局/叶页面静态闭包，按产物文件去重。
2. 明确路由到 manifest 的映射来源，覆盖普通 AppLayout 页面和独立 companion/control 页面；无法解析的映射应报告未知，不能默认为零。
3. 在一次受控构建上同时输出旧/新指标与最大的三个页面，先建立真实新基线，再确定预算；不要直接复用 580 KiB 导致所有页面突然红灯，也不要仅提高旧阈值掩盖差异。
4. 给现有预算测试补充入口独有依赖、共享依赖去重、懒布局、独立页面四个行为夹具。最后用一个冷启动浏览器请求清单核对实际下载集合与指标口径，并区分预热、字体和运行时懒模块。

**验收**：上述构造夹具新增指标为 680 KiB；共享块只算一次；生产 manifest 中每个页面均有可解释集合，预算声明与实现一致。数值是未压缩 JS 体积，不冒称网络传输量或交互延迟。

**回滚**：新增指标先以报告模式进入，旧门禁继续保留；映射存在误报时撤回新指标阻断规则并保留采样报告，不删除原有预算。

### PM-02：目录失败被成功记忆，重试路径不一致

**证据**：`src/utils/localCompanions.ts:10` 用 `loaded ||= promise` 记忆结果；`:13` 对非 2xx 直接返回，`:15` 对非数组直接返回，只有 `:27` 的异常 catch 才清理 `loaded`。`src/router/index.ts:131` 在进入聊天/桌宠路由前调用该函数，因此服务器暂时 503 后恢复，同一文档中的后续调用仍会复用已完成的空结果。网络异常路径可以重试，HTTP 与结构异常路径却不可以。

**当次隔离复现**（每个场景连续调用两次，第二次模拟服务器健康）：

| 首次响应 | 实际 fetch 次数 | 警告次数 | 结果 |
| --- | --- | --- | --- |
| HTTP 503 | 1 | 0 | 第二次未请求 |
| HTTP 200、顶层对象而非数组 | 1 | 0 | 第二次未请求 |
| fetch 抛网络错误 | 2 | 1 | 第二次请求发生 |

**落实步骤**：

1. 区分“正在请求”“有效目录已加载”“失败可重试”，不要把提前 return 等价为成功缓存。沿用 5 秒超时与本机判断，不放宽远程注册边界。
2. 非 2xx、非法顶层形状进入统一失败路径并释放 in-flight 缓存；合法空数组仍应视为成功，避免无限请求不存在的本机角色。
3. 复用应用内错误/重试模式，为需要本机角色的界面提供可理解的目录状态；采用明确重试或短退避，避免每次渲染都请求。
4. 添加并发请求去重、503→成功、结构错误→成功、合法空数组、远程不请求的定向测试。注册操作仍执行身份/profile 校验，不把恢复逻辑改成接受未知角色。

**验收**：首次暂时失败不永久屏蔽当前文档的后续请求；并发调用只发一条请求；成功后继续缓存；远程仍只用允许的内置身份。模拟通过后再验一次实际网关目录恢复，不需要启动真实 Live2D 渲染或生成模型。

**回滚**：回退该目录模块与局部状态展示，不修改已保存角色、模型文件或用户历史；若移除自动重试，仍保留手动重试并避免永久缓存失败。

### PM-03：静态场景数据缺少请求时间边界

**证据与边界**：`src/stores/sceneStore.ts:57` 的 fetch 未设置 AbortSignal 或应用层超时；`:218` 用 `Promise.all` 等待整个元数据组，包括可选项；`:117`–`:124` 的全局 loading 依赖全部活跃加载结束。`loadEpoch` 能阻止旧响应覆盖新状态，但不会让悬挂请求结束，也不会释放其活跃加载计数。

当网关/代理接受连接却长期不给正文时，页面可能持续处于加载状态；本轮未制造实际长期挂起的生产请求，不声称已观察到永久卡死。浏览器/操作系统可能最终超时，因此准确问题是缺少可预测的应用层恢复上界。

**落实步骤**：

1. 先在隔离服务器测必需、可选和分片三类延迟/无响应路径，记录 loading、错误展示与重试按钮当前行为。
2. 为共享请求所有者配置合理超时，超时后区分必需失败与可选降级。不要因一个消费者离开页面就取消仍被其他页面共享的请求。
3. force 开启新代际时明确旧代际请求的取消/完成策略，确保所有 beginLoad 有对应 endLoad；保留旧响应不得发布的现有保证。
4. 用可控时钟与延迟响应测试：旧请求晚到、新请求成功、可选超时、多个消费者共享、重试后 loading 归零。不要通过只断言“存在 AbortController”镜像实现。

**验收**：超时边界可配置且有用户可见恢复路径；可选项超时不阻断已可用主体；并发/代际测试不串状态；本机慢磁盘和远程受限访问都不误判成功。

**回滚**：保留超时前的成功缓存与代际保护，按独立提交撤回取消策略；不改变数据版本与存储格式。阈值误报时调整有实测依据的配置，不移除失败可见性。

### PM-04：全历史预热不受页面可见性和窗口数量约束

**证据**：`src/App.vue:66` 启动时读取全部作品历史，`:77` 逐项查询缩略图缓存，缺失则读原图并生成缩略图；`:92` 仅检查 `warmStopped`，使用 idle callback 加 4 秒 timeout 或 120ms timer 继续。停止标记只在 `:121` 应用卸载时设置；没有 `document.visibilityState` 暂停、每轮任务预算或跨窗口预热所有权。多窗口各有本地列表和调度器。单张串行与缓存命中已经降低代价，不能据此断言严重性能退化或内存泄漏。

**落实步骤**：

1. 用 1,000/10,000 条中性记录，分别测缩略图齐全与全部缺失、前台与隐藏、单窗口与双窗口；记录原图读取/编码数、总耗时、长任务和交互延迟。
2. 若确认后台工作影响交互，将预热提取为已有图库缓存层的独立调度器：隐藏页暂停、恢复后续跑，每个空闲片限制工作量，优先近期记录。单张解码无法即时取消时允许完成但不要继续排队。
3. 若双窗口重复明显，增加缓存任务所有权或跨窗口锁；继续保持缩略图是可重建缓存，不把预热锁扩大成作品读写锁。
4. 与图库可见区域生成缩略图的路径共享去重语义，验证预热取消、页面关闭和图片缺失不会影响真实作品及正常入册。

**验收**：先明确改善目标并保留同机前后对照；隐藏时不再持续启动新解码，恢复能继续；两个窗口同一图片不会重复执行昂贵编码；作品册缺缓存时仍可即时按需显示。

**回滚**：预热仅作用于派生缓存，可关闭后台预热并保留按需缩略图；不要删除原图或用户历史。只有测得收益才引入跨窗口复杂性。

### PM-05：完成现有目标设备测量，不提前指定虚拟列表或新缓存系统

`src/components/AppLayout.vue:14` 有四类 KeepAlive；图库已有失活处理，但 DOM/Blob URL 计数不能替代 GPU、图片解码内存、纹理或整个进程占用。此项已在 `docs/roadmap.md:49` 与计划 009 保留，本轮不把它重新包装成新泄漏结论。

**落实步骤**：受控构建固定 SHA 与 manifest → 单 worker 分别测冷/热进入和首次操作 → 对四类缓存页执行固定 20 次切换与长时停留 → 目标 Windows 记录进程内存、GPU/纹理、帧间隔及后台功耗 → 按同机同负载中位数、尾延迟和增长趋势定位真实瓶颈 → 只对超目标路径实施一项优化后复测。设备测试不要与全量门禁、构建或真实大任务并发竞争资源。

**验收**：证据包含硬件、DPI/刷新率、运行时、构建身份、场景数据量、可见性状态与冷暖缓存；不把 54Hz 主机结果直接与历史 120Hz 比较。没有持续增长证据不宣布泄漏，没有大列表实测需求不引入虚拟列表。

**回滚**：测量阶段不改生产行为；后续优化保留功能开关或局部提交，能够恢复原缓存策略而不丢草稿/结果。

## 执行路线及覆盖限制

建议先将 PM-01 和 PM-02 做成两个独立小提交：前者校准度量，后者修复可复现容错问题。随后用隔离故障测试处理 PM-03；PM-04/05 先测量再决定实现。每项按工作流选择受影响门禁，不因提交报告就升级成真实模型、设备或安装操作。

本报告未跑生产负载基准、真实模型生成、Live2D 长时 GPU/音频并发、Windows 安装版迁移或大图库真实恢复。未对整个应用做堆快照/CPU profile，未证明不存在资源泄漏。TypeScript、构建失败、服务端安全及数据治理的全面结论由同批其他维度报告承担。
