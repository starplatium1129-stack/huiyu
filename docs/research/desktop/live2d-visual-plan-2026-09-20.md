# 聊天房间与桌宠视觉设计方案

日期：2026-09-20。状态：A 批聊天房间、B 批无边框桌宠呈现已实施并完成定向检查；Windows 安装版与 C 完整设备验收待执行。承接 [010 陪伴体验计划](../../../plans/010-companion-experience-and-live2d-adapter.md)；本文细化真实模型取景、界面布局与验收，不重写模型接入方案。

## 1. 本轮依据与交付

- 已核对 ChatView、CompanionView、ChatCharacterStage、useStageFraming、layoutFit 与桌面贴靠实现。
- 本轮实际在隔离浏览器加载 8 个已有模型，1440×1000 窗口、compact 画质，采集约 739×768 的角色宿主画面。没有发送聊天、调用语音或生图，也没有操作桌面安装版。
- 证据与本地交互布局稿：项目根 `.cache/live2d-design-2026-09-20/`，入口 `index.html`，采集结果 `baseline.json`，各角色 PNG 为本次真实模型画面。图片含采集时的浅色舞台底，不能当作透明模型贴图。
- 布局稿使用真实截图而非生成的人物。切换角色、主题、房间/桌宠状态用于比较排版；不是运行中的 Live2D，也不证明动作、原生窗口和 DPI 已适配。
- 模型画面仅本机预览，不提交 Git、不打包或公开发布。设计文档可提交；本轮不提交源码变更。

发现一个环境差异：源码候选清单已移除雷电将军，但当前 3000 网关的本机角色目录仍返回该条目。可能是旧进程或目录投影不同，本轮不重启服务、不重新接入；新方案不包含这个已退役角色。不能把网关条目总数当作当前支持角色数。

## 2. 设计决定

1. 模型决定取景，再决定容器宽高。保持作者的五官、比例、服装、道具和署名，不用生成图覆盖模型，也不拉伸模型凑满版面。
2. 房间优先阅读与表情，桌宠优先轮廓与不遮挡工作。共用字体、颜色和细线图标，但不共用固定缩放倍率。
3. 首选低细节背景：暖白或深紫灰纯色、极弱静态色差。水墨初音优先中性底；先不叠加咖啡馆、强光照或透视地面。
4. 全身模型可在房间选择“全身”或“交流取景”；半身源模型只提供合适的半身构图，不承诺不存在的全身。
5. 模型未加载时保留现有静态图与明确加载入口；加载失败展示重试与回退，不把静态图标成 Live2D 已就绪。

| 模型 | 本轮画布尺寸 | 当前观察 | 房间建议 | 桌宠建议与约束 |
| --- | --- | --- | --- | --- |
| 宁宁 | 2500×5000 | 全身、长发，当前人物占舞台偏小 | 先核定人物边界再适度放大；脸部保持可读 | 全身优先，长发和鞋跟留边 |
| 夏目 | 9400×28892 | 全身，头顶与鞋接近上下边缘；原画布极长 | 先缩小至有稳定上下余量，再比较交流取景 | 不直接沿用房间倍率；裙摆与脚部完整 |
| 水墨初音 | 2874×1992 | 横向半身、墨迹与发饰外扩；room 默认 zoom=1.45、y=-3%，本轮装饰有裁切 | 用原生半身横幅；尝试较小倍率，不硬塞全身竖框 | 半身承托式桌宠；不可生成或补画下半身冒充原模型 |
| 芙莉莲 | 5167×9410 | 全身，法杖产生明显横向范围 | 保留法杖时增加舞台宽度，不仅按身高 fit | 设为宽道具类；聊天窗避开法杖侧 |
| 菲伦 | 4242×6000 | 全身长裙与横向法杖，带作者屏内说明 | 优先保留法杖全貌，表情阅读不足再提供交流取景 | 长裙、法杖与作者效果一起计算可见边界 |
| 长离 | 4000×7562 | 全身；本轮 motion groups 为空 | 保留作者署名与画面效果，不承诺不存在的动作 | 同一姿态下检查衣袖、发饰；无动作按静态范围验收 |
| 蕾姆 | 2500×2900 | 源模型到大腿附近的半身构图，Cubism 2 | 半身展示，底部用低调承托面自然结束 | 半身承托式，不强行做悬空全身；保留浏览器回退 |
| 芙宁娜 | 3000×4500 | 全身，高帽与裙尾扩大轮廓 | 顶部帽饰优先留边，避免脸被缩得过小 | 留出帽饰、侧向裙尾的动作空间 |

先按人物可见范围预留约 6–10% 边距作为校准起点；这不是验收阈值。最终范围由各模型待机、合法头部/手部交互、说话与表情采样的可见边界并集决定。不要用上表画布尺寸自动计算最终倍率。

现有取景由 `useStageFraming` 按 `surface:characterId` 保存（room / immersive / companion），zoom 范围 .65–2.2、x/y 为 ±25%。初音已有专用默认值；其他角色默认 1/0/0。实施时复用此入口，保留用户已保存的值；不得为了更新默认取景清空用户设置。不同服装是否需要单独校准，先以实际动作和轮廓采样证明，再决定是否扩展存储键。

## 4. 聊天房间布局稿

### 宽屏（建议 ≥1200 CSS px）

- 顶栏：角色选择、专注陪伴、新对话、更多；延续现有页面和按钮语义。
- 主区：角色舞台初始约 40%，对话约 60%，列间距 24–32px。宽道具角色允许舞台增至约 46%，不能挤掉对话输入区。
- 角色舞台：图形承载区不放大段介绍；角色名和“角色设置”放舞台外的底栏，控制层不压脸、头发或手部命中区。
- 对话：模型/语音设置收在顶部，历史独立滚动，输入区固定占布局底部，不浮在消息上。保留复制、记忆、重播、停止、回到最新、归档和错误提示。
- 专注陪伴：沿用最近一句回复展示，完整历史、草稿与角色保持同一份状态；进入/退出不发消息、不重载同一模型。

### 窄屏

900–1199px 先试约 38%/62%；实际阅读宽度不足则改为上下结构。小于 900px 的原型采用上下排列，模型区设有界高度并可折叠，输入区与历史仍有独立空间。小于 600px 时不强制首屏同时显示完整全身和长对话，可先显示交流取景并保留“查看完整角色”。以上为待验证断点，不覆盖现有响应式规则。

## 5. 桌宠三状态布局稿

| 状态 | 显示内容 | 收起内容 | 切换约束 |
| --- | --- | --- | --- |
| 安静陪伴 | 角色、可恢复的轻量操作入口；录音/错误等必要状态 | 输入框、长历史、非必要诊断 | 不抢焦点；移入/键盘操作可恢复工具，穿透时保留快捷键恢复 |
| 简短回复 | 角色旁 1–3 行气泡，关闭/展开入口 | 长文本放入独立聊天窗 | 气泡不压脸或命中区；文字过长不无限拉高 |
| 展开聊天 | 现有独立聊天窗：历史、输入、语音、停止、完整房间入口 | 模型不重复渲染到聊天窗 | 贴靠可解除；关闭小窗保留对话和草稿 |

桌宠宽高不能统一为一组固定值：全身可先试 320–420×600–780 CSS px；半身可先试 380–520×360–520；宽道具适当增加横向空间。聊天窗先试 360–440×480–620，并受到屏幕工作区约束。数值都是布局探索起点，不是原生窗口配置变更。

复用现有 `chat_dock.rs` 的左右贴靠与工作区限制；把人物可见区域、工具条和气泡作为避让依据。桌宠靠右边时优先把聊天窗放左侧；左右都不足时先缩小/移动聊天窗并保留可见的关闭与输入操作。Native Overlay 的物理像素与 CSS 像素换算继续由现有布局层负责，禁止靠放大透明窗口代替缩放模型。

当前桌宠 CSS 的 Live2D 宿主有固定 `top=76px / bottom=210px` 预留。安静陪伴时下方仍被预留会浪费舞台空间；下一步应按三个状态重新分配保留区，不能简单把所有模型统一放大。

## 6. 实施分批与验收清单

### A：先做房间样板

以夏目、初音、芙莉莲三个差异明显的模型为试点，复用 ChatView / ChatCharacterStage / conversation-room.css。只改呈现，保留模型加载、存储、记忆与语音生命周期。

### B：桌宠状态与独立聊天窗

复用 CompanionView / CompanionChatView / useRoomPresentation / chat_dock，不新增重复窗口或第二份会话。先优化安静态保留区，再做气泡与贴靠，不同时改接入层。

### C：逐模型校准与桌面验收

- [ ] 8 个模型：待机、可用的头部/手部互动、说话、常用表情；不触发未知成人动作。
- [ ] 可切换服装逐套检查；单服装明确单服装，未实现的作者能力不加假入口。
- [ ] 全身模式不裁头脚、发饰、裙摆、法杖；交流取景只允许事先标明的身体裁切。
- [ ] 深浅主题：脸部可辨认、白发不融进底色、黑发不融进深色，文字达到 WCAG AA；作者水印保留。
- [ ] 1440×900、1280×800、900×900、390×844；模型、设置弹层、消息与输入框无相互遮挡。
- [ ] 生成回复、停止、语音回放、未配置音色、模型加载失败、静态回退分别检查。
- [ ] 单次发送、草稿保留、历史阅读位置、房间聚焦时桌宠暂停；切换展示形式不重复播报。
- [ ] Windows 100%/125%/150%/200% DPI、左右边缘、任务栏、多屏含负坐标、置顶、穿透和快捷键恢复。
- [ ] 长时运行帧耗与显存；首轮不以固定 FPS 宣称性能通过。

本轮只完成源码核对、8 模型待机加载采样、静态布局探索与规划。动作边界、说话口型、全部服装、Native/DPI、多屏及设备验收均未完成；不沿用历史 PASS 代替。

### 已实施

- 原生 `create_companion_window` 已有 transparent(true)、decorations(false)、shadow(false)、skip_taskbar(true)，本轮保持这些设置并增加针对该窗口的回归约束；不宣称本轮才首次实现原生无边框。
- `theme-bootstrap.ts` 在 Vue 启动前识别 native companion；首帧 CSS 直接保持透明并隐藏普通应用的整窗加载牌。只有桌宠路径触发，正常聊天页面仍显示原来的加载占位。
- 清除桌宠根、角色舞台的底板、边框、地面投影及额外轮廓阴影；关闭根背景的主题过渡，避免启动/换主题时短暂留下整窗色块。
- 顶部改为紧凑浮条：角色、移动、设置、隐藏。闲置后收起，键盘焦点及正在操作的菜单仍可恢复/保持显示；隐藏按钮明确标注 Ctrl+Shift+Space 恢复入口。`uiHidden` 改为响应式状态，卸载时清理计时器。
- 根据用户“桌宠一定无边框”的新要求，桌宠未加载模型时不显示矩形场景封面，改为小型加载/错误操作提示；聊天房间仍保留原静态图回退。
- 回复气泡最多展示 3 行，保留完整文本，增加展开与收起按钮；修复其继承父层 pointer-events:none 导致点击落到角色画面的问题。聚焦/悬停时暂停自动收起；气泡收起不改变舞台尺寸。
- 桌宠初音新默认倍率为 1.00、位置 0/0，避免原来的 1.75 放大裁切；已有用户保存的取景仍优先，不重写记录。作者水墨、装饰与署名不修改。
- 独立聊天窗统一为清晰的主题表面和紧凑气泡，保留贴靠/解除贴靠、草稿、关闭窗口和完整房间入口。
